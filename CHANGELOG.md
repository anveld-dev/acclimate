# Changelog

## Breaking change — central learning

Learning now runs in the service. The application loop definitions, evaluation starters, evaluator commands and learning CLI have been removed. Configure a model provider, import and review tasks, and start learning in the bundle’s Learning tab. SDKs deliver releases and report production outcomes. Start and resume require a verified provider and 20 admitted tasks in each split. Both SDKs can list and remove blocked versions. The remaining command is `acclimate pull`.

Run the `acclimate-executor` container with a provisioned token mounted through `ACCLIMATE_EXECUTOR_TOKEN_FILE` and access to the Docker socket. Create the token with `acclimate-service --create-executor-token`. Build the chat runner image and configure gVisor (`runsc`) in production. Set `ACCLIMATE_PROVIDER_ENCRYPTION_KEY` on the service to a 64-character hex key so workspace provider credentials can be encrypted at rest. `npm run local:up` now creates the executor token and starts the executor. In production, follow the ordered [executor setup](apps/docs/content/docs/operate/enable-learning.mdx). `compose.yaml` now requires `ACCLIMATE_EXECUTOR_TOKEN_FILE`. The release workflow publishes `acclimate-executor` and `acclimate-runner` images with the same tags and platforms as the service and console, and `compose.yaml` names them through `ACCLIMATE_EXECUTOR_IMAGE` and `ACCLIMATE_RUNNER_IMAGE`; until a release includes them, build both from the checkout. Start and resume return 409 `optimizer-required` when the service has no optimizer model, and the loop reports `optimizerConfigured`.

Migrations `0022` to `0024` stop active rounds, pause running loops with `tasks-required` and copy evolve cases into service-owned tasks. They turn each stored `evaluate` machine right into `read`; give outcome reporters `write`. Startup refuses a static grant that still lists `evaluate`. The service no longer reads `ACCLIMATE_LEARNING_EVALUATION_QUEUE_SECONDS` or `ACCLIMATE_LEARNING_EVALUATION_SECONDS`. [Upgrade steps](deploy/README.md#upgrade-to-the-learning-loop-schema)

Scores change meaning. An exact-match rollout scores 1 or 0. A judged rollout is judged three times, passes when at least two judgments pass every criterion, and scores the share of criteria met, averaged over the judgments. A task's score is the mean of its five rollouts, and a task passes when three of them pass. Evolve scores from earlier judged rounds are not comparable with new ones. The automatic revert judges on the held-out pass rate, the share of rollouts that pass, so partial credit does not hide a task that stopped passing. The loop alert adds `previousPassRate` and `passRate`, and the alert email reports the pass rate. Upgrade the service before the executor: the service accepts the 1-or-0 judged scores of an older executor, but an older service rejects a newer executor's fractional scores.

Other behavior to know:

- Import sets a row aside as `no-reference`, `not-converted`, `too-large` or `duplicate` and converts the rest. A row is a duplicate when its input equals a live task's input in either split, or an earlier row's in the same import. Criteria already in a row are kept, and the judge drafts criteria only for a row with an answer and none of its own.
- A row or outcome with an expected answer is graded `exact` when the answer is not a string, or is a string of at most 80 characters on one line. A longer answer is graded by criteria the judge drafts from it, with the answer as the reference. Set `grading` to `exact` or `criteria` to choose; `job.expect()` takes it in both SDKs. An outcome graded by criteria becomes a task when its conversion finishes. A held-out task with drafted criteria waits for a person to confirm it.
- Pasted text and `.txt` uploads split into rows on lines of three or more dashes.
- A round whose current-version evaluation failed only on `gateway-upstream` errors, the provider failures that may clear, fails with `provider-unavailable`. It counts toward neither the `failed-rounds` pause nor the daily cap. The loop waits ten minutes (`waiting: provider-unavailable`) before it tries again, doubling the wait for each consecutive outage round up to six hours; any other round resets it. Start or Resume during the wait runs a round at once.
- The executor reports a provider refusal that waiting will not cure, such as a revoked key, an unknown model, a request the provider always rejects, or an unusable reply, as `provider-rejected`. That round fails as `incumbent-evaluation-failed` and counts toward the pause. Upgrade the service before the executor: an older service rejects the new code.
- When the conversion of an outcome graded by criteria fails for good or sets its row aside, the outcome becomes an `exact` task, set aside with `admissionReason: not-converted`, for a person to edit. An import row with its own input and expected answer keeps them when conversion drafts its criteria.
- An executor that exits because the service refused its credential removes the sandbox containers it started.
- Every `docker compose` command on `compose.yaml` needs `ACCLIMATE_EXECUTOR_TOKEN_FILE` set, even for a deployment that does not run the executor.
- The executor exits with status 78 and a plain message when the service refuses its credential, its credential file is missing or empty, its runtime is unsupported, the runner image is missing, or its startup sandbox preflight fails. A missing gVisor runtime, or one without `--host-uds=open`, now stops the executor at startup instead of failing every rollout.
- The service refuses to start with a provider encryption key that does not match the one it first stored a check for, and warns when the key is unset. [Provider encryption key](apps/docs/content/docs/operate/backup-and-restore.mdx)
- For an exact-match task with a failing rollout, the optimizer's feedback includes the expected answer. The screen skips candidates that address the grader.
- The optimizer may add knowledge that failed tasks reveal, such as a business policy or the set of answers a task allows, when it states it as a general fact, rule or procedure. The screen no longer skips such a candidate as hard-coding. It still skips one that answers particular cases or copies case inputs or traces. Before this change, a round on the sample support tasks screened out all five candidates, because each added company policies the tasks required. [Hard-coding and knowledge](docs/architecture/central-learning/loop.md#optimizer)
- The executor gateway retries provider errors and waits on `Retry-After` for up to seven minutes. It does not resend a request that ran for its full ten-minute timeout. With CLIProxyAPI and one Codex sign-in, turn the proxy's cooldown off. [Operator guide](deploy/README.md#cliproxyapi-with-codex-sign-in)
- An adopted round that loses its executor before the held-out check finishes keeps its release and raises the `regression-check-incomplete` alert.
- The console's workspace settings are three pages under **Settings** in the sidebar: **Members** (`/w/{workspace}/settings/members`), **Model provider** (`/settings/model-provider`) and **Machine tokens** (`/settings/tokens`). The provider and tokens no longer appear on Members. A bundle's **Learning** tab has **Overview**, **Tasks**, **Settings** and **Memory** pages, selected with `?tab=`. Links with `?round=` open the round on the Overview, and links with `?memory=` open Memory.
- The automatic revert now fires when the held-out pass rate falls by at least 10 percentage points or half the previous version's pass rate, whichever is smaller, and at least two tasks go from passing to failing. Before, a version passing under 10% could never be reverted.
- An unknown or revoked connection or receipt credential (`aci_`) now gets 401 `unauthenticated` instead of 403 `denied` on content reads and receipts. 403 stays for a valid credential asking for something it may not have.
- Malformed JSON bodies on receipts, credential issue and operation close return the standard error envelope: 400 `invalid_content` naming the field, or 415 without `Content-Type: application/json`. Each failed receipt rule has its own message. A receipt `digest` must be `sha256:` and 64 lowercase hex characters, and `revision` must be decimal digits. `contracts/openapi.json` documents connections, credentials and receipts in full and no longer forbids additional properties in responses.
- Both SDKs add `systemPrompt(payload)` / `system_prompt(payload)` and `prepared.systemPrompt` / `prepared.system_prompt`, which render a bundle exactly as a learning rollout's system message. `instructions` stays and holds only the instruction files.
- An exact version with the offline option now also falls back to the verified cache after HTTP 502 or 504, which a reverse proxy returns for a stopped service.
- The console calls the connection's reporting credential a **receipt credential**.

All notable changes to Acclimate will be documented in this file.

## [0.1.0] - Unreleased

The first release, open source under Apache-2.0. The service and console images, `@acclimate/sdk`, the four plugin packages, the `acclimate-sdk` Python package and the starter archives are all versioned `0.1.0`; the plugins peer-depend on `@acclimate/sdk` `^0.1.0`.

### Removed

- Removed HTTP routes for bundle drafts and their history, save, discard and publish operations, for proposals, comparisons and policy receipts, and for evaluation requests, their start, finish, interrupt, abandon and progress operations, and workspace evaluation capabilities.
- Removed the connection learning route and its stop, restore, renew, corrections, rechecks, outcome submission and lookup, work, incident replay, field audit, field requalification and round review subroutes.
- Removed the `propose` machine right and the release fields `comparisonId` and `policyOverride`. Bundle setup remains at `POST /v1/workspaces/{workspaceId}/bundle-setups`. Releases now require a reason in `unevaluatedReason`.
- Removed the GitHub Action and CI wrapper, the `acclimate-operator` command and the connected-learning driver, and the `acclimate-eval` and Python `acclimate` commands `compare`, `request`, `run`, `check`, `status`, `interrupt`, `export`, `verify-export` and `plan`, including `--policy`, `--handoff`, `--aa`, `--effects`, `--simulations` and `--seed`.
- Removed SDK exports for manual comparisons, policy, planning, analysis, evidence export, evaluation requests and progress, drafts, and the old learning driver. Removed TypeScript subpaths `@acclimate/sdk/evaluation/policy`, `@acclimate/sdk/evaluation/artifacts`, `@acclimate/sdk/evaluation/analysis` and `@acclimate/sdk/evaluation/progress`. The learning subpath now exposes the bundle learning loop.
- Removed startup settings `ACCLIMATE_CRITIC_MODEL`, `ACCLIMATE_CRITIC_ENDPOINT`, `ACCLIMATE_CRITIC_TOKEN`, `ACCLIMATE_LEARNING_REVIEW_SECONDS`, `ACCLIMATE_LEARNING_PARENT_MAX_REUSES`, `ACCLIMATE_LEARNING_PARENT_MAX_AGE_SECONDS`, `ACCLIMATE_LEARNING_PAIR_BUDGET`, `ACCLIMATE_LEARNING_MAX_REPETITIONS`, `ACCLIMATE_LEARNING_CALIBRATION_REPETITIONS`, `ACCLIMATE_LEARNING_MAX_STEPS_BETWEEN_AUDITS`, `ACCLIMATE_LEARNING_MAX_CHAIN_AGE_SECONDS`, `ACCLIMATE_LEARNING_CALIBRATION_ATTEMPTS`, `ACCLIMATE_LEARNING_FAILURE_WINDOW_SECONDS`, `ACCLIMATE_PROPOSAL_GROWTH_FLOOR_BYTES`, `ACCLIMATE_EVALUATION_ABANDON_SECONDS`.
- Removed Changes, draft, comparison and evaluation screens, along with connection learning, outcome lookup, review and field controls.

### Added

- Enrolled bundles run five-sample optimization rounds with screening, evaluation, automatic release on adoption, and private held-out monitoring. The service owns the tasks and the `acclimate-executor` container runs each rollout in a sandbox. The console's Learning tab covers setup, task import and review, Try, round history, usage, rollback and revisioned improvement memory.
- Applications can pin a job to a verified version and feed back a known answer with `createAcclimate().job(...).expect(...)` in TypeScript or `Acclimate().job(...).expect(...)` in Python. The workspace principal route identifies the calling principal and its rights.
- Both SDKs deliver immutable bundles with verified caching. Channel preparation confirms the release online for each job. Exact-version reads can opt into verified cached content after eligible transport failures or HTTP 503.
- Native plugins prepare bundles for Codex, Claude, Pi and Cursor. The native repository starter retains partial diffs when an agent task fails.
- `acclimate pull` saves a released payload.
- Python errors share the `AcclimateError` base with a stable `code`. `ApiError.request_id` carries the HTTP error body's `requestId`. Invalid arguments raise `UsageError`, a `ValueError` subclass.
- `npm run local:up` picks free ports, prepares the `local-demo` workspace and writes `env.sh` and `ca-bundle.pem`. `npm run local:trust` trusts the local certificate.
- [OpenAPI](contracts/openapi.json) documents the workspace HTTP API. The [learning contract](contracts/learning.md) covers enrollment, tasks, trials, round history and improvement memory.
- The service runs migrations through `0027_provider_key_check.sql`. Follow the backup and upgrade procedure before migrating an existing database. [Deployment instructions](deploy/README.md#upgrade-to-the-learning-loop-schema)
- Task review: `POST …/learning/tasks/confirm` confirms up to 100 held-out tasks at once, `POST …/learning/tasks/{id}/recheck` and `POST …/learning/tasks/recheck` rerun failed admission checks without a new revision, `GET …/learning/tasks` takes `confirmed`, `GET …/learning/tasks/imports` lists the 50 most recent imports, and a failed trial reports `error: {code}`. The TypeScript client adds `confirmLearningTasks`, `recheckLearningTask`, `recheckLearningTasks` and `listLearningImports`. The console adds split and **Needs confirmation** filters, **Confirm all shown**, **Run check again**, an Imports section, task IDs with a copy button and the trial score.
- Rounds record `failureCause: {code, message}`, and the loop reports `nextRoundAt` and `evolveTasksNeeded` while it waits. Blocked versions carry `roundId` and `roundNumber`. The console shows the cause on a failed round and in the paused banner, the next round time and tasks needed, and a **Roll back this release** button on the held-out alert. The [learning contract](contracts/learning.md#codes-a-script-reads) lists the codes a script reads.
- `acclimate-service --list-executor-tokens` lists executor credentials without their tokens, and `acclimate-service --reset-provider-keys --confirm` deletes every stored workspace provider so the service can start with a new key. The executor reports health through `acclimate-executor --health` (`ACCLIMATE_EXECUTOR_HEALTH_FILE`), which both Compose files use as its health check.
- `examples/learning/example-agent-tasks.jsonl` holds 60 tasks for the local stack's **Example agent** bundle. [Sample tasks](examples/learning/README.md)
- Two runnable examples in TypeScript and Python, each with a documentation walkthrough: `examples/support-agent/` answers with the released bundle and reports a correction with `job.expect()`, and `examples/ticket-triage/` publishes a bundle, imports 64 labelled tickets and runs the learning loop from one script. They replace `examples/python-support-agent/`, which targeted the removed evaluation flow. The local stack's `env.sh` now also exports `ACCLIMATE_URL` and `ACCLIMATE_WORKSPACE`. [Examples](examples/README.md)
- Added the `test:learning-e2e` check, which runs the service and a real executor against a scripted model endpoint. The self-improvement memory experiment is parked until it is ported to the executor. [Experiment](examples/self-improvement-memory/README.md)
