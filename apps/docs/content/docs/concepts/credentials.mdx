Every request to the service carries a credential. This page says which kind to give an application, a script or an executor, and what each one allows.

## Credential types

| Credential | Who issues it and where | What it can do |
| --- | --- | --- |
| Connection credential | A workspace administrator, on a connection in **Connections**, with **Create read credential** | Read the released version for that connection's bundle and channel, and nothing else |
| Receipt credential | A workspace administrator, on the same connection, with **Create reporting credential** | Report which version a job started with. It cannot read a bundle. |
| Machine token | A workspace administrator, on **Members** under **Machine tokens**, with **Issue token** | Call the API for one workspace with the rights you tick |
| Executor credential | The operator, with `acclimate-service --create-executor-token` | Let an executor take learning work from the service. It belongs to no workspace. |

Each secret is shown once. Connection and receipt credentials start with `aci_`. Machine tokens start with `acm_` and expire after 90 days unless you choose another period from 1 to 365 days.

An operator can also define machine tokens in the service's `ACCLIMATE_AUTH` setting. See [Service](/docs/reference/configuration#service).

## Rights

A machine token carries one or more of three rights: read, write and promote. The console labels them **Read content**, **Write content** and **Promote releases**. Each right stands alone, so promote does not include write and write does not include read.

| To do this | The token needs |
| --- | --- |
| Resolve a channel and prepare a version, with `job()`, `client.prepare()` or `acclimate pull` | read |
| Report an outcome with `job.expect()` | write, and read for the `job()` call before it |
| Import, create, edit or retire tasks, or run a trial | write |
| Add a version to a bundle | write |
| Publish a new bundle with its first release | write and promote |
| Release a version to a channel | promote |
| Turn on learning or change its settings | promote |
| Start, pause, resume or stop a loop, or roll back a round | promote |

A script that releases a new version, as in [Release a version](/docs/guides/release-and-roll-back#release-a-version), needs read, write and promote.

The [support agent example](/docs/examples/support-agent) needs read and write. The [ticket triage example](/docs/examples/ticket-triage) needs all three: write and promote to publish its bundle, write to import the tickets, promote to change the learning settings and start the loop, and read for every other step.

A machine token cannot list held-out tasks. A task list gives it the evolve tasks and only a count of the held-out tasks, and it cannot edit, retire or recheck a held-out task.

In the console, a member's role takes the place of rights. A Viewer can read, and an Editor can also write and release a version. Learning settings and the start, pause, stop and roll back controls need an Administrator.

Some actions need a person signed in to the console, whatever rights a token carries:

- Issue, rotate or revoke a machine token: an Administrator
- Save the model provider: an Administrator
- Confirm held-out tasks: an Editor or an Administrator
- Export held-out tasks: any signed-in member
