title: Glossary
description: Learn the terms used in the console, SDKs, CLI, and Acclimate documentation.
---

Each term has one meaning across the console, SDKs, CLI, and these docs. Where the API or SDK uses an older name for the same thing, the entry says so. It is the same record, not a second concept.

## Content and delivery

| Term | Meaning |
| --- | --- |
| Workspace | The scope for bundles, connections, evaluators, and the people who can access them. SDK arguments and routes call its ID `projectId` (Python `project_id`). |
| Bundle | A named collection of the instructions, skills, and approved memory one agent uses. |
| Payload | The JSON form of a bundle's files. It has `schemaVersion: 1` and a `files` list, each with a `path`, a `kind` of `instruction`, `skill`, or `memory`, and its `text`. `compare --payload` and `pull` read and write this format. |
| Version | An immutable snapshot of a bundle's payload. Its SHA-256 **digest** identifies the exact bytes a client verifies before using them. |
| Channel | A named pointer, such as `stable`, to the version new jobs should use. A **release** moves it. |
| Connection | The link between one application and the workspace, bundle, and channel it uses. SDK arguments call its ID `integrationId`. |
| Release | A decision to point a channel at a version. Restoring an earlier version creates a new release. Some console pages say *publish* for a bundle's first release. |
| Outcome | Your application's result for one task on a specific version. It can carry a correction your application approves for future proposals. |

## Comparing a change

| Term | Meaning |
| --- | --- |
| Parent | The version a change starts from, usually what a channel serves today. |
| Candidate | The proposed new version. It records its parent. A **draft** is a candidate you are still editing in the console. |
| Proposal | A suggested change to a bundle, with a candidate version once the change is ready. |
| Case | One saved task your evaluator runs. It has a public `caseId`, a private `input`, and a private `expected` answer. |
| Arm | One side of a comparison: the parent arm or the candidate arm. Each arm runs your agent with that version's content. |
| Pair | One case run on both arms with the same grader. Pair counts in results say how many cases have scores on both sides. |
| Coverage | How many of the expected pairs have usable scores, such as `3/3`. Partial coverage means some pairs failed or were not graded. The `coverage` command is different: it lists the local files the evaluator fingerprints. |
| Comparison | The recorded results of running a parent and candidate on the same cases with the same grader. |
| Evaluator | The process in your environment that runs a comparison. It loads your application module, calls your agent on each arm, grades each output, and reports the scores. The `acclimate-eval` and `python -m acclimate` CLIs are evaluators. |
| Application module | The `application.mjs`, `application.mts`, or `application.py` file that exports your `cases`, an `execute` function that runs your agent, and a `grade` function. |
| Descriptor | The public summary of your evaluator: its case IDs and the revision hashes of its code, cases, and grader. The `describe` command prints it. A comparison is only accepted from an evaluator whose descriptor matches. |
| Evaluator config | The private JSON file (`evaluator.json`) that tells an evaluator which service and workspace to use, its machine credential, and where its journal lives. The examples call its path `EVALUATOR_CONFIG`. |
| Handoff | A request to evaluate one candidate against its parent, saved as `evaluation-request.json`. Handoff and **evaluation request** are the same thing: the console and API say evaluation request, and the CLI flag is `--handoff`. |
| Run name | The name you give a CLI comparison with `--name`. Reusing it resumes that comparison. The console shows it on the change. |
| Journal | The evaluator's private local record of a comparison in progress, kept under the evaluator config's `journalRoot`. It lets an interrupted comparison resume without running finished work again. |
| `--live` | The CLI flag that allows a comparison to call your agent with real model or tool access, using your application's own credentials. Commands that would make those calls refuse to start without it. |
| Policy | A JSON file of release thresholds, such as "no case may regress". `--policy` applies it to a comparison and reports a **verdict**: pass, fail, or indeterminate. See [quality policies](/docs/guides/evaluate-a-change). |
| Indeterminate | A policy verdict meaning the evidence cannot decide pass or fail, for example because coverage is partial or a required cost was not measured. Treat it as "not yet shown safe". |
| Receipt | The record of a policy verdict the evaluator submits to the workspace with the policy's digest, so release review can see which policy was applied. `policyReceipt.status` is `recorded` when the service confirmed it. |

## People and access

| Term | Meaning |
| --- | --- |
| Operator | A person who runs the Acclimate service. Operators create or adopt workspaces, and issue machine credentials such as evaluator configs. On the [local stack](/docs/get-started/run-locally), you are the operator. |
| Administrator | A workspace member who manages that workspace's people and settings. |
| Adoption | An operator taking administrator membership of an existing workspace that has no members yet, with a recorded reason. `npm run local:up` adopts `local-demo` for you. |

Older SDK arguments and routes say `projectId` for the workspace ID and `integrationId` for the connection ID. The [HTTP API overview](/docs/reference/http-api) lists the corresponding routes.
