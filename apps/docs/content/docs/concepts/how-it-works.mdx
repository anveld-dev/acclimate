## Versioned delivery

A workspace owns bundles and connections. Import instructions, skills and memory into a bundle. Each version is immutable and carries the digest of its exact bytes. A release points a channel such as `stable` at a version. A connection tells the SDK which bundle and channel the application uses.

On each job start, the SDK resolves the channel, fetches and verifies the payload, and prepares job-local files. An active job keeps its pinned version through subsequent releases. Optional delivery receipts let a workspace see what version an application reported using. [Deliver content to jobs](/docs/guides/deliver-content)

## Learning loop

An enrolled bundle runs recurring evaluations on the released version. The app runs the agent and grades five rollouts per case. An outcome with a known expected result becomes an evolve case. The evaluator keeps a fixed held-out split and reports its score for monitoring only.

Phase 3 establishes baseline scores while keeping the release each round. In phase 4 the optimizer will propose and screen five candidates, score the survivors on the evolve split and select a version to retain. An adoption will release that version on the learning channel and record its diagnosis and results in improvement memory.
