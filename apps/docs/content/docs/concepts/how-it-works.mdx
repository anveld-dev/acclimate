## Versioned delivery

A workspace owns bundles and connections. Import instructions, skills and memory into a bundle. Each version is immutable and carries the digest of its exact bytes. A release points a channel such as `stable` at a version. A connection tells the SDK which bundle and channel the application uses.

On each job start, the SDK resolves the channel, fetches and verifies the payload, and prepares job-local files. An active job keeps its pinned version through subsequent releases. Optional delivery receipts let a workspace see what version an application reported using. [Deliver content to jobs](/docs/guides/deliver-content)

## Learning loop

1. On the workspace's **Members** page, under **Model provider**, configure an OpenAI-compatible model provider, its key and allowed models.
2. Open the released bundle’s **Learning** tab. Choose its channel, task model and a different judge model.
3. Import CSV, JSONL, a spreadsheet or pasted examples. Each task pairs an input with an expected answer or grading criteria. Review the task cards and confirm held-out material. Use **Try task** to inspect an executor run before starting a round.
4. Start learning once at least 20 evolve tasks and 20 held-out tasks pass admission. The same floor applies on resume.

The executor runs each rollout in a fresh sandbox and grades it outside the sandbox. An exact-match task scores 1 or 0. A criteria task is judged three times: it passes when at least two judgments pass every criterion, and its score is the share of criteria met. The service scores candidates on evolve tasks and automatically releases the selected version to the channel, with no approval step. Held-out scores monitor regressions. A clear held-out drop after an adoption, confirmed by a second measurement, reverts the release automatically. Inspect the round, usage and release history in the console or roll back an adopted round.
