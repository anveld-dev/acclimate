## Versioned delivery

A workspace owns bundles and connections. Import instructions, skills and memory into a bundle. Each version is immutable and carries the digest of its exact bytes. A release points a channel such as `stable` at a version. A connection tells the SDK which bundle and channel the application uses.

On each job start, the SDK resolves the channel, fetches and verifies the payload, and prepares job-local files. An active job keeps its pinned version through subsequent releases. Optional delivery receipts let a workspace see what version an application reported using. [Deliver content to jobs](/docs/guides/deliver-content)

## Learning loop

Each round scores the incumbent on the evolve split, then proposes five candidates. The optimizer receives the full incumbent harness, evolve case inputs, scores, rollout traces and errors, prior round summaries and diffs for the current setting, and pinned improvement memory. A workspace member with write access can add setup cases. The enrolled app principal can also report production inputs and known expected answers as evolve cases.

The scanner checks the proposed content and the selector screens candidates before evaluation. The evaluator grades five rollouts per case for each survivor. The selector adopts a candidate or keeps the incumbent. An adoption immediately releases the version and adds an attempt to improvement memory, which future rounds use and jobs never receive. The evaluator scores the retained version against its private held-out split for monitoring only. Inspect scores, candidates and improvement memory in the bundle’s **Learning** tab.
