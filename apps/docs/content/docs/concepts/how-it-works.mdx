## Versioned delivery

A workspace owns bundles and connections. Import instructions, skills and memory into a bundle. Each version is immutable and carries the digest of its exact bytes. A release points a channel such as `stable` at a version. A connection tells the SDK which bundle and channel the application uses.

On each job start, the SDK resolves the channel, fetches and verifies the payload, and prepares job-local files. An active job keeps its pinned version through subsequent releases. Optional delivery receipts let a workspace see what version an application reported using. [Deliver content to jobs](/docs/guides/deliver-content)

## Planned self-improvement loop

The loop ships in a later phase. For each enrolled bundle, the loop will score the incumbent on the evolve split. The optimizer proposes five candidates based on scores, traces and errors, previous rounds and improvement memory. It screens the candidates before execution and evaluates the survivors on the evolve split. The selector keeps the incumbent or adopts a survivor, releasing it to the learning channel and recording its diagnosis and results in improvement memory.

The evaluator keeps a fixed held-out split and scores the retained version each round for monitoring. The optimizer receives evolve feedback. An application outcome with an expected answer becomes an evolve case. Your application runs the agent and grades its work.
