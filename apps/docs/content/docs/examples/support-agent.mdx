This walkthrough is for a developer who wants to see delivery and learning work together. `examples/support-agent/` answers one support request with the version released on a channel. You run it, improve its bundle with 60 sample tasks and report a correction.

The application is `agent.ts` with its prompt helper `prompt.ts`, or `agent.py`. Do [Set up once](/docs/examples#set-up-once) first. The example uses the **Example agent** bundle the local stack publishes on `stable`, whose instructions are two sentences:

```text
You are a support agent for a small software company.

Answer in two short paragraphs. Ask one clarifying question when the request is ambiguous.
```

## Answer a request

The application calls an OpenAI-compatible model itself. These values fit the proxy from [Set up a local model proxy](/docs/get-started/first-learning-round#set-up-a-local-model-proxy):

```sh
export OPENAI_BASE_URL=http://127.0.0.1:8317/v1
export OPENAI_API_KEY='<proxy-key>'
export AGENT_MODEL=gpt-6-luna
```

The model IDs on this page are examples. Use one your provider serves. On Linux, use the address the proxy listens on.

The reply follows the instructions but cannot say what the company does about a duplicate charge, because nothing in the bundle tells it. The part of the application that uses Acclimate is short:

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

```ts title="agent.ts"
// Reads ACCLIMATE_URL, ACCLIMATE_WORKSPACE and ACCLIMATE_TOKEN.
const acclimate = createAcclimate();

// Pin the released version for this job. Every job re-reads the channel, so a release made by
// the learning loop reaches the next job without a deploy.
const job = await acclimate.job(process.env.ACCLIMATE_BUNDLE_NAME ?? 'Example agent', {
  channel: process.env.ACCLIMATE_CHANNEL ?? 'stable',
  input: request,
});
const reply = await complete(systemPrompt(job.version.payload), request);
console.log(reply);
// Keep the version with the result, so you can tell later which instructions produced it.
console.error(`\nAnswered with version ${job.version.version.id} (${job.version.version.digest}).`);
```

</Tab>
<Tab value="Python">

```python title="agent.py"
# Reads ACCLIMATE_URL, ACCLIMATE_WORKSPACE and ACCLIMATE_TOKEN.
acclimate = Acclimate.from_env()

# Pin the released version for this job. Every job re-reads the channel, so a release made by
# the learning loop reaches the next job without a deploy.
job = acclimate.job(
    os.environ.get("ACCLIMATE_BUNDLE_NAME", "Example agent"),
    channel=os.environ.get("ACCLIMATE_CHANNEL", "stable"),
    input=args.request,
)
version = job.version
reply = complete(system_prompt(version["payload"]), args.request)
print(reply, flush=True)
# Keep the version with the result, so you can tell later which instructions produced it.
print(f"\nAnswered with version {version['version']['id']} ({version['version']['digest']}).", file=sys.stderr)
```

</Tab>
</Tabs>

`job()` finds the bundle by name, resolves the channel, downloads the version if it is not cached and verifies its digest. `systemPrompt` (`system_prompt` in Python) renders the files the way a [learning rollout](/docs/concepts/how-it-works#how-a-rollout-runs-your-bundle) does, so the loop measures the prompt your jobs run with.

## Improve the bundle with the sample tasks

[`examples/learning/example-agent-tasks.jsonl`](https://github.com/anveld-dev/acclimate/blob/main/examples/learning/example-agent-tasks.jsonl) holds 60 support requests, one row per line. Each has the request, a reference reply and four pass-or-fail criteria:

```json
{
  "request": "I was charged twice for my March subscription. Can you fix this?",
  "ideal_reply": "Sorry about the double charge. I can see why that is worrying, and a duplicate payment for the same month is always refunded in full. …",
  "rubric": [
    "Answers in at most two short paragraphs",
    "Does not ask a clarifying question about the request",
    "States that the duplicate charge will be refunded",
    "Gives a refund timeframe of five business days"
  ]
}
```

The criteria include company facts, such as the refund timeframe, that the loop has to learn from the tasks the agent fails.

1. In the console, open the **Example agent** bundle's **Learning** tab. Set **Task model** to the same model as `AGENT_MODEL`, choose a different **Judge model** and choose **Save learning settings**.
2. Under **Import material**, choose `example-agent-tasks.jsonl`, then choose **Import tasks**.
3. Wait while the executor checks each task. This file gives 34 evolve tasks and 26 held-out tasks. In the run below all 60 were admitted.
4. Choose **Start**.

[Run a learning loop](/docs/guides/learning-loop) explains each step.

### What the first round changed

A real first round, with `gpt-6-luna` as the task model, `gpt-6.2-sol` as the judge model, `gpt-6.2-astra` as the optimizer and five rollouts per task:

| | Evolve tasks | Held-out tasks |
| --- | --- | --- |
| Version before the round | 0.43, with 5 of 170 rollouts passing | 0.41, with 3 of 130 rollouts passing |
| Adopted version | 0.99, with 161 of 170 rollouts passing | 0.53, with 10 of 130 rollouts passing |

A score gives partial credit for each criterion met, and a rollout passes only when it meets all four. See [How answers are scored](/docs/concepts/how-it-works#how-answers-are-scored).

The five candidates scored between 0.95 and 0.99. The adopted one replaced the two sentences with a product guide of about 5,800 characters that begins:

```text
You provide first-party support for our workspace web app. Unless the customer explicitly names another product, their account, documents, subscription, and integrations are in this workspace. Use the product guide below. State documented facts directly; don't substitute generic industry practices or ask the customer to identify our product.
…
- Each upload is limited to 100 MB. Compress a larger file or split it into parts within that limit.
- Full workspace exports start at Settings → Workspace → Export data. The download link is emailed and is valid for 7 days; after expiry, start a new export to get a fresh link.
```

The held-out score moved much less. The optimizer sees only the evolve tasks, and most requests in this file turn on a company fact of their own, so the guide lacks the facts the held-out tasks ask about. To close that gap, add tasks or [corrections](#report-a-correction) that cover those requests, or write the facts into the bundle yourself.

The round ran 1,280 rollouts in about 95 minutes on one Codex sign-in with four rollouts at a time, while another example was also running.

## Report a correction

When a support lead rewrites a reply, report the rewrite and the request becomes a learning task. Until you save the bundle's learning settings, the service answers 404 and the example prints `Learning is not set up for this bundle`.

Save the rewrite in a file and pass it with `--expected`:

```sh
cat > corrected.txt <<'EOF'
Yes, you can pause a subscription for up to three months. Your data stays in place and you are not billed while it is paused.

An account owner can pause it under Settings, then Billing, then Pause subscription. It resumes by itself on the date you choose.
EOF
```

The example prints the split from the receipt. The judge model then drafted six criteria from the corrected reply, such as "Confirms that a subscription can be paused for up to three months." The request appears on the **Learning** tab as a card marked **Production outcome**. A held-out one waits for you under **Needs confirmation**. One correction does not start a round. See [Report production outcomes](/docs/guides/learning-loop#report-production-outcomes).

## Use your own bundle

Set `ACCLIMATE_BUNDLE_NAME` and `ACCLIMATE_CHANNEL` to run on another bundle. On a service without the example bundle, create one under **Bundles** in the console, or [publish a bundle from a file](/docs/guides/release-and-roll-back#publish-a-bundle-from-a-file).
