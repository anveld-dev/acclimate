---
title: Install the SDKs
description: Install the TypeScript or Python SDK from its registry, from verified release files, or from a source checkout.
---

Install the SDK in the environment that runs your agent. Use the SDK release that matches your service's version. See [versioning and compatibility](/docs/reference/versioning).

## Prerequisites

| To use | You need |
| --- | --- |
| TypeScript SDK and `acclimate-eval` | Node.js 22.22 or later |
| Python SDK and `acclimate` (or `python -m acclimate`) | Python 3.11 or later |
| File preparation | Linux or macOS, and a private local staging directory |
| The [local stack](/docs/get-started/run-locally) | Docker with Compose v2.24 or later, an Acclimate checkout, Node.js with npm, and Python 3.9 or later |


## Install from the registry

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

Use Node.js 22.22 or later.

```sh
npm install @acclimate/sdk
npx acclimate-eval --help
```

The SDK includes the `acclimate-eval` command. Install a plugin package, such as `@acclimate/codex-plugin`, alongside the SDK when you need [native preparation](/docs/guides/deliver-content#choose-a-native-integration).

</Tab>
<Tab value="Python">

Use Python 3.11 or later. The SDK uses only the standard library and needs no Node.js.

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install acclimate-sdk
.venv/bin/acclimate --help
```

The distribution is named `acclimate-sdk`. Import it as `acclimate`. The `acclimate` command and `python -m acclimate` run the same CLI. On Python 3.10 or earlier, importing the package fails with a message that names the version it found.

</Tab>
</Tabs>

If the registry doesn't have your release yet, install from the release files below. Registry publishing is a separate maintainer step after each GitHub Release.

## Install from verified release files

Use release files for an air-gapped machine, or when your operator distributes Acclimate directly.

Choose a version on the [GitHub Releases page](https://github.com/anveld-dev/acclimate/releases). Download `manifest.json`, `SHA256SUMS` and every file that `SHA256SUMS` lists into one directory. From that directory, verify the files before installing anything. On Linux, run `sha256sum --check SHA256SUMS`. On macOS, run `shasum -a 256 --check SHA256SUMS`.

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

Run the install command from your app directory with the matching file. This example uses release 0.1.0.

```sh
npm install --offline --ignore-scripts /absolute/path/to/release/acclimate-sdk-0.1.0.tgz
./node_modules/.bin/acclimate-eval --help
```

</Tab>
<Tab value="Python">

Install the wheel without contacting a package index. This example uses release 0.1.0.

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install --no-index --no-deps /absolute/path/to/release/acclimate_sdk-0.1.0-py3-none-any.whl
.venv/bin/acclimate --help
```

</Tab>
</Tabs>

## Build from a source checkout

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

From the repository root, use Node.js 22.22 or later and Python 3.11 or later to build every artifact and check it against isolated consumers.

```sh
npm ci --ignore-scripts
npm run pack:verify
```

The command writes the SDK and plugin tarballs, Python wheel, starter archives, manifest and checksums to `artifacts/releases/<version>/`. To build the same version again, pass `-- --output /path/to/new-release` to `npm run pack:verify`.

</Tab>
<Tab value="Python">

Building the wheel needs only Python. Write the output outside the checkout:

```sh
python3.11 -m pip wheel --no-deps --wheel-dir /tmp/acclimate-wheel ./python
# or, with uv
uv build --wheel --out-dir /tmp/acclimate-wheel ./python
```

The build leaves no `build/` or `.egg-info` directories in the checkout. It downloads the `flit_core` build backend unless your index or cache already has it. Install the result with the offline `pip install` command above. To install straight from the checkout instead, run `pip install ./python`.

</Tab>
</Tabs>
