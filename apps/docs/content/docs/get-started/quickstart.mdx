title: Run your first comparison
description: Connect an existing agent and grader, then compare a saved candidate with its parent.

Connect an agent you already run and grade one bundle change on a saved task. You will get paired results for the parent and candidate in your workspace.

## Try it locally (no server)

Score a change on your own machine before you set up the service. A local run needs no workspace, evaluator config, handoff, or published bundle. It uses the same pairing, arm order, and grading as a service comparison, but the result is advisory and never release evidence.

Put the current instructions in one folder and the changed instructions in another. Files under `skills/` become skill files, files under `memory/` become memory files, and every other file becomes an instruction. Hidden files are skipped. A payload JSON file such as `{"schemaVersion":1,"files":[{"path":"AGENTS.md","kind":"instruction","text":"..."}]}` also works.

```text
parent/AGENTS.md
candidate/AGENTS.md
candidate/skills/refunds/SKILL.md
```

Add an adapter next to them. `execute` must pass `bundle` to your agent. If it ignores the bundle, both arms behave the same, and the comparison warns that every output was identical.

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

```ts title="application.mjs"
import { runAgent, scoreResult, savedCases } from './dist/support-agent.mjs';

export const cases = savedCases;

export async function execute({ bundle, input, signal }) {
  const instructions = bundle.payload.files.filter((file) => file.kind === 'instruction');
  const result = await runAgent({ instructions, task: input, signal });
  return { output: result.answer, usage: { costUsd: result.costUsd } };
}

export async function grade({ output, expected }) {
  return { reward: scoreResult(output, expected) };
}
```

Check the adapter on one case, then compare the two folders:

```sh
./node_modules/.bin/acclimate-eval try --live --payload candidate
./node_modules/.bin/acclimate-eval compare --local --parent parent --candidate candidate --live
```

</Tab>
<Tab value="Python">

```py title="application.py"
from acclimate.evaluation import ExecutionResult, GradeResult
from support_agent import run_agent, score_result, saved_cases

cases = saved_cases

def execute(run):
    instructions = [f for f in run.bundle["payload"]["files"] if f["kind"] == "instruction"]
    result = run_agent(instructions=instructions, task=run.input, cancellation=run.cancellation)
    return ExecutionResult(output=result.answer, usage={"costUsd": result.cost_usd})

def grade(run):
    return GradeResult(reward=score_result(run.output, run.expected))
```

Check the adapter on one case, then compare the two folders:

```sh
python -m acclimate try --live --payload candidate
python -m acclimate compare --local --parent parent --candidate candidate --live
```

</Tab>
</Tabs>

`try` runs `execute` and `grade` once and prints the output. It also checks every returned shape, including JSON-safe output, a finite reward, `usage` keys, and the `executionStatus` value. Problems that `try` reports would otherwise become missing scores in a paid run. Add `--case ID` to choose cases.

`compare --local` prints the same per-case table as a service comparison. It writes `local-report.json`, the output artifacts, and both payloads to a private folder under `.acclimate/local/`, or to the folder you pass with `--out`. Add `.acclimate/` to `.gitignore`. Add `--policy quality-policy.json` for an advisory verdict, and `--max-cost-usd 2` or `--deadline 15m` to bound spend. `--live` is required only when the evaluator calls models or paid services. Installed `application` adapters always do.

A local report can't be uploaded as release evidence. The service accepts results only for versions it stores and an attempt it issued. To gate a release, replay the same candidate against the service with the `compare` command printed at the end of the local run. That command passes `candidate.payload.json` from the report folder.

## Compare against the service

Have a published bundle and channel available in your workspace. In the console, use **Workspace → Bundles → New bundle** if you need to publish your starting instructions. [Install an SDK](/docs/get-started/install), and ask your operator for a [private evaluator config](/docs/operate/evaluator-access) for that workspace. The examples use `EVALUATOR_CONFIG` as a shell variable pointing to that file.

## Connect the evaluator to your agent

Create `application.mjs` or `application.mts` for Node.js, or `application.py` for Python, in the evaluator's working directory. Export `cases`, `execute`, and `grade`. Each case has a unique public `caseId`, private `input` and private `expected` answer. Give each arm a fresh isolated job if the agent's tools have side effects.

Replace the application imports in these recipes with your own agent, cases, and grader.

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

```ts title="application.mjs"
import { runAgent, scoreResult, savedCases } from './dist/support-agent.mjs';

export const cases = savedCases;
export const revisionFiles = ['package-lock.json'];

export async function execute({ bundle, input, signal, context }) {
  const result = await runAgent({ bundle, task: input, signal, job: context });
  return { output: result.answer, usage: result.measuredUsage };
}

export async function grade({ output, expected }) {
  return scoreResult(output, expected);
}
```

</Tab>
<Tab value="Python">

```py title="application.py"
from acclimate.evaluation import ExecutionResult, GradeResult
from support_agent import run_agent, score_result, saved_cases

cases = saved_cases
revision_files = ["support_agent.py", "requirements.lock"]

async def execute(run):
    result = await run_agent(bundle=run.bundle, task=run.input, cancellation=run.cancellation)
    return ExecutionResult(output=result.answer, usage=result.measured_usage)

def grade(run):
    verdict = score_result(run.output, run.expected)
    return GradeResult(reward=verdict.reward, explanation=verdict.explanation)
```

</Tab>
</Tabs>

Set the revision file list to the paths your app actually uses. Return bounded JSON as the gradeable output and a finite numeric reward from the grader. Your application chooses how to pass the pinned bundle to the agent.

## Describe the installed evaluator and save a candidate

From the directory containing the adapter, inspect its coverage and print its public descriptor. Use the commands for your installed SDK.

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

```sh
./node_modules/.bin/acclimate-eval coverage
./node_modules/.bin/acclimate-eval describe
```

</Tab>
<Tab value="Python">

```sh
python -m acclimate coverage
python -m acclimate describe
```

</Tab>
</Tabs>

The local coverage report can contain private paths. Paste the **describe** JSON into **Review release** for your saved candidate under **Changes** in the console. Create the evaluation request and download `evaluation-request.json` into the application's environment.

The live flag authorizes model-backed execution with your application's own credentials. Inspect the parent and candidate means, pair coverage, and individual case scores in the result and console. When you are ready to set thresholds, [add a quality policy](/docs/guides/evaluate-a-change).
