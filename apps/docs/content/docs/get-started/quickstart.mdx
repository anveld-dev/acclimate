You need:

- Docker, running. See [Prerequisites](/docs/reference/local-stack#prerequisites) for the versions.
- Node.js 22.22 or later with npm.
- Python 3.9 or later for the stack scripts, or 3.11 or later for the Python check.

## Start the stack

Clone the repository and start the stack:

```sh
git clone https://github.com/anveld-dev/acclimate.git
cd acclimate
npm run local:up
npm run local:trust
```

`local:up` starts the service, the console and sign-in, and prints the console URL, a login and its initial password. The first start takes a few minutes, or 10 to 20 when it builds from source. `local:trust` makes your browser trust the stack's HTTPS certificate. It asks you to type `trust` and may ask for your password.

Open the console URL and sign in. The `local-demo` workspace already holds a [bundle](/docs) named **Example agent**, with one instruction file released on the `stable` channel.

## Connect your application

A connection links one application to one bundle and channel.

1. In the console, open **Connections** and choose **New connection**. Enter a display name, choose the **Example agent** bundle and the `stable` channel, then choose **Create connection**. The console opens the connection's **Setup** tab.

2. Under **Read credential**, choose **Create read credential**. The secret is shown once, so copy it now.

3. Open the connection's **Settings** tab and copy the **Connection ID**.

4. In a shell at the root of the checkout, install the Node.js dependencies and load the stack's client settings. `env.sh` sets `ACCLIMATE_URL`, `ACCLIMATE_WORKSPACE` and `BUNDLE_ID`, and makes Node.js and Python trust the stack's certificate.

   ```sh
   npm ci --ignore-scripts
   source .local/stack/env.sh
   ```

5. Set the remaining variables. `ACCLIMATE_SCOPE` is a stable name for this application. It keeps this application's entries in the SDK's disk cache of verified versions apart from other applications'.

   ```sh
   export ACCLIMATE_BUNDLE="$BUNDLE_ID"
   export ACCLIMATE_CONNECTION='<connection-id>'
   export ACCLIMATE_TOKEN='<credential-secret>'
   export ACCLIMATE_SCOPE='quickstart'
   ```

Run the delivery check in the same shell:

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

```sh
npm run example:delivery
```

</Tab>
<Tab value="Python">

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install ./python
source .venv/bin/activate
npm run example:delivery:python
```

</Tab>
</Tabs>

The check prepares the files for one job, a single run of your agent. It resolves `stable` to a version, downloads it, verifies its digest, reads every prepared file and cleans up, with no model calls. Both languages print one line:

```json
{"versionId":"<version-id>","digest":"<digest>","files":["instructions.md"],"checkedFiles":1,"reporting":"disabled"}
```

`reporting` is `disabled` because the check has no receipt credential. To run it from your own application, download it in TypeScript or Python from the **First delivery** step of the **Setup** tab. For recipes that connect your agent and report job starts, choose **Bundle & channel**, then **Full setup guide**.

## Publish your own bundle

1. Open **Bundles** and choose **New bundle**.
2. Choose **Write instructions**, **Import files** or **Import JSON**. In imported files, skills go under `skills/` and memory under `memory/`.
3. Enter a bundle name. **Publishing settings** holds the initial channel, `stable` by default, and the compatibility target, the agent SDK whose [rules](/docs/guides/coding-agents#rules-for-bundle-files) the service checks the files against. Keep **Generic · no native checks** for your own application. Choose **codex**, **claude**, **pi** or **cursor** only for a bundle that agent SDK runs. The target is fixed after creation.

Creating the bundle publishes its first version and releases it on that channel. Create a connection for it as above.
