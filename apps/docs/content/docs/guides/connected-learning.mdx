---
title: Set up connected learning
description: Turn approved corrections into proposed versions and evaluate them on private development and audit cases.
---

Connect an application so it can report outcomes and approved corrections. Acclimate can use that feedback to propose a change, schedule evaluations, and release approved content to the connection.

## Configure the connection

1. Ask your operator to [configure the service proposer](/docs/guides/service-generated-proposals) and provision distinct machine principals for outcomes and for evaluation. The outcome principal needs workspace `write`. The evaluator needs `read` and `write`. Keep a separate delivery credential.
2. In your Node evaluator, build development and held-out audit apps with `defineEvaluation` from `@acclimate/sdk/evaluation`. Use `connectedEvaluationDescriptor(app)` from `@acclimate/sdk/learning` to register each exact private build. Use distinct development and audit case IDs, dataset revisions, and private inputs. Keep inputs and expected answers in the app. Use rewards from 0 to 1 with the connected selection policies.
3. In **Connections**, open **Learning** for an enabled connection whose source channel has a published release. Enter the installation ID, machine principals, allowed paths, proposal allowance, and development and audit descriptors. Choose manual review or authorize automatic rollout. Releases apply to this connection. Automatic rollback defaults to enabled.
4. Supply the connection UUID as `connectionId` on your delivery client. Resolve once per fresh job and keep the verified version and delivery revision with its result.

By default, the proposer edits permitted existing files. If you want it to add or retire skills, use **Manage skill package permissions** to authorize the skill names separately.

## Report an outcome

Call the hook after the application's terminal result is durable. Give each logical outcome a stable UUID. Include only teaching summaries approved for the proposer.

```ts
import { createLearningOutcomeReporter } from '@acclimate/sdk/learning';

const reportOutcome = createLearningOutcomeReporter({
  client: outcomeClient,
  workspaceId,
  connectionId,
});

await reportOutcome(job.bundle, {
  outcomeId: job.outcomeId,
  status: 'failed',
  feedback: {
    expected: 'Require signed evidence before publishing an assertion.',
    observed: 'Published an assertion based on a draft receipt.',
  },
});
```

Use your durable outbox to retry saved outcomes across process restarts. To attach teaching later, call `outcomeClient.reportLearningCorrection` with the existing `outcomeId`, a new durable `correctionId`, and the approved `feedback`. A correction from an older delivery revision needs a private recheck on the current version.

## Run the evaluator

Default-export `{ development, audit: [...] }` from your installed evaluator module, using the same app definitions you registered. If you handle older corrections, add `recheck` to replay the original check on the supplied baseline. Declare `recheckExecution: 'model-free'` only when the callback runs without a model. See `docs/evaluator-operations.md` for the full callback recipe.

```sh
acclimate-learning --config /private/evaluator.json --connection "$CONNECTION_ID" \
  --installation "$INSTALLATION_ID" --apps ./dist/learning-evaluators.mjs
```

Add `--live` to authorize live execution. Keep the same private config and journal across restarts. Development comparisons screen proposed changes. By default, after three accepted development steps, the service checks the accumulated changes against the current delivery version. If that check passes, a separate held-out audit provides release evidence. Inspect the comparison records, remaining proposal allowance, and unused audit cohorts in the connection.

## Monitor a release

At the job's actual start, call `prepared.reportStarted()` on a fresh resolution with reporting enabled. Persist the returned receipt with the job and ensure the service received it before passing it as `startedReceipt` with the terminal outcome. Eligible outcomes can carry a `fieldAudit` assignment for a pinned control version. Use `createLearningFieldAuditor` with the separate evaluator principal to grade the recorded served output and run a read-only control replay on the same private input. Its default sample is 10% of eligible jobs.

Keep completed verdicts bound to the revision the job used. Only a verdict for the current revision can trigger automatic rollback. To inspect a job, use **Delivery → Find a reported outcome**. To restore an earlier delivered version or refresh from the source channel, use **Restore or refresh the delivery target** and enter a reason. The restore records a new release, and a fresh job receives it on its next resolution.
