---
title: Review, release, and roll back
description: Review paired evidence, promote the exact candidate, and restore a retained version when needed.
---

Review the candidate's files and recorded comparison, then decide whether future jobs should receive that version.

## Review in the console

Open a saved change in **Changes** and choose **Review release**. Check the files changed and the exact candidate and parent versions. Inspect case counts, paired grades, failed or missing results, and known usage. A complete comparison can record a losing candidate. Your quality policy and review determine whether to release it.

Evidence-based release requires a complete comparison for the candidate and its parent. The channel must still point to that parent. If the current channel moved after evaluation, review it again against the current baseline before trying an evidence-based release.

Inspect any recorded policy verdicts. A failed or indeterminate verdict can block publication. An authorized reviewer can acknowledge every current blocking receipt and give a reason for overriding it. If you publish without evaluation, give the required reason.

## Review and promote from the terminal

Use the [operator CLI](/docs/reference/operator-cli) with a scoped credential. Review the comparison and take the current channel revision from the result. Run the promotion separately once you approve it.

```sh
npm run operator -- review --workspace WORKSPACE --bundle BUNDLE --channel live --comparison COMPARISON
npm run operator -- promote --workspace WORKSPACE --bundle BUNDLE --channel live \
  --version CANDIDATE --comparison COMPARISON --expected-revision REVISION
```

If the revision conflicts, read the channel again and review the current target before making another decision.

## Restore a version

Open **Releases** in the console, select a retained version, and enter the reason for restoring it. The terminal equivalent is:

```sh
npm run operator -- rollback --workspace WORKSPACE --bundle BUNDLE --channel live \
  --version PREVIOUS --reason 'Regression observed' --expected-revision REVISION
```

A restore creates a new release and advances the revision. New jobs that resolve the channel can pick up the restored version. Jobs already prepared keep their pins. To restore a managed connection, use [the connection's delivery target](/docs/guides/connected-learning#monitor-a-release).
