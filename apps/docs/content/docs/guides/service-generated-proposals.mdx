---
title: Request a service-generated proposal
description: Ask the service to suggest a bounded file edit, then compare the candidate in your app.
---

Ask Acclimate to suggest a change to an existing bundle file. Pin the parent version, specify the permitted paths, and provide only evidence you are authorized to share.

## Enable the proposer

The deployment operator sets `ACCLIMATE_MODEL_ENDPOINT` to the full OpenAI-compatible chat-completions URL and privately supplies `ACCLIMATE_MODEL_TOKEN` and `ACCLIMATE_MODEL`. The service accepts `gpt-6.2-sol`, `gpt-6-luna`, or `gpt-5.6-luna` and refuses to start with any other value. The selected model drafts the proposed edits. Your application chooses the model and grader used for evaluation. This operation can incur model costs.

## Request and inspect the change

Run the [operator CLI](/docs/reference/operator-cli) with the workspace's proposal authority. Explicitly name each permitted existing path. Repeat `--evidence` for each approved summary.

```sh
npm run operator -- request-proposal --project PROJECT --bundle BUNDLE --parent VERSION \
  --path skills/retry-review/SKILL.md --hypothesis 'Improve review' --evidence 'Observed failure'
npm run operator -- proposal --project PROJECT --bundle BUNDLE --id PROPOSAL
```

The first command submits asynchronous work. Use the returned proposal ID to read its status. With no provider configured, an accepted request fails during processing.

The proposer can change text at the permitted paths and stores a candidate version with its rationale. Review its before-and-after files. Then [evaluate the candidate](/docs/guides/evaluate-a-change) with your app and make a [release decision](/docs/guides/review-and-release).

For a worked example from the repository, `examples/service-proposer/README.md` describes `npm run example:improve -- run-service --live`. It uses the configured service proposer, runs up to four Codex reviews of the pinned versions, and stops before promotion.
