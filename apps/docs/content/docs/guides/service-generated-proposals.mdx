---
title: Request a service-generated proposal
description: Ask the service to suggest a bounded file edit, then compare the candidate in your app.
---

Ask Acclimate to suggest a change to an existing bundle file. Pin the parent version, specify the permitted paths, and provide only evidence you are authorized to share.

## Enable the proposer

The deployment operator sets `ACCLIMATE_MODEL_ENDPOINT` to the full OpenAI-compatible chat-completions URL and privately supplies `ACCLIMATE_MODEL_TOKEN` and `ACCLIMATE_MODEL`. Use `gpt-6.2-sol` for the documented example, or give the name your gateway accepts. The service trims the name and requires 1–256 UTF-8 bytes with no control characters. Check that the endpoint supports the [chat-completions request and response fields](/docs/reference/configuration#proposer-and-critic) the service uses. The selected model drafts the edits. Your application chooses the model and grader used for evaluation. This operation can incur model costs.

## Request and inspect the change

Run the [operator CLI](/docs/reference/operator-cli) with the workspace's proposal authority. Explicitly name each permitted existing path. Repeat `--evidence` for each approved summary.

```sh
npm run operator -- request-proposal --workspace WORKSPACE --bundle BUNDLE --parent VERSION \
  --path skills/retry-review/SKILL.md --hypothesis 'Improve review' --evidence 'Observed failure'
npm run operator -- proposal --workspace WORKSPACE --bundle BUNDLE --id PROPOSAL
```

The first command submits asynchronous work. Use the returned proposal ID to read its status. With no provider configured, an accepted request fails during processing.

The proposer can change text at the permitted paths and stores a candidate version with its rationale. Generated changes are held to a stricter rule than skills you write: a generated file is Markdown, and its `SKILL.md` frontmatter may set or change only `name` and `description`. Any other key an author declared, such as `allowed-tools`, `hooks` or `model`, stays exactly as written, because a generated change must never grant tools or permissions. Review its before-and-after files. Then [evaluate the candidate](/docs/guides/evaluate-a-change) with your app and inspect [how connected learning releases changes](/docs/guides/review-and-release).

For a worked example from the repository, `examples/service-proposer/README.md` describes `npm run example:improve -- run-service --live`. It uses the configured service proposer, runs up to four Codex reviews of the pinned versions, and stops before promotion.
