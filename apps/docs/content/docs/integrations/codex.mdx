Use `@acclimate/codex-plugin` when your application runs agents with the Codex SDK. The plugin writes a verified bundle version into a private directory in the layout Codex reads, and your application starts the thread there.

| Requirement | Value |
| --- | --- |
| Plugin | `@acclimate/codex-plugin`, with one entry point |
| Agent SDK | `@openai/codex-sdk`, checked at 0.169.0. The plugin does not depend on it. |
| Runtime | Node.js 22.22 or later on Linux or macOS. See [Install the SDKs](/docs/get-started/install#prerequisites). |

## Install

Install the agent SDK beside the plugin and the Acclimate SDK. The plugin and the Acclimate SDK must come from the same Acclimate release.

```sh
npm install @acclimate/sdk @acclimate/codex-plugin @openai/codex-sdk@0.169.0
```

For release files, see [Install from verified release files](/docs/get-started/install#install-from-verified-release-files).

## Files the plugin writes

`prepare` writes each job's files into a new private directory. It fails before writing anything if the version breaks the [rules for bundle files](/docs/guides/deliver-content#rules-for-bundle-files).

| Bundle file | Written to |
| --- | --- |
| Instruction | `AGENTS.md` |
| Skills | `.agents/skills/<name>/`, with their supporting files |
| Memory | `.acclimate/memory/` |

Codex does not load the memory files. Add the ones you choose from `prepared.memoryFiles` to the prompt. Each entry has a `path`, `text` and `absolutePath`.

## Prepare and run a thread

Pass the delivery from `client.prepare()` to the plugin's `prepare`, which accepts the inputs in [Choose a native integration](/docs/guides/deliver-content#choose-a-native-integration). Your application supplies `client`, the IDs, `model`, `prompt` and `env`.

```ts
import { Codex } from '@openai/codex-sdk';
import { prepare } from '@acclimate/codex-plugin';

const delivery = await client.prepare({ workspaceId, bundleId, channel: 'stable', reporter });
const prepared = await prepare(delivery);
const thread = new Codex({ env }).startThread({
  workingDirectory: prepared.cwd,
  skipGitRepoCheck: true,
  model,
  sandboxMode: 'workspace-write',
  approvalPolicy: 'never',
  networkAccessEnabled: false,
  webSearchMode: 'disabled',
});
const turn = await thread.runStreamed(prompt);
let response = '';
for await (const event of turn.events) {
  if (event.type === 'turn.started') prepared.reportStarted();
  if (event.type === 'item.completed' && event.item.type === 'agent_message') response = event.item.text;
}
await prepared.cleanup();
```

- Start a new thread in `prepared.cwd` for each job.
- Set the sandbox, approval and network policy explicitly. These are the native repository starter's values.
- `prepared.reportStarted()` queues the start receipt, or returns `null` without a `reporter`. See [Report job starts](/docs/guides/deliver-content#report-job-starts).
- Save `response` with `prepared.versionId` and `prepared.digest`. Then `prepared.cleanup()` removes the directory and releases the delivery.

## Keep your Codex configuration out of the job

Codex reads your global `config.toml`, MCP servers and `AGENTS.md` from `CODEX_HOME`. To keep them out, pass an `env` whose `CODEX_HOME` holds only `auth.json`. The Codex SDK then inherits nothing from `process.env`, so include what the Codex CLI needs, such as `PATH`.

## Use the native repository starter

Codex is the starter's default agent SDK. Its adapter already uses a `CODEX_HOME` with only `auth.json`. See [Prepare an existing repository](/docs/guides/deliver-content#prepare-an-existing-repository).

Install the pinned Codex SDK from your approved npm cache, where `$app` is the starter's absolute path. The check prints the Codex CLI version and needs no credentials.

```sh
npm install --prefix "$app" --workspaces=false --offline --include=optional --ignore-scripts --no-audit --no-fund \
  --save-exact @openai/codex-sdk@0.169.0
node "$app/verify-install.mjs" codex --codex-sdk
```

## What has been tested

The live checks used `gpt-6-luna` as an example model. They read the model's answers, because the Codex SDK reports no event when it loads a skill.

| Check | Result |
| --- | --- |
| A new thread reads its prepared version | Passed live on 0.169.0. Each thread returned values stored only in its own files. |
| A resumed thread keeps its version | Passed live in its original directory |
| File preparation, thread options and the starter's adapter | Passed offline. The adapter ran against a fake SDK module. |
| Replacing files under a running thread | Not tested |
| A live job through the native repository starter | Not tested |
