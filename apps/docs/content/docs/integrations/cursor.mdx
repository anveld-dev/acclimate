Use `@acclimate/cursor-plugin` when your application runs local agents with the Cursor SDK. The plugin writes a verified bundle version into a private directory in the layout Cursor reads, and your application creates the agent there.

| Requirement | Value |
| --- | --- |
| Plugin | `@acclimate/cursor-plugin`, with a `/native` entry point for the agent options |
| Agent SDK | `@cursor/sdk` `^1.3.1`, an optional peer of the plugin that only the `/native` entry point uses |
| Node.js | 22.22 or later. See [Install the SDKs](/docs/get-started/install#prerequisites). |
| Platform | Linux or macOS |

The plugin prepares files for a local agent. Cursor cloud agents are not supported.

## Install

```sh
npm install @acclimate/sdk @acclimate/cursor-plugin @cursor/sdk
```

The plugin and the Acclimate SDK must come from the same Acclimate release. To install them from release files, see [Install from verified release files](/docs/get-started/install#install-from-verified-release-files).

## Files the plugin writes

`prepare` creates a new private directory for each job and writes the version's files into it.

| Bundle file | Written to |
| --- | --- |
| Instruction | `AGENTS.md` |
| Skills | `.cursor/skills/<name>/`, with their supporting files |
| Memory | `.acclimate/memory/`, only the files you name in `approvedMemoryPaths` |

Cursor does not load the memory files. Pass the bundle paths of the memory files you want written as `approvedMemoryPaths`. `prepare` fails if a path is not a memory file in the version. `prepared.memoryFiles` lists the written files with their `path`, `text` and `absolutePath`. Add the ones you choose to the prompt.

A version must also follow the [rules for bundle files](/docs/guides/deliver-content#rules-for-bundle-files), which allow Cursor only lowercase skill names, or `prepare` fails before it writes anything.

## Prepare and run an agent

Pass the result of `client.prepare()` to the plugin's `prepare`. [Choose a native integration](/docs/guides/deliver-content#choose-a-native-integration) explains what else `prepare` accepts. Your application supplies `client`, the IDs, `apiKey`, `model`, `prompt` and `approvedMemoryPaths`.

```ts
import { Agent } from '@cursor/sdk';
import { prepare } from '@acclimate/cursor-plugin';
import { cursorLocalOptions } from '@acclimate/cursor-plugin/native';

const delivery = await client.prepare({ workspaceId, bundleId, channel: 'stable', reporter });
const prepared = await prepare(delivery, { approvedMemoryPaths });
const agent = await Agent.create({
  apiKey,
  model: { id: model },
  local: { ...cursorLocalOptions(prepared).local, sandboxOptions: { enabled: true } },
});
let result;
try {
  const run = await agent.send(prompt);
  let started = false;
  for await (const event of run.stream()) {
    if (!started && event.type === 'status' && event.status === 'RUNNING') {
      started = true;
      prepared.reportStarted();
    }
  }
  result = await run.wait();
} finally {
  await agent[Symbol.asyncDispose]();
}
await prepared.cleanup();
```

- `cursorLocalOptions` returns the `local` fields `cwd` and `settingSources: ['project']`.
- Create a new local agent for each job.
- `prepared.reportStarted()` queues the delivery's start receipt. It returns `null` when `client.prepare()` had no `reporter`. See [Report job starts](/docs/guides/deliver-content#report-job-starts).
- Save `result.status` and `result.result` with `prepared.versionId` and `prepared.digest` before you clean up.
- `prepared.cleanup()` removes the directory, including any files the agent created, and releases the delivery. Call it after `run.wait()` has returned. If the run's end is unknown, keep the files for inspection.

The repository's [`examples/cursor-agent.ts`](https://github.com/anveld-dev/acclimate/blob/main/examples/cursor-agent.ts) shows the complete job, including receipts and saving the result.

## Enable the sandbox

Cursor's local sandbox is off unless you enable it. Set `sandboxOptions: { enabled: true }` next to the fields from `cursorLocalOptions`, as the sample does.

## Use the native repository starter

The starter runs Cursor with `"harness": "cursor"`, with the sandbox enabled. See [Prepare an existing repository](/docs/guides/deliver-content#prepare-an-existing-repository).
