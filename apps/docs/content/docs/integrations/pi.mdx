Use `@acclimate/pi-plugin` when your application runs agents with the Pi coding-agent SDK. The plugin writes a verified bundle version into a private directory and builds the Pi resource loader for it, and your application creates the session.

| Requirement | Value |
| --- | --- |
| Plugin | `@acclimate/pi-plugin`, with a `/native` entry point for the resource loader |
| Agent SDK | `@earendil-works/pi-coding-agent` `^1.5.2`, an optional peer that only the `/native` entry point loads |
| Runtime | Node.js 22.22 or later on Linux or macOS. See [Install the SDKs](/docs/get-started/install#prerequisites). |

## Install

Install the agent SDK beside the plugin and the Acclimate SDK. The plugin and the Acclimate SDK must come from the same Acclimate release.

```sh
npm install @acclimate/sdk @acclimate/pi-plugin @earendil-works/pi-coding-agent
```

For release files, see [Install from verified release files](/docs/get-started/install#install-from-verified-release-files).

## Files the plugin writes

`prepare` writes each job's files into a new private directory. It fails before writing anything if the version breaks the [rules for bundle files](/docs/guides/deliver-content#rules-for-bundle-files).

| Bundle file | Written to |
| --- | --- |
| Instruction | `AGENTS.md` |
| Skills | `.agents/skills/<name>/`, with their supporting files |
| Memory | `.acclimate/memory/` |

`prepared.resources` lists every written file with its bundle `path`, `kind` and `absolutePath`. `createPiResourceLoader` from the `/native` entry point builds and loads a Pi resource loader that holds only the instruction, the skills and the memory files you select. It turns off Pi's own discovery of extensions, skills, prompt templates, themes and context files.

## Prepare and run a session

Pass the delivery from `client.prepare()` to the plugin's `prepare`, which accepts the inputs in [Choose a native integration](/docs/guides/deliver-content#choose-a-native-integration). Your application supplies `client`, the IDs, `provider`, `modelId` and `prompt`.

```ts
import { join } from 'node:path';
import { createAgentSession, ModelRuntime, SessionManager, SettingsManager } from '@earendil-works/pi-coding-agent';
import { prepare } from '@acclimate/pi-plugin';
import { createPiResourceLoader } from '@acclimate/pi-plugin/native';

const modelRuntime = await ModelRuntime.create({ allowModelNetwork: false });
const model = modelRuntime.getModel(provider, modelId);
if (!model) throw new Error(`Unknown Pi model: ${provider}/${modelId}`);

const delivery = await client.prepare({ workspaceId, bundleId, channel: 'stable', reporter });
const prepared = await prepare(delivery);
const { session } = await createAgentSession({
  cwd: prepared.cwd,
  agentDir: join(prepared.cwd, '.acclimate', 'pi-agent'),
  modelRuntime,
  model,
  tools: ['read', 'edit', 'write', 'bash', 'grep', 'find', 'ls'],
  resourceLoader: await createPiResourceLoader(prepared, ['memory/selected.md']),
  sessionManager: SessionManager.inMemory(prepared.cwd),
  settingsManager: SettingsManager.inMemory(),
});
prepared.reportStarted();
let output;
try {
  await session.prompt(prompt);
  output = session.getLastAssistantText() ?? '';
} finally {
  session.dispose();
}
await prepared.cleanup();
```

- Create a new session for each job, with the loader that `createPiResourceLoader` returns.
- Set `tools` explicitly. This is the native repository starter's list.
- `prepared.reportStarted()` queues the start receipt, or returns `null` without a `reporter`. See [Report job starts](/docs/guides/deliver-content#report-job-starts).
- Save `output` with `prepared.versionId` and `prepared.digest`. Then `prepared.cleanup()` removes the directory and releases the delivery.
- Clean up only after the session has stopped using the directory.

## Choose memory

The second argument of `createPiResourceLoader` lists the bundle paths of the memory files to append as context. Replace `memory/selected.md` with a path from your bundle. The default list is empty, so no memory loads unless you name it. A path that is not a memory file in the version throws an error.

## Use the native repository starter

The starter runs Pi with `"harness": "pi"` and a model value in the form `provider/model-id`. See [Prepare an existing repository](/docs/guides/deliver-content#prepare-an-existing-repository).
