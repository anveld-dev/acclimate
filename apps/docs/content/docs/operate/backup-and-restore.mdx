---
title: Back up and restore
description: Protect your PostgreSQL backups and verify a restore before putting it into service.
---

Back up the Acclimate database and the Keycloak database separately. Keep each database with its matching application version. Save the private runtime files separately. The Keycloak realm import file provisions a realm on first startup. A Keycloak database backup preserves the realm's users, credentials and subsequent changes.

## Dump the database

Use Python 3 and `psql`, `pg_dump` and `pg_restore` from the same PostgreSQL major version as the server. Run the scripts from the matching checkout, in an environment that can reach the private database. In the bundled deployment, use a tools environment on the private Compose network and connect to `postgres:5432` for Acclimate or `keycloak-db:5432` for Keycloak. Keep the database ports private.

Inject `DATABASE_URL` for the source database. The script accepts PostgreSQL URLs with the `sslmode`, `sslrootcert`, `sslcert`, `sslkey` and `connect_timeout` query options. It passes connection settings through libpq environment variables. Protect the environment from other users.

```sh
# Point DATABASE_URL at the source database and choose a new private archive path.
python3 scripts/operations/backup.py dump /private/backups/acclimate.dump --pg-bin /path/to/postgresql-16/bin
```

The script takes a consistent PostgreSQL custom-format snapshot and creates the archive with mode 0600. Keep its parent directory private. Give the Keycloak dump its own path. Encrypt backups at rest and in transit, set a retention policy and protect keys and copies. Provision database roles and ACLs separately. Keep a recovery plan for the PostgreSQL cluster.

## Restore in isolation

<Callout type="warn" title="Restore into a new database">
Never restore over a live database. Create a new, empty database with the correct owner and grants before restoring.
</Callout>

Point `DATABASE_URL` at the isolated target. Restore refuses a database with existing relations and uses `pg_restore --exit-on-error --single-transaction`. If it fails, investigate the error and retry against a fresh empty database.

```sh
python3 scripts/operations/backup.py restore /private/backups/acclimate.dump --pg-bin /path/to/postgresql-16/bin
```

Start the matching service build against the restored database in isolation. Verify stored payload bytes, channel revisions, learning rounds and improvement memory, and application access. For Keycloak, verify the realm, client settings and sign-in with a matching identity server. Check the target URL and scoped grants before switching a stopped service to a restored database. Run an authenticated read and monitor the service after startup. See [Upgrade and recover](/docs/operate/upgrades-and-recovery) for the order of operations.

## Rehearse the tooling

For a local qualification run, point `DATABASE_URL` at a disposable PostgreSQL server and use a role that can create and drop databases.

```sh
python3 scripts/operations/qualify.py --pg-bin /path/to/postgresql-16/bin
```

The script creates three randomly named databases, checks exact restored data and tests refusal of a populated target and transactional failure. It drops only the databases it created and leaves the database named in `DATABASE_URL` alone. If an outage or process kill interrupts cleanup, identify the generated `acclimate_ops_…` databases before removing them. Rehearse and verify restores of your operational archives on a schedule.
