---
title: Troubleshooting
description: Symptoms you may see on the local stack, in a deployment, in a learning loop or on the executor, with the cause and fix for each.
---

Text in backticks is the exact code or message you see. For every code, see [Error codes](/docs/reference/error-codes).

## Local stack and SDK

| Symptom | Cause | Fix |
| --- | --- | --- |
| An SDK call fails with `transport.unreachable` and `Could not reach the Acclimate service` while the stack runs | The shell does not trust the local certificate | Run `source .local/stack/env.sh` in that shell. See [Trust the local certificate](/docs/reference/local-stack#trust-the-local-certificate). |
| On Linux, the `Provider` line of `local:up` says `Verification failed` for a provider on `127.0.0.1` | The containers reach it as `host.docker.internal`, which on Linux is the Docker bridge address, such as `172.17.0.1` | Make the provider listen on the bridge address. See [Run learning rounds](/docs/reference/local-stack#run-learning-rounds). |

## Deployment

| Symptom | Cause | Fix |
| --- | --- | --- |
| A public hostname gives a TLS error, and `docker compose logs proxy` shows certificate errors | Caddy cannot get a certificate: DNS does not point at the server, or TCP 80 or 443 is not reachable | Fix DNS, the firewall or the [load balancer](/docs/operate/reverse-proxy#run-behind-a-load-balancer). Caddy retries by itself. |
| Keycloak shows `Invalid parameter: redirect_uri` | The client's redirect URI is not exactly `CONSOLE_ORIGIN` plus `/auth/callback`. The realm import sets it only once, so a later console hostname change does not reach it. | Correct the client's redirect URI in Keycloak. |
| Sign-in ends with `Sign-in could not be completed. Check server configuration or start again.` | The console cannot reach the issuer, the client secret is wrong, or the issuer differs between the console, the service and discovery | Compare `CONSOLE_OIDC_ISSUER`, `ACCLIMATE_OIDC_ISSUER` and the discovered issuer character for character, and check the secret. See [Use another OIDC provider](/docs/operate/self-host#use-another-oidc-provider). |
| The service stops at startup with `another Acclimate service process owns the invitation queue`, or exits with status 75 | A second service process uses the database, or a [pooler](/docs/operate/self-host#use-an-external-postgresql) runs in transaction mode | Run one service per database, connected directly or in session mode. |
| The service exits with status 1 and logs `while executing migration` | A migration failed and was rolled back, so the database keeps its previous migration | Fix the database error in the log, or [roll back the upgrade](/docs/operate/upgrades-and-recovery#roll-back-an-upgrade). |
| The log shows `migration <n> was previously applied but is missing in the resolved migrations` | An older build runs against a database a newer build migrated | Run the newer build, or restore the dump taken before the upgrade. See [Roll back an upgrade](/docs/operate/upgrades-and-recovery#roll-back-an-upgrade). |
| The service or the console stops at startup with `has been removed`, `is obsolete` or `are obsolete` | The runtime file sets a [removed variable](/docs/reference/configuration#removed-settings) | Delete it. |

## Learning

| Symptom | Cause | Fix |
| --- | --- | --- |
| **Start** is disabled and says the service has no optimizer model, or the API answers 409 `optimizer-required` | The service has no optimizer | [Set the optimizer model](/docs/operate/enable-learning#set-the-optimizer-model), or on the local stack [connect a model provider](/docs/tutorials/first-learning-round#connect-a-model-provider). |
| **Start** is refused with `tasks-required`, or the loop pauses with that reason | A split has fewer than 20 admitted tasks | [Add tasks](/docs/guides/learning-loop#add-tasks), fix the ones set aside and confirm the held-out tasks, then choose **Start**. |
| Held-out tasks stay pending | They wait for a signed-in person to confirm them. A [machine token](/docs/reference/credentials#rights) cannot. | In the console, check **Needs confirmation** and choose **Confirm all shown**. See [Review and confirm tasks](/docs/guides/learning-loop#review-and-confirm-tasks). |
| A round fails with `provider-unavailable` | Every failed rollout of the current version was a model provider outage or rate limit | Wait for the loop to [try again](/docs/guides/learning-loop#when-a-round-fails). If it keeps failing, check the provider's rate limits and lower the executor concurrency ([deployment](/docs/operate/enable-learning#start-the-executor), [local stack](/docs/reference/local-stack#executor-concurrency)). |

## Executor and model provider

| Symptom | Cause | Fix |
| --- | --- | --- |
| Imports and task checks stay queued, or the loop waits with `no-executor` | No executor is connected | [Start the executor](/docs/operate/enable-learning#start-the-executor). |
| The executor keeps restarting with status 78. Its log starts with `The service refused the executor credential`, `Cannot read the executor credential file`, `The executor credential is empty`, `Unsupported sandbox runtime`, `Inspecting the runner image` or `Sandbox preflight failed`. | Its credential, runner image or sandbox runtime is wrong | See [Check the executor](/docs/operate/enable-learning#check-the-executor). |
| **Start** is refused with `Verify the workspace model provider before starting` | The executor has not verified every allowed model with a chat request | Read each model's result on the **Model provider** page and fix the base URL, API key or model IDs. See [Connect a model provider](/docs/guides/learning-loop#connect-a-model-provider). |
| A model fails verification with `Upstream response is missing token usage` | Its replies report no token usage | Use a model or endpoint that reports it. See [Model provider](/docs/reference/configuration#model-provider). |
| Saving a model provider is refused with `Plain HTTP is allowed only for hosts listed in ACCLIMATE_PROVIDER_HTTP_HOSTS` | The host is not listed | The operator lists it. See [Provider addresses](/docs/reference/configuration#provider-addresses). |
| The service does not start and logs `ACCLIMATE_PROVIDER_ENCRYPTION_KEY does not match` | The key differs from the one the service first started with | [Restore the original key](/docs/operate/backup-and-restore#keep-the-provider-encryption-key). |
