title: Upgrade and recover

Preserve stored content and release history when changing service releases.

## Pin a release

Acclimate uses a shared `major.minor.patch` release version for the service, console and SDK artifacts. Git tags use a leading `v`, such as `v0.1.0`. The matching GHCR image tag is `0.1.0`. Use the release's checkout and read its release notes before changing versions. Set `ACCLIMATE_VERSION` in the Compose environment to the exact published image tag. That pin selects both the service and console images. The default tag is `latest`, which can change between pulls. Keep the original tag and checkout available for recovery.

## Upgrade the deployment

On startup the service runs the pending SQLx migrations for its checkout. Keep each database backup with its matching service build.

<Steps>
<Step>

### Pause traffic and stop the applications

Pause external clients. Take the public routes out of service and stop both application containers. Leave PostgreSQL running for the dump. In the bundled stack you can stop all three public routes by stopping Caddy first.

```sh
docker compose stop proxy
docker compose stop console service
```

</Step>
<Step>

### Back up and rehearse a restore

[Back up the application database and Keycloak separately](/docs/operate/backup-and-restore). Keep the previous deployment's private configuration available. Restore the application archive to a separate empty database and verify it with the matching service build before upgrading.

</Step>
<Step>

### Apply the release

Use the new checkout and set `ACCLIMATE_VERSION` to its published tag. Validate the Compose configuration and pull the application images. If you build from source, build the new service and console from that checkout instead. Use the same Compose project name and existing volume mapping when switching checkouts. Bring up the upgraded service and console while public traffic is still paused.

```sh
docker compose config --quiet
docker compose pull service console
docker compose up -d --no-build --wait service console
```

Keep one Rust process per database. A normal `docker compose down` preserves volumes. The `--volumes` option deletes them.

</Step>
<Step>

### Verify before resuming traffic

Check service and console readiness. Start the proxy with `docker compose up -d --no-build --wait proxy` for [your authenticated read and sign-in checks](/docs/operate/health-and-readiness#verify-access-and-activity) while access is limited to your verification clients. Resume user and application traffic after those checks pass. If verification fails after a schema change, recover the previous release using its matching verified backup.

</Step>
</Steps>

## Upgrade from migration 0015 or 0016

Migrations 0017 and 0018 permanently drop the old change and connection-learning records. Keep the backup as the archive. Remove rejected legacy environment settings before starting the new service. Startup identifies the first obsolete setting it encounters.

1. Take a full backup with `python3 scripts/operations/backup.py dump /private/backups/acclimate-pre-loop.dump`. Restore it into a separate database with the matching pre-upgrade build to read old rounds.
2. Before applying migration 0018, find connections that receive a learned version. After `0018` they receive their own channel's version instead:

   ```sql
   SELECT e.project_id, e.bundle_id, e.integration_id, e.source_channel, e.delivery_channel,
          d.version_id AS delivered, s.version_id AS source_head
   FROM connected_learning_enrollments e
   JOIN channels d ON (d.project_id, d.bundle_id, d.name) = (e.project_id, e.bundle_id, e.delivery_channel)
   JOIN channels s ON (s.project_id, s.bundle_id, s.name) = (e.project_id, e.bundle_id, e.source_channel)
   WHERE d.version_id <> s.version_id;
   ```

   Before upgrading, record the delivered version ID for each affected connection. After upgrading, you can release that version on the source channel with a reason. This also updates any other connection using that channel.
4. `learn-<connectionId>` channels stay as ordinary channels with their release history.
