This page lists every environment variable Acclimate reads, grouped by the process that reads it. Developers need only [Application](#application). The rest is for operators, and [Self-host Acclimate](/docs/operate/self-host) shows where each runtime file lives.

## Application

### Read by the SDKs

`createAcclimate()` in TypeScript and `Acclimate.from_env()` in Python read these three variables, and you can pass each value as an option instead. `acclimate pull` reads `ACCLIMATE_TOKEN` when its config file names no token.

| Variable | Required | Value |
| --- | --- | --- |
| `ACCLIMATE_URL` | Yes | Public HTTPS base URL of the API |
| `ACCLIMATE_WORKSPACE` | Yes | Workspace ID |
| `ACCLIMATE_TOKEN` | Yes | The credential for the application's calls. See [Credentials and rights](/docs/concepts/credentials). |

### Used by convention

The SDKs do not read these. The console's **App setup** code and the repository examples use them, and pass the values to the client.

| Variable | Value |
| --- | --- |
| `ACCLIMATE_SCOPE` | Stable application name, passed as `scope`. It namespaces the local cache. Never use a token. |
| `ACCLIMATE_BUNDLE` | Bundle ID |
| `ACCLIMATE_CHANNEL` | Channel name, such as `stable` |
| `ACCLIMATE_CONNECTION` | Connection ID, passed as `connectionId` |
| `ACCLIMATE_RECEIPT_TOKEN` | Optional receipt credential, kept apart from `ACCLIMATE_TOKEN`. See [Report job starts](/docs/guides/deliver-content#report-job-starts). |
| `ACCLIMATE_CACHE` | Cache directory, in place of the SDK's default |
| `ACCLIMATE_JOB_DIR` | Directory the job's files are written to |
| `AGENT_TASK` | Task text for the console's connected agent example |

## Service

Three service values must be identical to their console values: `ACCLIMATE_OIDC_ISSUER` to `CONSOLE_OIDC_ISSUER`, `ACCLIMATE_LOGIN_TOKEN` to `CONSOLE_LOGIN_TOKEN`, and `ACCLIMATE_CONSOLE_TOKEN` to `CONSOLE_SERVICE_TOKEN`. The login token, the console token and every static machine token must differ from each other.

| Variable | Required | Default | Value |
| --- | --- | --- | --- |
| `DATABASE_URL` | Yes | None | `postgresql://` or `postgres://` URL with an explicit host, user and database. URL-encode only the password. |
| `ACCLIMATE_BIND` | No | `127.0.0.1:3000` | Private API listener. Compose sets `0.0.0.0:3000`. |
| `ACCLIMATE_INTERNAL_BIND` | No | `127.0.0.1:3001` | Listener the executor connects to. Compose sets `executor-listener:3001`. |
| `ACCLIMATE_OIDC_ISSUER` | Yes | None | HTTPS realm issuer, including any trailing slash, with no credentials, query or fragment |
| `ACCLIMATE_LOGIN_TOKEN` | Yes | None | Login authority token |
| `ACCLIMATE_CONSOLE_TOKEN` | Yes | None | Console transport token |
| `ACCLIMATE_OPERATORS` | Yes | None | Non-empty JSON array of `{ "issuer", "subject" }`, one for each operator |
| `ACCLIMATE_AUTH` | Yes | None | JSON array of [static machine grants](#static-machine-grants), or `[]` |
| `ACCLIMATE_SERVICE_BINARY` | No | `target/release/acclimate-service` under the checkout | Executable path, read only by the `npm start` wrapper outside a container |

- Each operator pair must be unique. Its `issuer` must equal `ACCLIMATE_OIDC_ISSUER`, and its `subject` must be nonempty and at most 512 bytes.
- Use `ACCLIMATE_AUTH=[]` for browser-only use, or when every machine token is issued from the console.
- Remove `ACCLIMATE_MODE` and `CONSOLE_MODE` from older runtime files. The service and the console refuse to start when either is defined.

### Static machine grants

`ACCLIMATE_AUTH` holds machine tokens fixed in the service's environment. Changing it needs a restart, unlike tokens issued from the console.

```json
[
  {
    "token": "<secret>",
    "principalId": "support-agent",
    "workspaceId": "<workspace-id>",
    "rights": ["read", "write"]
  }
]
```

- `rights` holds any of `read`, `write` and `promote`. See [Rights](/docs/concepts/credentials#rights).
- A token identifies one principal and can appear once for each workspace.
- A `principalId` must not contain a colon.

## Optimizer

These service variables set the optimizer, the model that changes bundles in a learning round. Without them, delivery still works and starting a loop is refused with `optimizer-required`. See [Set the optimizer model](/docs/operate/enable-learning#set-the-optimizer-model).

| Variable | Required | Default | Value |
| --- | --- | --- | --- |
| `ACCLIMATE_MODEL_ENDPOINT` | No | Unset | Full URL of an OpenAI-compatible Chat Completions route, posted to as written, with no embedded credentials |
| `ACCLIMATE_MODEL_TOKEN` | With the endpoint | None | Bearer credential, nonblank, with no control characters |
| `ACCLIMATE_MODEL` | With the endpoint | None | Model ID, 1 to 256 bytes after trimming, with no control characters |
| `ACCLIMATE_MODEL_REASONING_EFFORT` | No | Unset | `low`, `medium`, `high`, `xhigh`, `max` or `ultra`. Unset omits `reasoning_effort`. |
| `ACCLIMATE_MODEL_TIMEOUT_SECONDS` | No | `600` | Timeout for each HTTP attempt, 30 to 3,600 |
| `ACCLIMATE_MODEL_MAX_COMPLETION_TOKENS` | No | `32768` | `max_completion_tokens` on each call, 1,024 to 262,144 |
| `ACCLIMATE_LEARNING_MAX_FAILED_ROUNDS` | No | `3` | Consecutive failed rounds before the loop pauses, 1 to 4,294,967,295 |

- A round pins `ACCLIMATE_MODEL` and `ACCLIMATE_MODEL_REASONING_EFFORT` when it starts.
- An invalid timeout, token limit or reasoning effort stops the service at startup, even without an endpoint. An unset, zero or invalid failed-round limit uses the default.
- The service retries HTTP 429, HTTP 5xx and connection or timeout errors twice.

To try the optimizer on your own machine, see [Set up a local model proxy](/docs/get-started/first-learning-round#set-up-a-local-model-proxy).

## Model provider

The task model and the judge model come from the model provider a workspace administrator saves in the console. Two service variables control how the service stores and reaches it.

| Variable | Required | Default | Value |
| --- | --- | --- | --- |
| `ACCLIMATE_PROVIDER_ENCRYPTION_KEY` | For learning | Unset | 64 hex characters that encrypt the stored provider API keys |
| `ACCLIMATE_PROVIDER_HTTP_HOSTS` | No | Empty | Comma-separated hosts a provider may reach over plain HTTP or at a private address |

Without the provider encryption key, the service starts but cannot save a model provider. See [Keep the provider encryption key](/docs/operate/backup-and-restore#keep-the-provider-encryption-key).

### Provider addresses

Set `ACCLIMATE_PROVIDER_HTTP_HOSTS` to the same value on the service and the executor. Each entry is an exact hostname or IP address, compared without case. The service checks a provider's base URL when it is saved, and the executor checks it again against the addresses the host resolves to.

- The base URL must use HTTPS, or plain HTTP for a listed host. It must not contain a user name, password, query or fragment.
- Loopback addresses, `localhost` and `*.localhost`, private IPv4, carrier-grade NAT (`100.64.0.0/10`) and IPv6 unique-local addresses need the host on the list, even over HTTPS.
- These are always refused: link-local, unspecified, multicast and broadcast addresses, the cloud metadata addresses `100.100.100.200`, `168.63.129.16` and `fd00:ec2::254`, and the hostnames `metadata.google.internal` and `metadata.goog`.

## Invitation email

Set `ACCLIMATE_SMTP_HOST` on the service to send workspace invitations by email. Keycloak's own email is configured separately.

| Variable | Required | Default | Value |
| --- | --- | --- | --- |
| `ACCLIMATE_SMTP_HOST` | No | Unset | SMTP relay hostname, required when any other `ACCLIMATE_SMTP_*` variable is set |
| `ACCLIMATE_SMTP_FROM` | With SMTP | None | Sender mailbox, such as `Acclimate <noreply@example.com>` |
| `ACCLIMATE_CONSOLE_ORIGIN` | With SMTP | None | The console's `CONSOLE_ORIGIN`, used in invitation links |
| `ACCLIMATE_SMTP_TLS` | No | `starttls` | `starttls`, `tls` for implicit TLS, or `none` |
| `ACCLIMATE_SMTP_PORT` | No | `465` with `tls`, otherwise `587` | 1 to 65,535 |
| `ACCLIMATE_SMTP_USERNAME` | No | Unset | SMTP user name, set together with the password |
| `ACCLIMATE_SMTP_PASSWORD` | No | Unset | SMTP password, set together with the user name |

`ACCLIMATE_SMTP_TLS=none` is accepted only for `localhost`, `127.0.0.1`, `::1` and `mailpit`, and only without SMTP credentials.

## Executor

The executor runs learning rollouts in sandboxes. In the bundled deployment, Compose sets most of these variables. See [Enable learning](/docs/operate/enable-learning).

| Variable | Required | Default | Value |
| --- | --- | --- | --- |
| `ACCLIMATE_EXECUTOR_SERVICE` | Yes | None | Base URL of the service's executor listener. Compose sets `http://service:3001`. |
| `ACCLIMATE_EXECUTOR_TOKEN_FILE` | One of the two | None | File that holds the executor credential. A missing, unreadable or empty file stops the executor. |
| `ACCLIMATE_EXECUTOR_TOKEN` | One of the two | None | The executor credential itself, read only when the file variable is unset |
| `ACCLIMATE_SANDBOX_RUNTIME` | No | `runsc` | `runsc` for gVisor, or `docker` |
| `ACCLIMATE_RUNNER_IMAGE` | No | `acclimate-chat:1` | Runner image each sandbox runs, present at startup. Compose sets the release's `acclimate-runner`. |
| `ACCLIMATE_SANDBOX_DIR` | No | `/var/lib/acclimate-executor` | Directory for the files of each leased rollout |
| `ACCLIMATE_SANDBOX_VOLUME` | No | Unset | Docker volume mounted at `ACCLIMATE_SANDBOX_DIR`, when the executor runs in a container |
| `ACCLIMATE_EXECUTOR_CONCURRENCY` | No | `1` | Rollouts run at once |
| `ACCLIMATE_EXECUTOR_HEALTH_FILE` | No | `/tmp/acclimate-executor-health` | File touched after each successful lease request and heartbeat |
| `ACCLIMATE_PROVIDER_HTTP_HOSTS` | No | Empty | The service's value. See [Provider addresses](#provider-addresses). |

- `acclimate-executor --health` exits 0 when the health file is at most 120 seconds old.
- A wrong credential, runner image or sandbox runtime, or a failed startup sandbox check, makes the executor exit with status 78 and a message that names the fault. See [Check the executor](/docs/operate/enable-learning#check-the-executor).

## Console

| Variable | Required | Default | Value |
| --- | --- | --- | --- |
| `CONSOLE_ORIGIN` | Yes | None | Canonical public HTTPS origin, with no path or trailing slash |
| `CONSOLE_PUBLIC_API_URL` | Yes | None | Public HTTPS base URL of the API, shown in **App setup** |
| `CONSOLE_SERVICE_URL` | Yes | None | Private HTTP or HTTPS base URL of the API, `http://service:3000` in Compose |
| `CONSOLE_LOGIN_TOKEN` | Yes | None | The service's `ACCLIMATE_LOGIN_TOKEN` |
| `CONSOLE_SERVICE_TOKEN` | Yes | None | The service's `ACCLIMATE_CONSOLE_TOKEN` |
| `CONSOLE_OIDC_ISSUER` | Yes | None | The service's `ACCLIMATE_OIDC_ISSUER` |
| `CONSOLE_OIDC_CLIENT_ID` | Yes | None | Confidential OIDC client ID. The bundled realm uses `acclimate-console`. |
| `CONSOLE_OIDC_CLIENT_SECRET` | Yes | None | Secret of that client |
| `CONSOLE_ALLOW_EDITS` | No | Disabled | The literal `true` lets members with the right role make changes in the console |
| `CONSOLE_WORKSPACE` | No | Unset | Fallback workspace when the user has no saved selection |
| `CONSOLE_BUNDLE` | No | Unset | Fallback bundle in the same case |
| `CONSOLE_CHANNEL` | No | Unset | Fallback channel in the same case. Many operations use `stable` without one. |
| `HOST` | No | `127.0.0.1` | Listener address. Compose sets `0.0.0.0`. |
| `PORT` | No | `3100` | Listener port, 1 to 65,535 |
| `NODE_ENV` | No | None | The console image runs with `production` |

- Without `CONSOLE_ALLOW_EDITS=true`, the console only shows bundles, releases, connections, tasks, the model provider and learning.
- The trusted proxy must send the host of `CONSOLE_ORIGIN` as `Host`.
- Register `CONSOLE_ORIGIN` plus `/auth/callback` as the OIDC client's redirect URI.
- Prefer choosing the workspace, bundle and channel in the console over the fallback variables.
- `CONSOLE_SESSION_TOKEN` is not a setting. The console derives it from each request's session cookie.
- Leave Nitro's `NITRO_HOST`, `NITRO_PORT`, `NITRO_UNIX_SOCKET`, `NITRO_SSL_CERT` and `NITRO_SSL_KEY` unset in the bundled deployment, so its health check and proxy can reach the private HTTP listener.

## Compose

Set these in the shell that runs `docker compose`. They tell `compose.yaml` and the Keycloak overlay `compose.keycloak.yaml` where your private files are and which images to run. Every path is absolute. Each `*_IMAGE` variable defaults to the GHCR image at `ACCLIMATE_VERSION`.

| Variable | Required | Default | Value |
| --- | --- | --- | --- |
| `CONSOLE_HOST` | Yes | None | Public hostname of the console, with no scheme or path |
| `API_HOST` | Yes | None | Public hostname of the API, different from `CONSOLE_HOST` |
| `ACME_EMAIL` | Yes | None | Contact email for the certificates Caddy requests |
| `ACCLIMATE_SERVICE_ENV` | Yes | None | Private runtime file with the service's variables |
| `ACCLIMATE_CONSOLE_ENV` | Yes | None | Private runtime file with the console's variables |
| `ACCLIMATE_POSTGRES_PASSWORD_FILE` | Yes | None | Private file with the raw PostgreSQL password |
| `ACCLIMATE_EXECUTOR_TOKEN_FILE` | Yes | None | Private executor credential file on the host, outside the checkout |
| `ACCLIMATE_VERSION` | No | `latest` | Tag of the service, console, executor and runner images |
| `ACCLIMATE_SERVICE_IMAGE` | No | GHCR | Full service image reference |
| `ACCLIMATE_CONSOLE_IMAGE` | No | GHCR | Full console image reference |
| `ACCLIMATE_EXECUTOR_IMAGE` | No | GHCR | Full executor image reference |
| `ACCLIMATE_RUNNER_IMAGE` | No | GHCR | Full runner image reference, also passed to the executor |
| `KEYCLOAK_HOST` | With the overlay | None | Public hostname of Keycloak, different from the other two |
| `ACCLIMATE_KEYCLOAK_ENV` | With the overlay | None | Private Keycloak runtime file |
| `ACCLIMATE_KEYCLOAK_POSTGRES_PASSWORD_FILE` | With the overlay | None | Private file with Keycloak's raw database password |

- The password in `ACCLIMATE_POSTGRES_PASSWORD_FILE` must match the URL-encoded password in `DATABASE_URL`.
- `docker compose` refuses to run without `ACCLIMATE_EXECUTOR_TOKEN_FILE`, even before learning is set up. Compose mounts the file into the executor container and points the executor's own variable at the copy.
- Pin `ACCLIMATE_VERSION` to the exact Acclimate release without the Git tag's leading `v`, such as `0.1.0`. See [Versioning and compatibility](/docs/reference/versioning).
- Compose passes `ACCLIMATE_PROVIDER_HTTP_HOSTS`, `ACCLIMATE_EXECUTOR_CONCURRENCY` and `ACCLIMATE_SANDBOX_RUNTIME` from this shell to the executor. Setting them in the service's runtime file does not reach the executor.

### Keycloak runtime file

The file that `ACCLIMATE_KEYCLOAK_ENV` names holds these variables for the co-hosted Keycloak. [Self-host Acclimate](/docs/operate/self-host) creates it. The first realm import reads the last two.

| Variable | Value |
| --- | --- |
| `KC_DB_PASSWORD` | Raw password from the `ACCLIMATE_KEYCLOAK_POSTGRES_PASSWORD_FILE` file |
| `KC_BOOTSTRAP_ADMIN_USERNAME` | User name of the temporary administrator |
| `KC_BOOTSTRAP_ADMIN_PASSWORD` | Password of the temporary administrator |
| `ACCLIMATE_CONSOLE_ORIGIN` | The console's `CONSOLE_ORIGIN` |
| `ACCLIMATE_OIDC_CLIENT_SECRET` | The console's `CONSOLE_OIDC_CLIENT_SECRET` |

## Service commands

The service executable also runs one-off operator commands. Every command except `--check-grants` connects to the database, so run it with the service's `DATABASE_URL`. In the bundled deployment, run it through `docker compose exec -T service /usr/local/bin/acclimate-service`. [Enable learning](/docs/operate/enable-learning) gives the order for the executor commands.

| Command | What it does |
| --- | --- |
| `acclimate-service --create-executor-token` | Creates an executor credential and prints it as JSON with `id` and `token` |
| `acclimate-service --list-executor-tokens` | Prints a JSON array of executor credentials, never their tokens |
| `acclimate-service --revoke-executor-token <id>` | Revokes one executor credential |
| `acclimate-service --reset-provider-keys --confirm` | Deletes every stored model provider and the key check value, then prints `{"removedProviders": n}` |
| `acclimate-service --check-grants` | Checks an `ACCLIMATE_AUTH` value from standard input, without starting the service |

- `--list-executor-tokens` prints each credential's `id`, `createdAt`, `lastSeenAt`, declared `runtime`, `revoked` and `revokedAt`.
- `--reset-provider-keys` deletes each provider's URL, allowed models and provider API key. Use it only to start again with a new provider encryption key, after which each workspace administrator enters the model provider again. Without `--confirm`, it explains itself and deletes nothing.
- `--check-grants` reads up to 1 MiB of JSON and never echoes it. It prints `{"schemaVersion":1,"valid":true}` and exits 0, or prints `{"schemaVersion":1,"valid":false,"code":"grants.invalid"}` to standard error and exits with a failure status.
