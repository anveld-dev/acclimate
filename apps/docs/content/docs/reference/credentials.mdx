Every request to the service carries a credential. This page says which kind to give an application, a script or an executor, and how a member invited to a team's workspace connects an application.

## Credential types

| Credential | Who issues it and where | What it can do |
| --- | --- | --- |
| Connection credential | A workspace administrator, on a connection in **Connections**, with **Create read credential** | Read the released version for that connection's bundle and channel, and nothing else |
| Receipt credential | A workspace administrator, on the same connection, with **Create reporting credential** | Report which version a job started with, but not read a bundle |
| Machine token | A workspace administrator, on **Members** under **Machine tokens**, with **Issue token** | Call the API for one workspace with the rights you tick |
| Executor credential | The operator, who runs the service, with `acclimate-service --create-executor-token` | Let an executor take learning work from the service. It belongs to no workspace. |

Each secret is shown once. Connection and receipt credentials start with `aci_`. Machine tokens start with `acm_` and expire after 90 days unless you choose another period from 1 to 365 days. An operator can also define machine tokens in the service's `ACCLIMATE_AUTH` setting. See [Service](/docs/reference/configuration#service).

## Rights

A machine token carries one or more of three rights: read, write and promote. The console labels them **Read content**, **Write content** and **Promote releases**. Each right stands alone, so promote does not include write and write does not include read.

<Screenshot name="issue-token" width={384} alt="The Issue machine token dialog with a name field, the Read content, Write content and Promote releases checkboxes, an expiry and an optional reason." />

| To do this | The token needs |
| --- | --- |
| Resolve a channel and prepare a version, with `job()`, `client.prepare()` or `acclimate pull` | read |
| Report an outcome with `job.expect()` | write, and read for the `job()` call before it |
| Import, create, edit or retire tasks, or run a trial | write |
| Add a version to a bundle | write |
| Publish a new bundle with its first release | write and promote |
| Release a version to a channel | promote |
| Turn on learning or change its settings | promote |
| Start, pause, resume or stop a loop, or roll back a round | promote |

A script that releases a version, as in [Release a version](/docs/guides/release-and-roll-back#release-a-version), needs read, write and promote. The [support agent example](/docs/tutorials/support-agent) needs read and write. The [ticket triage example](/docs/tutorials/first-learning-round) needs all three, because it publishes its bundle, imports tickets and starts the loop.

A machine token cannot list, edit, retire or recheck held-out tasks. A task list gives it the evolve tasks and a count of the held-out tasks.

In the console, a member's role takes the place of rights. A Viewer can read, and an Editor can also write and release a version. Learning settings and loop controls need an Administrator.

Some actions need a person signed in to the console, whatever rights a token carries:

- Issue, rotate or revoke a machine token: an Administrator
- Save the model provider: an Administrator
- Confirm held-out tasks: an Editor or an Administrator
- Export held-out tasks: any signed-in member

## Join a workspace

When your team already runs Acclimate, a workspace administrator invites you at the email address you sign in with. The administrator also creates a connection for your bundle and channel, and sends you its connection ID and a connection credential through your team's private secret channel.

1. Open the invitation link, sign in to the console and choose **Join workspace**. If the invitation stays pending, verify the invited email address with your identity provider.
2. Open **Bundles**, choose the bundle and inspect its files in **Content**.
3. [Install the SDK](/docs/get-started/install) in the environment that runs your agent.
4. On the bundle's channel, choose **App setup**. Set the four variables it lists in your application's private environment.

   | Variable | Value |
   | --- | --- |
   | `ACCLIMATE_URL` | The API URL that **App setup** shows |
   | `ACCLIMATE_TOKEN` | The connection credential |
   | `ACCLIMATE_CONNECTION` | The connection ID |
   | `ACCLIMATE_SCOPE` | A stable name for your application, used for the cache |

5. Download the delivery check from **App setup** and run it with the command shown beside it. It makes no model calls, and prints the resolved version, its digest and the number of files it checked.
6. In your application, call the SDK when each job starts, and keep the version ID and digest with the job's result. See [Deliver content to jobs](/docs/guides/deliver-content).
