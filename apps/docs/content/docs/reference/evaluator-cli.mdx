---
title: Evaluator CLI
description: Describe an installed evaluator, run a comparison, and inspect or export its retained evidence.
---

Use `acclimate-eval` with the TypeScript SDK or `python -m acclimate` with the Python SDK. Both take the same commands, flags and exit codes.

The CLI checks your command line first. Then, for commands that run callbacks, it loads your application module: `application.mjs` or `application.mts` (TypeScript), or `application.py` (Python), in the working directory. Choose another entry with `--app`. Python accepts a module name or a source file. If both `application.mjs` and `application.mts` exist, the CLI uses `application.mjs` and prints a warning.

`status`, `verify-export` and `interrupt` never load your application module. You can run them on a machine without your agent's code, but they still need a config: `status` takes `--config` or `--read-config`, and `interrupt` takes `--config`.

## Commands

| Command | Loads your module | Purpose |
| --- | --- | --- |
| `coverage` | Yes | Inspect local sources, package imports, and declared revision inputs. Keep the report private. |
| `describe` | Yes | Print the public descriptor for the installed cases, runtime, and grader. |
| `doctor` | Yes | Check setup with `--config` and a `--bundle`, `--handoff`, or named run. You can include `--policy`. |
| `compare` | Yes | Run a downloaded handoff, or create and run a named comparison from a complete bundle payload. |
| `request` | Yes | Create a handoff from a bundle, channel, payload, and durable `--intent`. Write the handoff with `--out`. |
| `run` | Yes | Execute an existing request with the evaluator config and handoff or name. |
| `check` | Yes | Apply a policy to the retained comparison. An evaluator config can record the verdict. |
| `export` | Yes | Write review evidence to a new private directory. |
| `status` | No | Inspect request state and optional reported activity. |
| `interrupt` | No | Record interruption with an explicit `--reason`. Check the original worker separately for termination. |
| `verify-export` | No | Validate a review export through its `--manifest`. |

## Common invocations

Run from the installed application environment. Add `--live` when your callbacks call models.

```sh
acclimate-eval doctor --config "$EVALUATOR_CONFIG" --handoff evaluation-request.json
acclimate-eval compare --config "$EVALUATOR_CONFIG" --handoff evaluation-request.json --live
acclimate-eval status --config "$EVALUATOR_CONFIG" --handoff evaluation-request.json
```

```sh
python -m acclimate doctor --config "$EVALUATOR_CONFIG" --handoff evaluation-request.json
python -m acclimate compare --config "$EVALUATOR_CONFIG" --handoff evaluation-request.json --live
python -m acclimate status --config "$EVALUATOR_CONFIG" --handoff evaluation-request.json
```

A separate reviewer can inspect status with the private reader config and public handoff:

```sh
acclimate-eval status --read-config "$READER_CONFIG" --handoff "$HANDOFF"
python -m acclimate status --read-config "$READER_CONFIG" --handoff "$HANDOFF"
```

Create and run a named comparison from a candidate payload. Reuse the name to recover the same run:

```sh
acclimate-eval compare --config "$EVALUATOR_CONFIG" --bundle "$BUNDLE_ID" --channel stable \
  --payload candidate.json --name "$RUN_NAME" --live --policy quality-policy.json
```

Use `--name` to refer to a headless run using its original evaluator config. For a deliberate repeat after a terminal run, see [run from a payload](/docs/guides/evaluate-a-change#run-from-a-payload). For uncertain execution or lost responses, see [evaluation recovery](/docs/operate/upgrades-and-recovery#recover-an-evaluation).

## Flags

Paths can be relative. The CLI resolves them against the current directory.

| Flag | Commands | Value |
| --- | --- | --- |
| `--config CONFIG` | all except `coverage`, `describe`, `verify-export` | Private evaluator config. See [evaluator access](/docs/operate/evaluator-access#configure-the-worker). |
| `--read-config READER` | `status`, `check`, `export`, `verify-export` | Private reader config. Use instead of `--config`. |
| `--handoff FILE` | `compare`, `doctor`, `run`, `status`, `check`, `export`, `interrupt`, `verify-export` | The request handoff JSON from the console or `request --out`. |
| `--name RUN_NAME` | `compare`, `doctor`, `run`, `status`, `check`, `export`, `interrupt` | A run name of 1–80 letters, digits, underscores or hyphens. Use instead of `--handoff`. |
| `--retry-after PRIOR_NAME` | `compare` | Start a fresh attempt after a finished run. Use instead of `--name`. |
| `--bundle ID` | `compare`, `doctor`, `request` | Bundle ID. |
| `--channel CHANNEL` | `compare`, `request` | Channel to propose the candidate on. |
| `--payload FILE` | `compare`, `request` | Complete candidate bundle payload. |
| `--intent FILE` | `request` | Durable request intent, reused for recovery. |
| `--out PATH` | `request`, `export` | Handoff file to write, or a new export directory. |
| `--policy POLICY` | `compare`, `doctor`, `request`, `check` | Quality policy JSON. |
| `--selection FILE` | `export` | Artifact selection for `toReviewArtifact`. |
| `--manifest FILE` | `verify-export` | Export manifest. |
| `--reason REASON` | `interrupt` | Why the run is interrupted. |
| `--live` | `compare`, `run` | Authorize model calls. Required when the adapter's execution is `live`, rejected when it is `model-free`. |
| `--app PATH` | commands that load your module | Application module to load. Python also accepts `PACKAGE.MODULE`. |
| `--json` | all | Print errors as one JSON line on stderr, even on a terminal. `compare` and `coverage` also print JSON results. |
| `--verbose` | all | Include stack traces and the chained cause in errors. `ACCLIMATE_DEBUG=1` does the same. |
| `--version` | none | Print the SDK version. |
| `--help` | any | Print usage. `COMMAND --help` prints one command's flags. |

Running with no arguments prints usage and exits 1, so an empty command in CI fails instead of passing.

## Application module exports

Export these names from your module. In TypeScript you can instead export one default object, preferably built with `defineApplication`:

```ts title="application.mts"
import { defineApplication } from '@acclimate/sdk/evaluation';

export default defineApplication({
  cases: [{ caseId: 'refund', input: { message: 'Refund order 1' }, expected: 'billing' }],
  execute: async (run) => ({ output: await route(run.instructions, run.input) }),
  grade: ({ output, expected }) => ({ reward: Number(output === expected) }),
});
```

| TypeScript | Python | Required | Meaning |
| --- | --- | --- | --- |
| `cases` | `cases` | Yes, unless `ACCLIMATE_EVALUATOR_CASES` is set | Array of `{ caseId, input, expected, repetitions? }`. Python dict rows also accept `case_id`. |
| `execute` | `execute` | Yes | Runs one case against one version. May be sync or async. |
| `grade` | `grade` | Yes | Scores one output. May be sync or async. |
| `execution` | `execution` | No | `'live'` (default) needs `--live`. `'model-free'` is for deterministic adapters and needs no `--live`. |
| `revisionFiles` | `revision_files` | No | Files, relative to the module, whose bytes are part of the grader identity. |
| `configId` | `config_id` | No | Configuration name. Defaults to `application`. |
| `grader` | `grader` | No | `{ sourceUtf8 }` or `{ artifactDigest: 'sha256:…' }`. Defaults to the bound module digest. |
| `runtime` | `runtime` | No | `{ settings, artifacts }`. Settings are JSON. Artifacts map names to `sha256:` digests. |
| `toReviewArtifact` | `to_review_artifact` | No | Allowlist fields for review exports. |

Set `ACCLIMATE_EVALUATOR_CASES` to the absolute path of a private JSON case array (mode 0600) to replace the exported cases.

`repetitions` is a count that starts at 1 and defaults to 1. Each run receives a `repetition` index that starts at 0, so `repetitions: 3` produces repetitions 0, 1 and 2.

### Execute input

The execute callback receives the case `input`, `caseId`, `repetition`, a cancellation `signal` (Python `cancellation`), a private job `context`, and the verified `bundle`. Read the bundle's content with these helpers instead of filtering `bundle.payload.files` by kind:

| TypeScript | Python | Value |
| --- | --- | --- |
| `run.instructions` | `run.instructions` | Text of every instruction file, joined with blank lines. |
| `run.instructionFiles` | `run.instruction_files` | Instruction files. |
| `run.skillFiles` | `run.skill_files` | Skill files. |
| `run.memoryFiles` | `run.memory_files` | Memory files. |

Return `{ output, executionStatus?, outputRef?, usage? }` (Python `ExecutionResult`). `output` must be plain JSON. Convert a `Date` with `toISOString()` (Python `isoformat()`). TypeScript reports a non-JSON output type at compile time, naming the field. `usage` accepts `inputTokens`, `outputTokens` and `costUsd`. Python also maps `input_tokens`, `output_tokens` and `cost_usd`. Any other key marks the output invalid.

## Errors and exit codes

On a terminal, errors print as readable text:

```text
error[usage.missing_flag]: A required flag is missing. --live: This evaluator is live. Add --live to authorize model calls.
  usage:
    compare --config CONFIG --handoff HANDOFF [--live] [--policy POLICY] [--json]
  next: fix_command
```

Without a terminal, or with `--json`, stderr gets one JSON line with `code`, `message`, `field`, `reason`, `hint` and `nextAction`. Setup errors include the underlying exception, such as an `ImportError` or `ReferenceError` in your module, as `cause`. Add `--verbose` for the full stack trace.

| Exit | Meaning | What to do |
| --- | --- | --- |
| 0 | Success. With a policy, the candidate passed. | Nothing. |
| 1 | Usage or setup error: the command line, config, application module or definition. | Fix it and rerun. |
| 2 | The quality gate failed: the policy verdict is `fail`. | Review the candidate. |
| 3 | Indeterminate: the policy cannot decide, the run has not finished, or exported evidence is missing. | Inspect the evidence gaps. |
| 4 | The run or the service failed: the request finished as `failed`, the service was unreachable, or a policy receipt was not confirmed. | Check the service and the first callback failure, then retry. |
| 5 | Recovery required: execution may have started, a submission is unconfirmed, the journal needs attention, or the request was interrupted or has a newer parent. | Follow `nextAction` and [evaluation recovery](/docs/operate/upgrades-and-recovery#recover-an-evaluation). |

See [error codes](/docs/reference/error-codes) for every diagnostic code with its exit code and next action.

When the service is unreachable, `doctor` and `compare` report `service.unavailable` with the `serviceUrl` they tried. Check that the service is running and that the config's `serviceUrl` is correct.

## Callback failures

When an execute or grade callback raises, the evaluator records the exception type, a redacted message and the stack trace in `callback-error.json` in that arm's private job directory. Common credential patterns and the evaluator token are removed. The file stays on the evaluator machine and is never uploaded. Set `"captureCallbackErrors": false` in the evaluator config to opt out.

The `compare` and `run` output names the first failed callback and the path of its diagnostic file:

```text
First callback failure: "refund" [0] candidate · execute · execution_failed
  Details (private, not uploaded): /private/journals/…/callback-error.json
```

In JSON output, the same information is in `firstCallbackFailure`. Output that is not plain JSON is recorded in `output-validation.json` with the failing field.
