Use this page when you call Acclimate without an SDK, or when you need to read a raw response. It indexes the routes and explains authentication, payload verification and write retries.

## Contract files

| File | Describes |
| --- | --- |
| [`contracts/openapi.json`](https://github.com/anveld-dev/acclimate/blob/main/contracts/openapi.json) | Every route, request and response body, status code and error code, as OpenAPI 3.1. It is the source of truth. |
| [`contracts/bundle.schema.json`](https://github.com/anveld-dev/acclimate/blob/main/contracts/bundle.schema.json) | Bundle payloads. |
| [`contracts/learning.md`](https://github.com/anveld-dev/acclimate/blob/main/contracts/learning.md#codes-a-script-reads) | The learning status values a script can branch on. |

The SDKs ship the same shapes as types. In TypeScript, import them from `@acclimate/sdk`. In Python, import them from `acclimate` or `acclimate.types`.

JSON fields are camelCase on the wire and in both SDKs' request and response objects. Python method names, arguments and attributes are snake_case. For example, the Python `ApiError.request_id` carries the error body's `requestId`.

See [Versioning and compatibility](/docs/reference/versioning) for how the contract changes between Acclimate releases.

## Authentication

Send the credential as a bearer token, over HTTPS for any remote call:

```text
Authorization: Bearer <token>
```

- A machine token carries rights in a workspace: `read`, `write` or `promote`. See [Credential types](/docs/concepts/credentials#credential-types) for the other credentials and [Rights](/docs/concepts/credentials#rights) for what each right allows.
- A person calls the API through the console after signing in. On the learning routes, a signed-in person needs the Administrator role wherever a machine token needs `promote`. Releasing a version and publishing a bundle also accept an Editor.
- A few routes accept only a signed-in person. They refuse a machine token with 403 `denied`. The tables below mark them.
- A request with no token or an unknown token gets 401 `unauthenticated`. A token without the needed grant gets 403 `denied`. See [Service codes](/docs/reference/error-codes#service-codes).
- When an SDK client has a connection ID, it sends the ID as `X-Acclimate-Connection-Id` on version, payload and channel reads.

The [health endpoints](/docs/operate/health-and-readiness) `/health` and `/ready` need no token and sit outside `/v1`.

`GET /v1/workspaces` lists the workspaces the caller can access. Every other route in this table starts with `/v1/workspaces/{workspaceId}`.

| List or create releases | `GET` or `POST /bundles/{bundleId}/channels/{channel}/releases` |
| List or create connections | `GET` or `POST /connections` |
| Revoke a connection | `POST /connections/{connectionId}/revoke` |
| Issue a connection credential | `POST /connections/{connectionId}/credentials` |

## Read and verify a version

1. Resolve the channel. The response holds the channel's revision and the metadata of its version, which never changes. To ask only for a change, send the last `ETag` in `If-None-Match`. HTTP 304 means the channel still points at the same version.
2. Fetch the exact stored bytes from the version's `/payload` route.
3. Check the SHA-256 digest of those bytes against the metadata before you parse them. Parsing and writing a JSON object again can change the bytes.
4. Validate the parsed payload against the bundle schema.

A payload holds up to 128 UTF-8 text files of at most 256 KiB each and 1 MiB in total. Each file has a relative `path` and a `kind` of `instruction`, `skill` or `memory`. [Rules for bundle files](/docs/guides/deliver-content#rules-for-bundle-files) lists the path rules.

```json title="Bundle payload"
{
  "schemaVersion": 1,
  "files": [
    { "path": "instructions.md", "kind": "instruction", "text": "Answer in two short paragraphs." }
  ]
}
```

`POST /bundles/{bundleId}/versions` takes this object as `payload`, with an optional `parentVersionId`.

A release write takes three fields:

| Field | Value |
| --- | --- |
| `versionId` | The version to release. |
| `expectedRevision` | The channel's current revision, as a string. Use `"0"` for a new channel. |
| `unevaluatedReason` | The reason recorded with the release. It must not be blank. |

When the channel has moved, the write fails with 409 `revision_conflict`. Read the channel again before you submit a new release.

## Retry a write

### Idempotency keys

A write that requires an idempotency key, such as creating a version or a release, takes an `Idempotency-Key` header of 1 to 128 printable ASCII characters. To retry, send the same key with the same request bytes. The same key with different bytes gets 409 `idempotency_conflict`.

### Retained results

Bundle setup, version creation and release writes can keep their result, so you can read it after a lost response.

1. Send the write with a UUID as its `Idempotency-Key` and the header `X-Acclimate-Durable-Operation: true`.
2. If the response is lost, read the result with `GET /operations/{key}?operationPath={path}`. `{key}` is the idempotency key and `{path}` is the full API path of the original request. A bundle setup can be looked up by its key alone.
3. To stop the key from being used again, send `POST /operations/{key}/close` with the same `Idempotency-Key` and the JSON body `{"operationPath": "{path}"}`. A later write with that key gets 409 `operation_closed`.

## Learning

Every route in this section starts with `/v1/workspaces/{workspaceId}/bundles/{bundleId}/learning`, except the model provider. The Right column gives the right a machine token needs.

[Run a learning loop](/docs/guides/learning-loop) explains what the loop does with each call. [Learning codes](/docs/reference/error-codes#learning-codes) lists the codes these routes return.

### Loop

| Route | Purpose | Right |
| --- | --- | --- |
| `PUT` on the prefix | Turn on learning or change its settings: the channel, `domain` and `benchmark`, the task model, the judge model and `maxRoundsPerDay`. | promote |
| `GET` on the prefix | Read the loop: its status, why it is waiting or paused, the task counts in each split, the active round and any alert. | read |
| `POST /start` | Start the loop. Refused with `tasks-required` when a split has fewer than 20 admitted tasks, and with `optimizer-required` when the service has no optimizer. | promote |
| `POST /pause` | Pause the loop. | promote |
| `POST /resume` | Resume the loop. Refused for the same reasons as `/start`. | promote |
| `POST /stop` | Stop the loop. | promote |

While the loop waits, the `GET` response also holds `waiting`, `nextRoundAt` and `evolveTasksNeeded`. `optimizerConfigured` says whether the service has an optimizer.

### Tasks

| Route | Purpose | Right |
| --- | --- | --- |
| `GET /tasks` | List tasks, in pages. Filters: `split`, `source`, `admission`, `flagged` and `confirmed`. | read |
| `POST /tasks` | Create one task. | write |
| `PATCH /tasks/{id}` | Edit a task. This creates a new task revision and runs the admission check again. | write |
| `DELETE /tasks/{id}` | Retire a task. Its rows are kept. | write |
| `POST /tasks/confirm` | Confirm up to 100 held-out tasks in one change. Returns a result for each ID. | write, signed-in person only |
| `POST /tasks/{id}/recheck` | Run the admission check again for a task set aside with `check-failed`, without a new revision. Any other state returns 409. | write |
| `POST /tasks/recheck` | The same for every `check-failed` task, or for the `taskIds` in the body. | write |
| `GET /held-out-tasks/export` | Download the held-out tasks. | Signed-in person only |

### Imports and trials

| Route | Purpose | Right |
| --- | --- | --- |
| `POST /tasks/import` | Upload a spreadsheet, CSV, JSONL or text as a stream. Returns an import with its counts. | write |
| `GET /tasks/imports` | The 50 most recent imports, newest first, with counts, `createdAt` and `source`. | read |
| `GET /tasks/imports/{id}` | One import's status and its counts of converted, pending and set-aside rows. | read |
| `POST /tasks/{id}/try` | Run one task on the executor against the channel's current version. Returns a trial ID. | write |
| `GET /trials/{id}` | A trial's status, gateway log, output and verdict, and `error.code` when it failed. | read |

An import sent from a console session also returns the drafted task cards.

### Rounds and rollback

| Route | Purpose | Right |
| --- | --- | --- |
| `GET /rounds` | The round timeline. | read |
| `GET /rounds/{id}` | One round with its candidates, diffs and diagnoses, and the results on the evolve split. | read |
| `POST /rollback` | Move the channel back to the version a named round replaced. The removed version is blocked from adoption. | promote |
| `GET /blocked-versions` | Versions blocked from adoption after a rollback or an automatic revert. | read |
| `DELETE /blocked-versions/{digest}` | Unblock a version. | promote |

### Usage, outcomes and memory

| Route | Purpose | Right |
| --- | --- | --- |
| `GET /usage` | Rounds, rollouts and tokens for each day. | read |
| `POST /outcomes` | Report a production outcome, with an optional `grading`. The SDKs send it from `job.expect()`. | write |
| `GET /memory` | The improvement memory at a revision. | read |

### Model provider

The workspace's model provider is at `/v1/workspaces/{workspaceId}/model-provider`.

| Route | Purpose | Right |
| --- | --- | --- |
| `GET` | Read the base URL, the allowed models, whether a provider API key is set and the executor's verification result. It never returns the key. | read |
| `PUT` | Save an OpenAI-compatible base URL, the provider API key and the allowed models. | Signed-in administrator only |
