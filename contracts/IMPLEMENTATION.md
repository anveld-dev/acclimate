# Core implementation contract

The additive [installed evaluator and review contract](dx-evaluation.md) covers the DX release's public handoff, retained evaluator operations, capability checks, response budgets and read-authorized observations.

The [remediation freeze](remediation.md) adds immutable bundle targets, opt-in durable console receipts/fences, request- and attempt-bound evaluation evidence and current effective replay authorization. Its reviewed ownership and rollout rules supersede the original R0 ownership/24-hour details below for those named paths.

`packages/sdk/src/types.ts` is the frozen wire contract. Rust DTOs use camelCase and match it. No types are silently forked. Root owns shared changes.

API prefix `/v1/projects/{projectId}`. POST `/bundles` takes `{name}` returns Bundle. POST `/bundles/{bundleId}/versions` takes CreateVersionRequest returns VersionMetadata. GET metadata and `/payload` use `/bundles/{bundleId}/versions/{versionId}`. GET `/bundles/{bundleId}/channels/{channel}` returns ChannelResolution, or 304 with ETag. POST same path plus `/promotions` takes PromoteRequest returns Promotion. POST/GET `/bundles/{bundleId}/proposals[/{id}]` returns Proposal. POST/GET `/bundles/{bundleId}/comparisons[/{id}]` returns Comparison. Mutations 201 except proposal 202. Errors ApiErrorBody: 400 invalid_content, 401 unauthenticated, 403 denied, 404 not_found, 409 revision_conflict/parent_conflict/idempotency_conflict, 413 payload_too_large, 503 unavailable. Other validation errors 400. GET /health is unauthenticated liveness.

All mutations require Idempotency-Key (1..128 printable ASCII). Auth config is `ACCLIMATE_AUTH` JSON array of `{token,principalId,projectId,rights:["read","write","propose","promote"]}`. Each command requires its right, with read access separately. Static tokens for one trusted organization, operator supplies strong tokens and TLS. No implicit development credentials. Fingerprint method + scoped path + exact body bytes. Dedup rows and writes commit atomically, key scoped principal/project/method/path. Retain 24h (expired can be reused); failures roll back. Recheck access before replay.

Service stores an accepted payload as its encoded JSON UTF-8 bytes once (compact + newline); hashing/download use stored bytes. Cross-language fixture tests verify fixture bytes, not a reserialized object. At most 128 files, 256KiB per UTF-8 text, 1MiB complete payload; paths max 240 ASCII chars, slash-separated portable relative segments, each `[A-Za-z0-9._-]+`, no dot/dotdot/empty/reserved device names or case collisions; reject prefix file/directory collisions too. No archive/symlinks in payload. Request cap 2MiB. Nonempty names, channels `[A-Za-z0-9_-]{1,64}`. All records project/bundle scoped.

A comparison's results may be an incomplete subset of its unique expected inventory. Every included pair has both outcomes. Complete means all expected pairs present, no infrastructure failures, all grades scored and finite; task failures can be scored by the declared rubric. Null grades and costs stay null. Validate nonnegative finite usage, repetitions >=0, at most 1000 expected pairs. Parent and candidate must match stored digests and candidate.parentVersionId. Runtime/dataset/grader identity nonempty. Reports are immutable app assertions. Evidence promotion requires complete report matching target and parent and CURRENT channel version == parent, as well as revision CAS. It does not assert score improvement: human reviewer decides. Empty channel, manual seed and rollback use unevaluatedReason. Promotion response includes new revision/version and history fields. No public history listing required initially.

The service checks recorded application policy receipts before publishing a candidate. A failed or indeterminate receipt on any comparison for that version returns HTTP 409 `policy_override_required`. A promoter can supply a complete matching comparison and `policyOverride` containing a reason and the exact set of blocking `{comparisonId,policyDigest}` pairs. Draft publication uses the same check. The promotion history records the decision and reviewer. Restoring a previously approved release may reuse the approval while the blocking receipts stay identical. The resulting promotion identifies the original approval in `policyApprovalPromotionId`. For connected rounds a blocked automatic promotion waits for an independent reviewer.


Proposal request pins parent, allowed existing paths, hypothesis and up to 20 bounded evidence strings. Service proposer may change only text at existing allowed paths (same path/kind set, unchanged other files), then stores full candidate and rationale; it never executes tools. Default provider disabled: accepted proposals fail explicitly if none configured. Real provider is an optional configured OpenAI-compatible model client, enforce Luna model identifiers for this development session; fake provider is for tests only. Limit one active model request per process, 3 attempts, 60s timeout, output cap; persist attempts and candidate/success in one transaction; restart unfinished jobs with bounded retries, no retry of successful candidate. Document single-process deployment, no multi-replica queue claim.

SDK baseline exports: `AcclimateClient`, `ApiError`, `resolveAndCache`, `prepareFiles` and all types. Constructor options `{baseUrl,token,scope}` (scope is stable authenticated principal identity supplied by app; never token on disk). Client methods accept projectId,bundleId,... and request args; SDK owner settles exact optional policy signatures and documents them for plugin/helper owners. VerifiedBundle carries version,payload,resolution?,resolvedAt,stale. Native plugins accept VerifiedBundle and create their own private temp workspace, return cwd and cleanup plus native mapping. They never run models. Root owns manifests and lockfiles; agents send dependency requests. Comparison helper owns compare.ts + own tests, requests export through SDK owner; no native execution or hosted grading. Native live smoke uses only gpt-6-luna/gpt-5.6-luna; no fallback to other models.

File ownership for shared checkout: root contracts/types/manifests/docs/scripts/CI; Rust agent Cargo.toml,Cargo.lock,src/,migrations/,tests/; SDK agent packages/sdk/src/{client,cache,prepare,index}.ts + tests/delivery/; comparison agent compare.ts + tests/compare/ + examples/compare-review.ts; native agent packages/{codex,claude,pi}-plugin/src + own tests + examples/codex-smoke.ts + native-integration README. No worktrees required for these nonoverlapping directories. No implementation commits until tests pass unless root coordinates it.
