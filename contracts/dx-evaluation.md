# Installed evaluator and review contract

The normative design is [PLAN.md](../docs/design/developer-experience-council/PLAN.md), approved D2. This contract records additive wire/packaging changes; implementation evidence belongs in the DX acceptance ledger, not in the design consensus.

- SDK descriptor/handoff/capability/observation types live in `packages/sdk/src/types.ts` and are mirrored by Python TypedDicts. Public configuration contains revisions, runtime identity and fixed case/repetition inventory, never callbacks, credentials, private case contents or expected answers.
- `GET /v1/projects/{p}/evaluation-capabilities` authenticates the caller's static machine read/write grant, rejects console identities, validates supported guided targets, and returns a private/no-store point-in-time snapshot. It never reserves access or probes a provider. Current evaluator write is broad project write; propose/promote are not required.
- Guided project IDs are 1–128 ASCII letters/digits/`._-`, excluding dot/dotdot. IDs in guided routes are canonical lower-case UUIDs. Unsupported targets never silently downgrade a retained evaluator write into transient deduplication.
- Comparison creation and evaluation start/finish/interrupt participate in the existing retained operation namespace. Marked requests retain results/fences independently of the transient 24-hour cache. Every writer/replay/lookup/close rechecks current effective authority. Operation results may contain a Comparison and remain distinct from delivery observations.
- New evaluators persist exact UTF-8 request bodies before send, reuse original keys, and reconcile authoritative lifecycle state after historical replay. An execution marker without a sealed report forbids reexecution. No report submission, heartbeat, interruption or signal proves exactly-once external work or provider termination.
- TypeScript and Python share the fixed ordered scope encoding and one kernel flock inode. Their unfinished journal formats remain runtime-owned and cannot take over one another. Original service/project/principal/root are preserved; schema-1 historical TS requests have explicit recovery limits when their original transient outcome expired.
- Request bodies remain bounded to 2 MiB. Ordinary JSON and operation response envelopes have an explicit bounded 4 MiB default in both SDKs; raw content retains its distinct download budget. Responses are bounded while reading, before JSON parsing.
- `GET /v1/projects/{p}/integration-observations` exposes bounded read-authorized discovery independently from admin credential management. Its latest observation is one retained receipt selected by server receivedAt/eventId; version/stage/time fields are never mixed across rows. Missing/expired observations are unknown, not consumption evidence.
- Public Node-only evaluator/CLI/policy/artifact exports are separate from pure validation. Installed starters own execution, grading, quality policy and optional review redaction statically. Requests cannot select executable code. Run completion, quality-policy satisfaction and deliberate release authority stay separate.
- Review exports are explicit role-level sidecars over confirmed immutable comparisons. Default projection omits raw outputs/errors/runtime values/paths. Optional output/explanation release requires a static mapper and explicit selection. Local consistency and online scalar binding do not attest model execution or redacted output truth.

A terminal comparison can carry private policy receipts. Each receipt binds the policy digest, verdict and checks to the request, attempt, comparison and reporting evaluator. Project readers can inspect them under the comparison’s evidence permissions. A candidate with blocking receipts requires an explicit authorized override of the current receipt set.
