Draft and Content already label this capability. Reuse a small Read only cue in the existing review/history heading so unavailable actions have a visible explanation. This is discoverability, not an authorization defect.
6. Existing release dialogs correctly freeze candidate, expected channel revision, draft generation and either selected evidence ID or manual reason. Their ordinary desktop render is approved as a baseline. No proven release-safety bug found in the reviewed branches. Accessibility peer identified a source-supported focus-return concern: publish/restore are controlled dialogs without DialogTrigger, while installed Radix default return uses its trigger ref. Explicit invoking-ref/fallback behavior must be proved or repaired for Cancel, Escape, outside-close and success.

## Shared component proposal

Use the same Disclosure for “details” and subordinate recovery/setup information, the same status row for reported state plus timestamp, and the same decision summary for publish/restore identity. Reserve strong action styling for the next concrete action (create request, inspect evidence, review release, confirm), with manual release remaining an explicitly named alternative. Keep recovery warnings visible outside collapsed details and reuse one recovery panel layout across owner/foreign operations without erasing their distinct retry permissions and original-route binding.

Do not turn details into a set of new persistent navigation modes. The evidence table, diff, configuration and operational diagnostics can expand inside the existing workspace panel; preserved form state and exact scope are more valuable than visual uniformity alone.

Peer debate: editor and navigation reviewers agree that whole-draft Save, entry operations and exact saved-generation evaluation remain separate; no generic Run action or new navigation mode. Admin agrees recovery should share a visible status/reason grammar while preserving unlike credential and content-operation rules. Systems and release reviewers agree publication/restore dialogs should use content-aware desktop width (roughly 480–512px), wrapping/stacked footer actions and a reusable identity summary. The baseline evidenced footer is much closer to the dialog edge than manual confirmation; this is an alignment issue observed in the PNG, not proof of clipped controls. Keep the explicit action label rather than abbreviating away evidence binding. Accessibility review requested phone/zoom, long reason and keyboard focus evidence. Installed Radix analysis raises a real focus-return concern for triggerless controlled publish/restore dialogs; preserve or restore focus through explicit invoking refs and a stable fallback. The shared dialog already caps height against the viewport, so do not describe absent scroll containment as a confirmed defect.
