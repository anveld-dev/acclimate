## Baseline spacing and type contract

Do not assess only the primitive JSX defaults: global CSS overrides them.

- Body and labels are 14px; `--text-xs` is deliberately reset to 14px. Small metadata must remain readable rather than receding to 11–12px.
- Button/Input/NativeSelect are at least 36px at fine pointer; controls, disclosure triggers, navigation links, dialog close targets and form labels become at least 44px at coarse pointer. Mobile/coarse text entry uses 16px to avoid zoom and preserve legibility.
- Dialog is 384px by default; workspace creation opts into 512px, workspace details 576px, version inspector 1024px. Current Connections and Members dialogs use the 384px default. Dialog global padding is 24px, gap 20px, title 18px, description 14px/1.6; mobile ≤600px padding is 16px. Narrower optional native classes do not override this cascade by themselves.
- DialogHeader reserves 32px for close, while the coarse close target is 44px with an 8px right inset; long titles need actual 320px overlap evidence and possibly a larger reserved header region; DialogFooter stacks reverse-order below 640px and otherwise lays out right-aligned actions. The large evidenced-release footer does not fit comfortably inside 384px with 24px side insets in the actual desktop screenshot.
- Editor baseline at desktop is source top 156px, width 1006px, visible source 676px. Mobile390 draft top 288px/visible 556px, mobile320 top 350px/visible 494px; desktop read-only content top111px/visible662px. These measured layout-4 budgets are acceptance floors, not permission to shrink type or targets.
- File rows and selected heading wrap paths; mobile picker opens in normal document flow so it never covers source. Shared editor textarea uses 14px/22px fine pointer, 16px mobile/coarse, with an inset focus ring.

## Concrete material improvements

1. **Content-aware confirmation width and wrapping footer.** Keep simple revoke/discard confirmations compact. Give publish/evidence/restore identity confirmations a standard 480–512px tier and preserve the explicit evidence-qualified primary label. At every tier, footer actions must wrap or stack within the content inset; long localized labels must not escape it. Keep task identity and consequence visible above technical IDs. Existing Dialog remains the implementation surface.
2. **Shared coarse menu-item contract.** `DropdownMenuItem` is a Radix menuitem, not a button; the global coarse `button` selector does not guarantee 44px targets. Draft actions hardcode 44px locally while Add entry currently uses 32px. Add the coarse minimum to the existing menu primitive/slot contract and verify all menus; avoid one-off page fixes.
3. **Local form failure conventions.** An overlay mutation must show its error inside that overlay, with a field association and `aria-invalid` when the error is field-specific. Editor package rename currently reports through the outer draft message, potentially behind the modal. Promote a narrow reusable form-error convention if repeated; do not invent a generic form schema.
4. **Accessible full identifier path.** `ShortId` renders an eight-character code with native `title` as the full-value hint, but is currently unused and is therefore component debt rather than a current user-path defect. For current singleton workspace truncation, prefer wrapping the visible link/name; if a full ID is needed for a task, provide a selectable/copyable full value in existing details/popover/disclosure or a focusable trigger. A cosmetic tooltip alone does not provide a coarse-pointer/copy path. Keep the input validation `title` if useful, but show workspace slug syntax as visible helper text too.
5. **Single disclosure for single action.** Draft footer import nests an outer disclosure around ImportContent's own disclosure. Collapse the composition to one trigger/body while keeping form state mounted. This is a tangible reduction in state ambiguity rather than another visual style.

6. **Group form relationships within modal bodies.** New connection renders Label/Input and Label/NativeSelect as separate DialogContent grid children, so the outer 20px gap applies within each field as well as between fields. Members already groups each label/control with an 8px rhythm. Add a conventional body/field grouping composition using existing Label/Input/NativeSelect (8px within a field, 16px between fields, outer 20px between header/body/footer). This makes the relation clear and preserves space without a schema framework.
7. **Explicit focus restoration for controlled overlays.** Existing Radix Dialog restores to DialogTrigger, but several controlled modal flows (Members, Connections, Restore, Publish) are opened by external buttons without DialogTrigger or explicit close-return refs. Carry the invoking element or a deliberate logical fallback in the shared application composition; verify return focus after cancel, successful mutation, and trigger removal. This is a source-confirmed gap to test in actual renders, not a claim that a keyboard failure was already reproduced.
8. **Shared mobile page heading layout.** Navigation reviewer identifies Menu, title/description, and New bundle competing in the same narrow PageTitle flex row. Reserve a distinct full-width line for explanatory copy where it materially crowds; verify this shared wrapper across Bundles, Connections and Members.

## Optional improvements requiring evidence

- A new hover/focus Tooltip wrapper for truncated names can be useful if full names already have a durable touch/keyboard path. TooltipProvider alone does not prove that path. Do not hide action labels or essential status behind hover.
- A shared inline status/error composition may improve icon/tone/spacing consistency, but existing `role=status`, `role=alert`, CopyButton, and Sonner already provide real feedback. Toasts should announce a confirmation while persistent page state carries a result or recovery action.
- Standardize the current scattered 8/12/16/20/24px spacing only when a repeated relationship differs. Do not normalize editor padding, form layout and review disclosures to one generic card.
- A sticky header/footer inside long modal can help, but verify body scroll, keyboard focus and 200% zoom first. Current content scroll is valid and simpler than nesting scroll areas everywhere.
- Overlay backdrop darkness/radius changes are aesthetic. Current black80 overlay+blur clearly isolates tasks; changes need visual contrast evidence and are less important than action containment or field errors.

## Peer debate and implementation gate

Debated directly with navigation, editor, release, admin and accessibility reviewers before and after viewing all six actual boards. Navigation and editor agree D decision + A/E utility is useful; both reject moving entry commands into the Draft menu. Navigation rejects wholesale Sidebar adoption and invented routes; editor rejects B bottom Save and C source displacement. Release ranks D highest for decisions, accepts visible full binding and explicit action labels, and rejects A tooltip-only parent; its higher C release ranking is compatible with rejecting C as a complete editor system. Admin agrees contextual forms, exact revoke targets and field grouping transfer without a schema. Accessibility confirms controlled-dialog return-ref and coarse menu-item gaps, and requests actual short-viewport/long-title checks.

Root implementation scope now reported: contextual 512px decision dialogs, wrapping footer, invoking-element return focus, bounded popups; grouped admin fields/local help/exact revoke identity/SDK duplication reduction; shared PageTitle/coarse menu items/local Entry errors/single importer disclosure. This is appropriately bounded. Challenge: do not turn every dialog into a fixed 512px surface, add an unnecessary generic DialogBody API, force universal identity schemas, add every conceptual menu item, or call generated phone insets runtime proof.

The implementation gate requested that new browser evidence show ordinary and long decision content, 320/390px and native 200% zoom, menu coarse targets, local rename error inside modal, importer one-trigger retention, close title reserve, focus after cancel/success/removing the triggering entry, and popup scroll containment. Existing 1006px/y156 desktop editor and narrow source budgets, 14px minimum reading type and 44px coarse targets remain acceptance criteria. Include toast/modal overlap evidence: baseline dirty-confirmation PNG shows save toasts outside the scrim; this is a known composition to inspect, not a demonstrated blocker. No reviewer approval is implied by passing source review or by generated image quality.
