# Information architecture and product review

## Initial audit

Viewed current actual 1440px Content, dirty draft, review and Releases captures, plus expanded release details, version inspector, draft history and incomplete evidence lookup. Read published-content, release-history and navigation source.

- The two navigation scopes are useful: workspace destinations above bundle/channel destinations. Keep exact scope and dirty-navigation guards; another permanent navigation rail needs a demonstrated task benefit.
- Content and draft already use a compact persistent file explorer with distinct selected-file and whole-draft actions. Preserve published versus browser edits versus saved generation. More source width alone does not justify hiding frequent file selection.
- Releases still spans the entire desktop for a short summary and remote Inspect/Restore actions. A bounded history could improve identity/action association. Existing disclosure, version inspector and deliberate restore-with-reason behavior should remain distinct; no new selection state is inherently needed.
- Review has a clear first action, Inspect evidence, but many equal-weight disclosure bands below it. Any regrouping must preserve file changes, saved snapshot identity, evaluation request/lookup and manual release as separate tasks. Selected evidence and its completeness facts must remain central.
- IDs and technical provenance appropriately live behind disclosures until needed. Hidden states can be long: release details, draft snapshot history and raw comparison data need wrapping and local hierarchy, not additional default summary duplication.

V9 setup/admin are accepted baseline.

## Concept verdict after debate

Viewed all six actual v10 images and debated all five peers. Borrow a small coherent A/C/E change; retain current core navigation, editor and single-column evidence review.

- **A:** reduce redundant scaffolding, not task separation. The Evaluation request heading can go when its Set up/Create another disclosure already names the task. Omit an empty Results section only when there are no matching requests **and no older-page cursor**. Preserve cursor explanation/pagination, loading/error/pending states and independent disclosures. Reject the mock's service-run evaluation, invented command, inline publish/evidence selector and missing manual reason.
- **B:** reject the side tools column. It spends paired-outcome width on infrequent utilities and replaces actual missing/execution/grading facts with invented score summaries.
- **C/D:** borrow a true 1024px history bound and responsive aligned actual metadata. Keep existing stacked records, complete UTC timestamps, full reasons and separate Inspect/Restore behavior. Rigid tables compress long reasons and IDs; new revision input, current-release Restore, invented fields and colored policy interpretations are invalid.
- **E:** use one attached submitted-search input group inside the existing rail. Preserve Enter/button application to the URL, applied count/clear/path state and actual raw published source. Search tooltip must work on focus/hover; coarse targets stay usable. Reject mock instant/pending semantics and rendered or mutable content changes.
- **F:** reject the remote toolbar. It separates filtering from the list, repeats Files/path chrome and fabricates published-entry operations.

## Final actual implementation verdict

Accept the narrow A/C/E implementation on final build `26b421e824c921e6806f7553819bab836d9bcd75f274fdc8e0050169e47ec85b`. Personally viewed the accepted 1440px three-release overview and independent expanded details, filtered published search, evaluation first use, zero-match page with real cursor, loaded older matching evidence, 1024px restore Dialog, native 200% release details/search and keyboard-focused search tooltip. Re-read final search, evaluation setup/cursor and release layout source.

- The 1024px history bound improves record/action proximity. Aligned metadata keeps full reviewer, release/version IDs, digest, previous version and optional comparison in flow. Full UTC/reasons and deliberate restore reason/context survive; no table or selection layer was added.
- Attached search stays with the file list and restores useful input width. Actual raw published source remains central. The focused native-zoom capture shows the submit control contained within its group with a readable tooltip. Accepted workflow evidence verifies typed input does not navigate until submission, q/kind/path semantics, clear/no-match behavior and narrow navigation.
- First use removes the meaningless empty Results band while retaining file/snapshot review and setup. The real zero-match cursor capture still explains incomplete pagination and offers Load older requests; later evidence is reachable. App execution and evidence limits remain explicit, with no side inspector or synthetic score summary.

The accepted summary reports five passing checks/39 captures; native-tooltip-focus reports one passing check/three captures, both with matching final hashes before/after and no geometry violations. Those are inspected evidence reports, not tests run by this reviewer. Synthetic bound outcomes establish UI/provenance behavior only.
