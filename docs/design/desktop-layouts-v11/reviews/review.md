# Creation and suggestion workflow review

Initial source audit covers `bundle-library`, `bundle-changes`, `improvement-workspace` and history refresh logic, plus the current actual desktop library. The library already has a compact 1024px bound and exact channel links; a bundle without published channels is not openable. Search is local and appears for larger inventories. Creation is a publication task, not a draft: retain initial channel, fixed compatibility target, publication preview/no-evaluation summary, import confirmation and unresolved-creation recovery before resubmission.

Changes has intentionally different inventories: saved drafts belong to the selected channel; provider suggestions span all channels and need review before choosing a release channel. Keep these scopes, separate refresh/errors/cursors and draft status/generation. Unknown/error states are not empty histories. Queued, running, succeeded and failed suggestions must remain distinct; succeeded means reviewable content, not approval or publication. Loaded active suggestions refresh even outside the newest page.

Suggest a change must retain source channel/revision and published parent details, hypothesis, editable paths and authorized evidence. The provider receives the whole parent bundle including reusable memory; editable paths restrict writes, not reading. Private session memory remains app-owned. Keep that distinction visible beside explicit unchecked provider-disclosure consent and Request suggestion. The command is disabled without consent, hypothesis and selected paths; read-only, pending submission and related-operation guards remain. Frozen recovery must preserve later browser edits rather than treat them as the submitted request.

I inspected all six A–F images and debated the five other reviewers. **Borrow only A’s bounded Changes index and C’s bounded whole suggestion form.** A’s geometry can align actual draft/suggestion facts without inventing names, per-channel suggestion metadata or draft execution statuses. Keep sequential inventories and full details. C’s 768px reading area is appropriate only when notices, errors and pending recovery share the same bound. Reject its collapsed Check result and invented configured/awaiting sections. B compresses unrelated workflows into parallel columns and adds unsupported draft “Ready/Running” states. Current library and inline creation beat E/F’s duplicate forms, nested modals, invented compatibility/multiple initial channels and direct import publication shortcuts.

The SDK already accepts `status: 'all'`, so repair can use existing read capability. If all-status pages are locally filtered, an all-closed page with an older cursor must not claim the channel has no open drafts. Keep pagination and the loaded-page distinction, or request open/all explicitly and reset the matching pagination scope.
