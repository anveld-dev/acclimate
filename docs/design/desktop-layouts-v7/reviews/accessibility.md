# Accessibility and interaction review

I inspected all six generated images, the actual v6 1024/1440/1920 draft screens, long-name/path evidence, focused tooltip and entry dialog, and native 200% zoom captures. I also read Shell’s focus ownership, FileNavigator, shared Dialog/Tooltip/Popover/menu/disclosure components and styles, and the accepted runtime summaries. Images establish visual composition; they do not establish keyboard or assistive-technology behavior.

My ranking is **A > C > B > E > D > F**. A gives the bundle title room to wrap and places the channel in a separate scope row. C offers the same useful allocation more compactly, but its one-line title and missing Draft label are not implementation requirements. B still makes the title compete with a wide channel. E makes the whole selected channel readable, but its apparent multiline select should not replace the tested native selector. D delays file access below bundle navigation and adds substantial responsive/focus work. F separates dirty state and save/evaluation actions from task entry without evidence that the distance benefits users.

I debated all five peer reviewers. Hierarchy, workflow, systems and evaluation favor C before A; the skeptic and I favor A’s honest wrapping. We agree on the actionable common ground: improve long-name allocation with the existing controls. Preserve ordinary compact headers, full visible identity where it fits, and actual product paths and labels. Generated `/AGENTS.md` and `skills/review/SKILL.md` are not product facts.

The current interaction system deserves preservation. The real long-1024 screen wraps the title and full selected path rather than making identity hover-only. The cost is excess height because the channel gets most of the row. A targeted scope reflow is justified; smaller type, icon-only navigation and a new select are not.

Current source and accepted v6 evidence support 14px text, coarse-pointer 44px controls, visible keyboard focus, hover and focus tooltip access, Escape and focus return, scrollable decision dialogs, mounted but hidden disclosure content, and native 200% continuity. The ten-cycle immediate resize run passes all twenty handoffs. Shell remembers navigation focus ownership while preserving editor and modal ownership; there is no evidence to reopen the repaired BODY-focus race.

The actual implementation earns support independently of the concept ranking. I inspected new long-name 1024/1440/1920 and ordinary-1440 captures in `artifacts/desktop7-scope`, coarse-1024, 900/600 edges, and focused tooltip, menu, entry dialog and resized-account states in `desktop7-desktop`. The long desktop title and channel are readable at rest; ordinary headers remain compact. Directory boundaries read better without changing copied path text. The 900px layout honestly spends another row when necessary. I see no remaining desktop composition problem that warrants another generation round.

Fresh desktop and edge summaries pass focus ownership, Escape/fallback, source retention, coarse targets and overlays against build `837fea…`. This supports retaining the existing focus system. I also inspected fresh native-200% draft, published content, evaluation and SDK captures in `desktop7-core`: the named navigation, state, file picker and actions reflow visibly, with no horizontal obstruction. Its 58-capture summary passes; `desktop7-interactions` passes 54 captures and 196 checks, including dialog Escape/return cases. At 600px, the long native channel still clips visually; desktop gains should not be presented as solving arbitrary narrow-name display. Native popup appearance and broad assistive-technology behavior remain outside this evidence.

**Verdict:** support the limited implemented reflow and preserved interaction foundation. Do not infer broad assistive-technology qualification from screenshots or these checks.
