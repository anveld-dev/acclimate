# Installed evaluator and review contract

> **Internal development record.** This file coordinated parallel implementation work and is not a consumer contract. Routes now use `/v1/workspaces/{workspaceId}` and releases replace promotions. Use [`contracts/openapi.json`](../../../contracts/openapi.json) for the wire contract and the [versioning and compatibility reference](../../../apps/docs/content/docs/reference/versioning.mdx) for compatibility rules.

The normative design is [PLAN.md](../../design/developer-experience-council/PLAN.md), approved D2. This contract records additive wire/packaging changes; implementation evidence belongs in the DX acceptance ledger, not in the design consensus.

- SDK descriptor/handoff/capability/observation types live in `packages/sdk/src/types.ts` and are mirrored by Python TypedDicts. Public configuration contains revisions, runtime identity and fixed case/repetition inventory, never callbacks, credentials, private case contents or expected answers.
- `GET /v1/projects/{p}/evaluation-capabilities` authenticates the caller's machine principal, rejects console identities, validates supported guided targets, and returns a private/no-store point-in-time snapshot. It never reserves access or probes a provider. `writeEvaluation` is true when the principal holds `evaluate`. Additive fields report `rights` (`read`, `evaluate`, `write`, `propose`, `promote`), `credential` (`{kind:"static"}` or `{kind:"machineToken",id,expiresAt}`) and `abandonment` (`explicit`, `inactivitySeconds`).
- The narrow `evaluate` right is the evaluator's least privilege. It implies `read` and covers draft creation for a candidate, evaluation request creation, start/finish/interrupt/abandon, progress, comparisons and policy receipts. It never publishes or discards drafts, creates versions directly, promotes or changes channels. `write` implies `evaluate`, so existing evaluator grants keep their authority.
- Workspace administrators issue, list, rotate and revoke expiring machine tokens (`acm_` prefix, principal `machine:{name}`) at `/v1/workspaces/{p}/machine-tokens` and read the append-only audit at `/v1/workspaces/{p}/machine-token-events`. Secrets are stored as SHA-256 digests and returned once. Each transaction rechecks the token under a row lock, so revocation applies to the next request without a restart. Static `ACCLIMATE_AUTH` grants remain valid.
- Evaluator configs supply the token inline (`evaluatorToken`), through an absolute private `evaluatorTokenFile` with the config file's permission checks, or from `ACCLIMATE_EVALUATOR_TOKEN` when neither is named. Naming both fields is a schema error.
- Guided project IDs are 1–128 ASCII letters/digits/`._-`, excluding dot/dotdot. IDs in guided routes are canonical lower-case UUIDs. Unsupported targets never silently downgrade a retained evaluator write into transient deduplication.
- Comparison creation and evaluation start/finish/interrupt/abandon participate in the existing retained operation namespace. Marked requests retain results/fences independently of the transient 24-hour cache. Every writer/replay/lookup/close rechecks current effective authority. Operation results may contain a Comparison and remain distinct from delivery observations.
- New evaluators persist exact UTF-8 request bodies before send, reuse original keys, and reconcile authoritative lifecycle state after historical replay. An execution marker without a sealed report forbids reexecution. No report submission, heartbeat, interruption, abandonment or signal proves exactly-once external work or provider termination.
- `abandoned` is a terminal evaluation status. A running unmanaged attempt is abandoned after `ACCLIMATE_EVALUATION_ABANDON_SECONDS` without a start, progress report or bound comparison, or explicitly through `POST .../evaluation-requests/{id}/abandon` with a reason. Evaluations add optional `lastActivityAt`, `abandonedAt` and `abandonedBy`. The service refuses the attempt's later reports and promotion rejects any comparison bound to it (`evidence_abandoned`). A new request for the same candidate may then start, and `--retry-after` accepts an abandoned predecessor. Abandonment only fences server-side evidence; it never claims the original worker stopped, and a replacement can repeat external work. Connected-learning requests refuse it.
- TypeScript and Python share the fixed ordered scope encoding and one kernel flock inode. Their unfinished journal formats remain runtime-owned and cannot take over one another. Original service/project/principal/root are preserved; schema-1 historical TS requests have explicit recovery limits when their original transient outcome expired.
- Request bodies remain bounded to 2 MiB. Ordinary JSON and operation response envelopes have an explicit bounded 4 MiB default in both SDKs; raw content retains its distinct download budget. Responses are bounded while reading, before JSON parsing.
- `GET /v1/projects/{p}/integration-observations` exposes bounded read-authorized discovery independently from admin credential management. Its latest observation is one retained receipt selected by server receivedAt/eventId; version/stage/time fields are never mixed across rows. Missing/expired observations are unknown, not consumption evidence.
- Public Node-only evaluator/CLI/policy/artifact exports are separate from pure validation. Installed starters own execution, grading, quality policy and optional review redaction statically. Requests cannot select executable code. Run completion, quality-policy satisfaction and deliberate release authority stay separate.
- Review exports are explicit role-level sidecars over confirmed immutable comparisons. Default projection omits raw outputs/errors/runtime values/paths. Optional output/explanation release requires a static mapper and explicit selection. Local consistency and online scalar binding do not attest model execution or redacted output truth.

A terminal comparison can carry private policy receipts. Each receipt binds the policy digest, verdict and checks to the request, attempt, comparison and reporting evaluator. Project readers can inspect them under the comparison’s evidence permissions. A candidate with blocking receipts requires an explicit authorized override of the current receipt set.
