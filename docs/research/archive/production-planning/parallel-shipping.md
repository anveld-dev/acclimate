# Production shipping work split

Planning only, 2026-11-14. [Reviewed plan](../../../architecture/production-only/plan.md) and [review decisions](../../../architecture/production-only/review.md) govern this split. Source inspection only; no application edits, runtime launches, tests, private-state reads, database access, browser actions or model calls. Existing PostgreSQL data and private launcher/evaluator state must survive retirement of the old entrypoints.

## Contracts to freeze before implementation

- **One deployment:** make `compose.yaml` the complete single-host stack: Rust API, built Node console, PostgreSQL 16 and Caddy TLS proxy. Retire `compose.service.yaml` as an operational overlay; retain a refusal/comment pointing to the canonical recipe if compatibility needs it. Systemd remains explicitly API-only documentation. No second complete deployment platform.
- **Configuration:** auth/runtime owners publish the exact environment names, redacted diagnostics, obsolete-variable rejection, and config-only preflight interfaces. Shipping consumes them, without reimplementing authentication validation. Rust config-only validation does not connect to PostgreSQL or run migrations. Console validation is callable before built-server import and before Vite listens, while build/import for bundling remains secret-free.
- **Processes:** production service start executes the release binary; console start executes its built Node entrypoint. Development uses the same required identity configuration and Vite. No command provisions a database, infers an OS-user database, creates secrets, seeds examples, starts Docker, reads `.local/console-demo`, or launches a local bridge. Retained `local`/`demo` aliases only explain replacements and fail.
- **Origin/networking:** one pinned HTTPS console origin, a separately configured public HTTPS API URL for external SDK recipes, and explicit private HTTP upstream addresses. Caddy strips/replaces forwarding headers and sends the defined Host/proxy representation; console owner defines precisely which representation it accepts. Publish only proxy ports; API, console and PostgreSQL have private listeners/networks. Backend URLs and transport credentials never enter browser configuration.
- **Probes/shutdown:** API `/health` is liveness and bounded `/ready` has the reviewed database/lock/worker/draining meaning. Console `/ready` validates configuration and bounded upstream readiness without contacting OIDC. Compose uses these endpoints, restart delay/policy and grace exceeding the runtime's documented drain bound. API owner retains startup migration, singleton guard and queue shutdown ownership.
- **Adoption:** `POST /v1/auth/workspace-adoptions` accepts exact `{projectId, reason}` through a live operator session plus dedicated console transport. API owner implements transactional authorization/audit/idempotency; console owner supplies explicit review and result UI. A retry returns immutable history without restoring removed membership. The existing operator CLI stays a machine service client; no machine-token adoption shortcut or new CLI login flow.
- **Evaluator:** maintain a checkout/app example `npm run evaluate:app -- --config /absolute/private/evaluator.json --bundleID UUID --requestID UUID --adapter NAME [--live]`. Require versioned private config containing `serviceUrl`, `projectId`, `evaluatorPrincipalId`, `evaluatorToken`, and absolute `journalRoot`; no ambient/local-state defaults. Config is owner-only, canonical and bounded, with no symlink substitution. Scope uses the configured principal. Installed adapter allowlist, descriptor matching, explicit Luna-only live opt-in and runner recovery remain intact.
- **Evaluation UI:** default to copyable project/bundle/request IDs and public descriptor handoff. Descriptor equality alone never advertises a runnable checkout command. Optional example command uses an obvious private-config placeholder and is labeled setup-required; it contains no secret or inferred server filesystem path. Console never starts an evaluator. Journal service URL/principal/root are recovery identities: preserve them for old attempts rather than silently moving journals or replaying work.

## Integration order and review gates

1. Freeze the names/interfaces above and enumerate launcher/private-I/O importers. S1/S2 can prepare commands/manifests while auth, runtime, console and fixtures progress; S3 can implement explicit evaluator config without waiting for OIDC.
2. Merge reusable private I/O/config and caller replacements before retiring launcher modules. Wire package scripts once through S1. Merge runtime/console probes and preflight before qualifying either built entrypoint. Preserve all 141 behaviors / 183 variants; update identity/setup rather than deleting outcome assertions.
3. Qualify on isolated PostgreSQL and private test fixtures: missing/legacy config fails before listen; builds need no secrets; both built processes start; actual HTTPS/OIDC fixture login works; public setup URL differs safely from private upstream; evaluator never reads `.local`; old journal identity is preserved; operator CLI machine contracts remain valid. Prove API singleton/readiness/drain and full-stack persistence with the owning test lanes.
4. S6 updates active docs after behavior settles, then alone regenerates/checks the documentation site. S5 records exact executed evidence and every unrun gate separately. Static/image/Compose validation does not count as executed container qualification. Docker is unavailable: no daemon startup, public deployment, image publication or secret creation is implied.

## Cutover/operator inputs

The recipe requires an operator-selected persistent database/volume, verified backup, issuer/client, console/public-API origins, TLS certificate/key paths and separate private runtime credentials. Required placeholders fail when absent; never ship the old example database password. Use externally managed volume identity or an explicit restore target so a Compose project rename cannot silently select an empty database. Do not replace IDs, reset PostgreSQL, delete private old state, run `down --volumes`, infer ownership from machine grants, or turn the first login into a global owner.

Document coordinated stop, original-principal pending-write reconciliation, verified PostgreSQL backup, upgraded singleton startup/migration, readiness verification and routing. Old browser sessions are revoked once by 0013; content/history/memberships/machine identities survive. Memberless workspaces require the explicit audited adoption action. Preserve unresolved operation/evaluator metadata; an unobserved outcome is not proof of failure and a changed endpoint/principal/root is not automatic recovery. Rehearse backup/restore and upgrade on disposable data, never the running workspace database. External live-provider, real HTTPS, container and publication gates remain separately qualified operator actions.
