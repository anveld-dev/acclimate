# Independent scope review

Reviewed the combined plan, all five inputs, and the current evaluator, comparison DTOs, native preparation and command implementation. The direction is sound, but the following decisions must be settled before implementation ownership is assigned.

## Must fix

1. **Preserve a usable incomplete-draft workflow.** Section 1 requires native compatibility on every draft save and immutable snapshot creation. That turns a release/preparation invariant into an editor restriction: an interrupted metadata edit or an old incompatible snapshot cannot be saved for later repair. The audit asks that incompatible content cannot become a native release. Smallest alternative: generic validation still gates draft saves; selected-target diagnostics remain visible; native compatibility decisively gates publication/rollback and provider-produced candidates. Evaluation helpers also validate before native preparation. Demonstrate save → reload → repair → release with an initially broken manifest. If intentionally forbidding incomplete drafts, describe the recovery/editing flow and why that restriction is necessary.

2. **Cut mutable compatibility policy unless an actual retargeting workflow needs it.** A fixed target, a change-policy command, CAS revisions on multiple APIs, all-channel revalidation and proposal-worker revision fencing are a new policy subsystem. No audited operator needs to change a bundle's plugin after creation. Smallest alternative: immutable optional target on new bundles, existing bundles remain generic, shared TS/Rust preparation rules, release enforcement for native bundles. Adoption can copy/import reviewed content into a new targeted bundle. If preserving bundle identity during adoption is required, explicitly justify that user need and retain the mutable design; do not present both designs as interchangeable small details. Most native rules currently live in one shared helper; avoid suggesting four independent compatibility engines need consolidation.

3. **Remove service-verified canonical descriptor hashes.** `input-evaluation.md` duplicates already-frozen dataset/runtime/grader/inventory fields with several digests and a recursively canonicalized public object. Sorting keys and saying “ordinary JSON primitives” does not define portable number/string serialization, duplicate-key handling or Unicode ordering. The service cannot establish that the declared case/build hashes describe installed execution anyway. Smallest alternative: app-supplied configuration ID plus opaque revision, existing frozen fields and bounded declared limits; compare these structurally against the installed adapter before starting. Bind reports to request/attempt and repeat exact identity checks at finish. App-owned case/build digest strings may remain opaque identifiers. Only standardize a cross-language digest protocol if a concrete consumer requires independently computing it.

4. **Keep the payment simulator from becoming the improvement success criterion.** Editing `memory/retry-policy.json` changes an ordinary program's input; unchanged instructions/skills do not affect execution. Charge traces are meaningful for that fixture, but this does not show that the product improves an agent harness. Smallest alternative: use the simulator solely as a model-free orchestration regression, and adapt the existing `service-proposer` dataset/grader and `Model.review` seam to the same installed-adapter interface. The concrete user flow must select that adapter, request evaluation, run the copied helper, inspect per-case findings/rewards and deliberately release. An opt-in Luna run remains separately recorded; absence of that evidence leaves native improvement qualification open. Default CI need not call a model.

5. **Narrow recovery without removing its safety property.** Exact retry bytes, authorized receipt replay and a close fence are justified: `not_observed` cannot safely unlock a replacement command. However, the inputs expand this into a new prepare/submit/recover gateway, public raw-body SDK support, durable opt-in header and migration of virtually every console action. First implement the audited draft, proposal/evaluation-create and release/restore lanes using existing server actions plus one internal pending-record/transport helper. Keep credential reconciliation separate because secrets cannot replay. Document how marked versus legacy keys share locks before coding. Connection creation, discard, interruption, optional cross-session text retention and public SDK transport expansion should each need a demonstrated recovery gap. A lane must remain recoverable when text is forgotten; do not cut the fence merely to reduce files.

## Optional reductions and finish-line clarity

- Use session-only exact-body storage first; omit optional 24-hour local text retention. Keep metadata-only legacy reconciliation and close.
- Omit `retryOf`: a fresh explicit request already fixes reruns; informational lineage adds validation without closing an audited gap.
- Reconcile the inputs' helper names and author-token versus dedicated-evaluator-principal recommendations before ownership. A dedicated local principal with existing rights is sufficient; no new authorization model is needed.
- Replace “closes the current audit” with “fixes local failures and implements qualification tools.” A20/A22 remain blocked/not run without real provider/hosted evidence; A21 remains unpublished until consumers download actual release assets. Require separate local implementation and external qualification statuses, with retained artifact paths and dated commands as evidence.
