# Harness integrations

**Archived proposal — superseded by the smaller content service.** [Current overview](../../../../design/overview.md).
For example, a Codex worker could stream a turn back to Acclimate while asking the platform to approve a tool call. That integration is only a proposal: the native approval event alone does not prove that every request or external action is controlled.

Research snapshot, November 2026. These are integration candidates, not implemented or qualified adapters. The [production contract](../design/runtime/production.md) and [platform design](../design/runtime/execution.md) govern admission, ownership, evidence, and release; a harness session is not the authoritative run record.

## Claude Code and Agent SDK

The [Claude Agent SDK for Python](https://github.com/anthropics/claude-agent-sdk-python/blob/22b8eb9c19adfa78759b79e22bd664a57843bb06/README.md#L96-L115) drives the Claude Code agent loop. This is different from Anthropic's model API Python SDK: a model API call alone does not provide the coding agent's tools, session, or permission lifecycle. `ClaudeSDKClient` supports conversational interaction, Python hooks and custom tools exposed through an SDK MCP server. Hooks run in the application at lifecycle points; tool permissions also have a callback. An allowlist auto-approves entries rather than removing all other tools; explicit denial and permission configuration matter. [Source](https://github.com/anthropics/claude-agent-sdk-python/blob/22b8eb9c19adfa78759b79e22bd664a57843bb06/README.md#L51-L59), [hooks and custom tools](https://github.com/anthropics/claude-agent-sdk-python/blob/22b8eb9c19adfa78759b79e22bd664a57843bb06/README.md#L102-L127).

Sessions can resume, but prompt snapshot behavior matters: a first-request system prompt can persist across resume until compaction or a new session, unless snapshotting is disabled. [Source](https://github.com/anthropics/claude-agent-sdk-python/blob/22b8eb9c19adfa78759b79e22bd664a57843bb06/README.md#L80-L87). Resume is not proof that an external effect is safe to repeat.

**Proposal.** Run a version-pinned SDK sidecar per bounded worker, translating streamed messages, permission requests, hooks and terminal results into the platform protocol. Supply controlled MCP tools and route model access through an admitted gateway. Qualify whether every relevant model request and built-in tool can be mediated under the selected configuration; callbacks alone are not a security boundary. Test cancellation, resumed prompt identity, approval timeouts, crash recovery and uncertain external effects before enabling production work.

## Codex

The official [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk) describes TypeScript and Python integrations, threads, turns and streamed results. The [app-server protocol](https://learn.chatgpt.com/docs/app-server) offers a lower-level client boundary with thread and turn lifecycle, events, approvals and tool-related requests. Its schema distinguishes stable and experimental fields. The current app-server documentation marks WebSocket transport experimental and unsupported; do not generalize that statement to stdio. The local `codex-cli 0.169.0` help still labels `app-server` experimental. That check confirms the command and stdio option exist, not production qualification; pin the release and qualify the exact surface. The older MCP guide URL returned 404 during verification, so it is not a support-policy source here.

**Proposal.** Prefer a supervised app-server subprocess when the needed protocol is available; map thread/turn identifiers, streamed events, approval requests, interrupts and final state into the run journal. An SDK sidecar is an alternative where its surface suffices. Pin the binary and protocol version, and persist the mapping to the platform run and package. Verify the actual local integration and selected release for custom tools, approval scope, session resume and request interception: an approval event does not establish mediation of every model request or effect. Test restart, unknown outcomes, stale worker fencing, and whether restored sessions retain the intended configuration. No checkpoint should be treated as an exactly-once effect record.

## Pi

The checked-out snapshot was cloned as `badlogic/pi-mono`; the current project is [earendil-works/pi](https://github.com/earendil-works/pi). Its [TypeScript SDK](https://github.com/earendil-works/pi/blob/b4899f59ef0fba6507c2e619fd804dcde51920ba/packages/coding-agent/docs/sdk.md#L1-L28) embeds a session in Node or Bun. [RPC mode](https://github.com/earendil-works/pi/blob/b4899f59ef0fba6507c2e619fd804dcde51920ba/packages/coding-agent/docs/rpc.md#L1-L31) instead controls a subprocess using newline-delimited JSON commands, responses and events. Pi extensions run inside Pi and can register tools and intercept tool calls; an external RPC adapter is a separate component and does not automatically gain the extension's in-process interception. See the [extension documentation](https://github.com/earendil-works/pi/blob/b4899f59ef0fba6507c2e619fd804dcde51920ba/packages/coding-agent/docs/extensions.md).

**Proposal.** Supervise RPC from Rust and install a pinned, platform-owned extension for controlled tools and interception. Keep this gatekeeping extension and its configuration in the operator-owned adapter artifact, separate from the candidate-editable HarnessPackage. Bind both identities in the AgentVersion/runtime profile, and use a gateway for model admission. Qualify which calls interception covers, whether a caller can bypass it, extension UI approval behavior in headless mode, and the semantics of session files, cancellation and resumption. Treat session history as recovery input, not an authoritative checkpoint of external effects.

## Vercel fx

The [fx SDK](https://github.com/vercel-labs/fx/blob/afecbe3770edad6487d1558106d7c528e01d6d8f/sdk/README.md#L1-L5) exposes the Zig agent engine to JavaScript through a native Node addon and WebAssembly. Its agent, session and turn objects separate configuration, conversation and execution; sessions stream events, accept cancellation and can resume stored turns. [Source](https://github.com/vercel-labs/fx/blob/afecbe3770edad6487d1558106d7c528e01d6d8f/sdk/README.md#L32-L61). The project describes itself and its WebAssembly SDK as [experimental](https://github.com/vercel-labs/fx).

The SDK documents a significant recovery distinction: an interrupted tool marked idempotent may run again; otherwise it reports an uncertain outcome instead of automatically repeating it. [Source](https://github.com/vercel-labs/fx/blob/afecbe3770edad6487d1558106d7c528e01d6d8f/sdk/README.md#L189-L217). Its session ID is not authorization, and a checkpoint mismatch can still load with an event. [Source](https://github.com/vercel-labs/fx/blob/afecbe3770edad6487d1558106d7c528e01d6d8f/sdk/README.md#L109-L133).

**Proposal.** Start with a pinned JavaScript sidecar and explicitly supplied tools; assess a direct Zig boundary separately. Authenticate every session operation and make platform admission and effect reconciliation authoritative. Qualify native versus Wasm behavior, tool and approval hooks, model-request mediation, durable-store guarantees, mismatch handling and crash recovery. Reject incompatible checkpoints before native loading, even if upstream would load with a mismatch event. Map native tool execution IDs/retries onto host effects so two recovery engines cannot dispatch independently. An idempotency declaration must be backed by the actual effect implementation.

## Shared qualification

Each adapter needs a versioned capability description and conformance tests for lifecycle, streaming, policy admission, cancellation, approvals, checkpoint compatibility and ambiguous effects. Evaluations should pin adapter and harness versions, package, model configuration, environment, task and grader, and retain failed and incomplete trials. Reject unsupported requirements rather than silently bypassing them. These observations describe upstream surfaces; they do not establish that Acclimate can enforce them today.

**Verification scope.** Read pinned source and official docs; checked only local Codex version/help. No native sessions, model requests, installs, reference scripts, tests, or benchmarks ran.
