# Productization acceptance and release gates

**Earlier feature-slice gates; production cutover follows the [current evidence](../production-only/evidence.md).** These checks cover the Rust content service, TanStack console and an app-owned agent SDK. Verified identity is now mandatory; real-provider deployment remains separately qualified. The integration owner records the commit, commands, environment, results and known gaps for each claim. A fixture success is evidence about that fixture, not proof of a future feature.

Today [CI](../../../.github/workflows/ci.yaml) runs PostgreSQL tests and the model-free full-roadmap qualification. [The roadmap fixture](../../../scripts/full-roadmap/README.md) exercises a service proposal, app comparison and operator promotion; [the console browser check](../../../scripts/test_console_browser.py) now uses the real service, owned PostgreSQL and verified OIDC through test-owned TLS. [Delivery tests](../../../packages/sdk/tests/delivery/delivery.test.ts) cover verified caching and retries. These are useful baselines, but do not establish durable console drafts, hosted login, or real provider delivery.

The fixture owner publishes versioned inputs and expected IDs/digests in `contracts/fixtures/`; each owning stream consumes the shared DTOs and errors instead of inventing its own. Synthetic callbacks and fixture receipts make failures repeatable. They cannot establish actual browser persistence, transaction races, native discovery, provider behavior, or model quality. Keep optional Luna runs separately labeled with model, bounds and unknown costs; no paid call is a default gate. Existing native preparation tests are not a live Claude, Pi or Cursor claim.

## Migration and integration

The migration owner extends [the existing migrations](../../../migrations/0001_init.sql), preserving scoped bundle/version IDs, exact payloads, channel revisions, promotions and comparisons. In `tests/postgres.rs`, seed an old-schema database with multiple project IDs, history and grants, migrate, then verify backfilled projects and all old reads, denies and SDK resolution. Also migrate an empty database and reject conflicting configuration without partial results. Test scoped foreign keys and concurrent commands on real PostgreSQL. Take a restorable backup and rehearse recovery before deployment: after new writes, dropping new tables or running an old binary can lose data or violate its assumptions. Rollback means restore a backup or use an explicitly tested forward repair; do not promise a lossless down migration.

The coordinator freezes shared DTOs, errors, actor/scope and fixture contracts before parallel implementation. Streams may use deterministic seams independently; an integration gate opens only after its real dependencies land. First connect migration, service, SDK and console for the local draft/release slice. Then integrate the separate proposal workflow; delivery receipts have their own later opt-in gate. The same flows now require verified login, current membership and Rust-owned sessions. Owners fix failed gates in their own surfaces and the coordinator reruns affected integration checks. Update CI with the deterministic and PostgreSQL tests; run the actual browser check in an environment with a built console and installed browser, recording its result separately if CI cannot provide one.

For the first verified-user walkthrough, start from an explicitly labeled disposable workspace. Import initial content into an empty workspace, save a draft, restart and reopen it, then run the fixture evaluator against that exact snapshot and its published base. Inspect frozen declared settings, comparison IDs, missingness and costs. Publish the reviewed snapshot with its comparison, expected draft generation and channel revision. Confirm the draft history and release agree. Also save a newer generation after evaluation and prove that the older comparison cannot publish the new snapshot. Test manual publication with an explicit unevaluated reason separately.

Next request a bounded proposal from the published version. Confirm that the UI discloses the full bundle sent to the configured provider and obtains authorization; reject edits outside the allowed paths. If file-level disclosure is added later, test its filtering separately. Exercise an incomplete comparison and a valid reviewed release. Reject mismatched request settings, a wrong evaluator principal and start-after-interruption. Test that mutating caller options cannot relabel executed versions, and a mutating failed grader cannot change the output used by a retry. Show untrusted output references as text unless an authorized resolver is configured. Install the packed SDK in a clean fixture app, resolve and prepare the released version. Exercise a lost response across browser restart and cache expiry without duplicate mutations. Keep artifacts private and omit credentials and memory text. This walkthrough is not a quality study or proof that an agent used the content.

The later receipt gate explicitly enables reporting, verifies scoped credentials, expiry, deduplication, offline drops and evidence wording, then inspects the reported history. Its absence does not block the first local product gate. Python parity gates Python reporting support only.

Use **implemented** when the code and contract exist with relevant automated tests, naming remaining integration gaps. Use **locally checked** only after the real PostgreSQL and browser walkthrough passes on the stated commit, plus the clean SDK install/resolve/prepare check; say which provider checks were simulated. Use **hosted ready** only after hosted identity, scoped authorization and revocation, deployment configuration, migration/recovery rehearsal and the same end-to-end flow pass in the intended hosted environment. Record any native or Luna checks separately and never generalize one provider's result to another.

## Local qualification evidence — 2026-11-13

The shared working tree based on `ef73c27` passed `python3 scripts/productization/qualify.py --pg-bin /opt/homebrew/opt/postgresql@17/bin` on macOS with PostgreSQL 17, Rust service and Node. This is evidence for the working tree, not a committed release. The runner created its own empty PostgreSQL cluster and credentials, used ephemeral service/database ports, and removed them after completion. It did not read dotenv files or configure a model provider.

The real HTTP flow passed explicit example setup, second-project scope denial, two immutable draft generations and history, service restart/reopen identity, stale generation and channel revision rejection, exact parent/candidate app-owned deterministic evaluation, partial and infrastructure-failed comparisons, evaluator-principal mismatch rejection, interruption/start rejection, mismatched snapshot evidence rejection, and matching draft publication. A deliberately discarded save response was recovered using its durable operation ID after expiring the old response cache in the disposable database and restarting Rust; exact replay returned the same result, changed bytes conflicted, and another principal saw no result. Cache expiry was advanced by SQL, not by waiting 24 hours.

The same run built and packed `@acclimate/sdk`, installed its tarball into a clean external temporary consumer, resolved the actual reviewed channel, pinned the immutable version and prepared the verified content on disk. It made no receipt, integration, native-agent-discovery or model-quality claim. The associated [runner documentation](../../../scripts/productization/README.md) explains requirements and limitations. Real-browser evidence is recorded separately below when available; HTTP success alone does not confer the **locally checked** label.

**Local draft/review slice: locally checked.** After `npm run build --workspace @acclimate/console`, `python3 scripts/test_productization_browser.py --pg-bin /opt/homebrew/opt/postgresql@17/bin` passed against a second private PostgreSQL cluster and real Rust process with headless Chrome. It imported valid content into an empty workspace with explicit import confirmation, confirmed the unsaved-edit warning and kept editing, saved two generations, closed Chrome, restarted Rust, reopened the identical version ID/digest and history in a new browser, created the console's fixture evaluation request, ran the actual app-owned `examples/evaluate-request.ts` command, inspected the matching complete report, and published that draft through the console. Content, releases and setup pages had no horizontal overflow at 1440 and 390 pixels; no page errors or rendered bearer token were observed. The model-free evaluator checks declared content inventory, not model quality. This local evidence does not imply hosted readiness or native-provider support. The operation expiry/lost-response branch was checked by the HTTP runner; the browser run did not intercept a network response.

Both commands were rerun successfully after the service access fixes and a fresh production console build at 2026-11-14 04:22 UTC (2026-11-13 America/Chicago). The clean SDK consumer also passed again against the rebuilt package.

Later integration checks also passed all Rust tests against a fresh private PostgreSQL cluster, including a one-connection browser-read regression, crossed-admin updates, integration credential replay and scoped receipt checks. `scripts/productization/hosted_authority.py` passed operator bootstrap, dynamic project access, nonoperator denial, editor/viewer/removal behavior, session revocation and re-login after a revoked cookie. Machine SDK grants remained usable without browser sessions in hosted mode. This checks Rust authority only; no external OIDC provider was contacted.

The final browser run also rejected an invalid initial setup without leaving a stuck pending command, then completed a corrected import. SDK/console typechecking, production builds, model-free tests, Python packaging, Rust formatting/clippy and the generated docs checks passed. Local startup now stays empty on first use; example creation is explicit.
