## Material findings and design implications

1. **Coarse Add entry menu items are only 32px by source.** The generic coarse rule reaches buttons but not Radix div menuitems. Reuse the shared DropdownMenu item style to establish 44px coarse targets, and capture menu open with focus/hover rather than trusting closed-page scans. Draft actions already have a local 44px override.
2. **Connections phone heading visually collides with Refresh connections.** Actual `mobile390-connections.png` has the button across the right portion of the title. The metric pass missed sibling overlap. A shared phone heading/action row treatment must allow each to occupy honest space. Check long headings at 320px too.
3. **Package-rename errors escape their active modal.** Entry actions catches rename failure into page-level `message`; the message renders behind the modal overlay. The modal has no local error or field `aria-invalid`/error description. Keep invalid-package/path feedback beside the focused field, visible and announced, without relying on dismissing the modal to discover it. Native required/pattern handling in workspace creation is already present; lack of global `aria-invalid` use alone is not a blanket form failure.
4. **Programmatic Dialog focus return is missing by source and needs browser reproduction.** Members, connections create/revoke/secret, release restore and publish use controlled state without DialogTrigger or custom return-focus. Installed `node_modules/@radix-ui/react-dialog/dist/index.mjs:174` prevents the default focus fallback, then calls `context.triggerRef.current?.focus()`; without a trigger the call does nothing. Record invoking control and choose a persistent fallback after success; obtain browser proof for Cancel/Escape/outside and async replacement/removal. Account/entry/version/details are trigger-backed; pending guard and shell creation explicitly restore focus. Do not regress those working paths.
5. **AlertDialog horizontal bounds differ from Dialog.** Height is already fixed by shared CSS; absence in its primitive is not a bug. At 320px its default max-width is 320px without the Dialog gutter. Long translated/identity text and focus rings need real 320px/native200 open capture before approving a shared popup system.
6. **Published popup needs short-height failure-state proof.** Width is explicitly bounded in its consumer. Only available-height scrolling is missing; two ordinary actions may fit, but clipboard fallback adds lines. Retain full selectable source fallback and inspect the popup at native200. This is a bounded proof gap, not a claim of known clipping.
7. **Copy stale-status protection already exists.** Shared CopyButton resets on value change and compares current value after async completion, so stale feedback for switching selected entries is protected. WorkspaceDetails retains a separate ad-hoc copy handler; if scope changes while it is open, async completion has no generation guard. Unify later if this state is in scope; do not report the shared CopyButton as broken.
8. **Singleton workspace identity is visually truncated.** Navigation reviewer identified the actual singleton workspace link, with full visual reveal only in native `title`. Wrap the existing link so keyboard/touch users can inspect workspace scope; a new tooltip is unnecessary. This is distinct from the unused ShortId helper.

Peer agreement before boards: editor confirms 32px Add entry and off-modal package error; systems confirms retained disclosure state, cascade-aware modal bounds and controlled-dialog focus gap; navigation agrees to wrapping the actual workspace link and honest phone heading rows; release agrees to content-aware decision modal width/wrapping footer while retaining explicit labels and candidate/parent association; admin flags secret dismissal as a current product contract, not authorization for an invented acknowledgement sequence. Role/identity confirmation, last-admin and recovery warnings stay readable. Workspace ID syntax currently uses native pattern/title; a concise visible syntax hint helps users before validation without replacing native semantics.
