## Concrete changes worth making

1. **Single import expansion.** The draft footer wraps ImportContent in one Disclosure and ImportContent adds another. Compose the importer body beneath the footer's existing trigger. Keep its file/folder controls, read feedback, preview, atomic errors and explicit Add. One reusable application composition should own the trigger rather than page CSS hiding a second trigger.
2. **Local modal validation.** Package-rename exceptions currently set the outer workspace `message`, behind the open Entry actions overlay. Keep the error beside `skill-name`, associate it with the input and mark the invalid field. A compact error that cannot be seen while fixing its cause is not a successful density improvement. General invalid path/kind issues should similarly retain a clear repair path at Save; do not fabricate successful rename semantics.
3. **Coarse menu-item density belongs in the shared layer.** Add entry items explicitly use `min-h-8`, while shared DropdownMenuItem defaults `min-h-7`. The global coarse rule covers buttons but not these role=menuitem divs. Draft actions manually enforces 44px. Apply the same 44px coarse contract to shared menu items and verify all popup choices; shrinking menus can evade the current button-only measurement.
4. **Keep action scope and destructive meaning clear.** Draft-wide Save/review/evaluation stay above entry-local Actions. Entry/package removal can use the existing destructive treatment and clearly indicate package scope without adding an unsolicited confirmation. Saved-draft discard needs actual target/status evidence and a deliberate interaction review, because clean discard currently has no guard. Removing the final entry can also unmount the Dialog; capture focus recovery before claiming a polished action flow.
5. **Describe actual search behavior.** Draft search is live file-path filtering; published search submits paths or text. Use honest labels, retain Clear filters and explain a selected file outside filtered results. This is an existing usability gap, not a mandate to introduce global/semantic search.
6. **Use shared form/status/popup grammar.** Reuse shadcn Button/Input/NativeSelect, Collapsible-based Disclosure, Dialog, Popover and DropdownMenu by behavior. Keep local validation, pending summary/details and destructive presentation cohesive. Do not force Content Copy/Download buttons, editable modal fields and menu items into one universal Actions primitive.

No application code/build/test changes are part of this review file.

## Final implementation verdict

**No material editor objection to the implemented change.** Inspected final actual standard-2 PNGs for desktop draft, phone Add entry keyboard menu, invalid package rename, expanded import, history/details, published Actions keyboard popup and dirty-navigation confirmation. Also reopened the same-fixture core desktop draft and edge exact-generation-2 review. The core geometry remains **1006px source width at y156**; the different skill-selected state naturally has an additional full-path line rather than hiding identity to match a basename-only height.

The final Add menu is 192px wide including padding, and its three coarse-pointer items each measure 44px high. All labels fit without the baseline's artificial two-line wrapping. Invalid package rename now shows the actual validation error inside Entry actions, beside the field with `aria-invalid` and `aria-describedby="skill-package-error"`; changing the field clears the stale local error. The current source still uses a native select rather than copying the generated custom option menus.

Import is one expansion with its original folder/files controls and limits. History/details retain full generation/snapshot/base identities and normal wrapping. This removes duplicate nesting without merging import application with durable Save. Draft Save, selected Entry actions and exact saved-generation evaluation retain their separate scope. Published Copy/Download remains a bounded popup with focused first action and Escape return. Dirty navigation visibly presents Keep editing before Leave editor, and the reported check confirms browser text remains after cancel/Escape.

Inspected the valid `artifacts/layout5-states-final-native-2` published popup at physical 1280px/DPR2 and the short evidenced decision view. Its JSON verifies the 640px CSS viewport and the short 640×328 context, internal scrolling to reachable facts/actions, gutters and focus return. **Do not use final-native-1 cropped images as proof.** The phone manual decision also keeps full parent/candidate/generation/reason visible and stacks Back/Publish without an invented tooltip dependency. These share the same control/focus/status family as editor utilities while keeping contextual surface sizes.
