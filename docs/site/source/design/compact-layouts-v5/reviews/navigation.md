## Material opportunities

1. **Shared mobile page-heading allocation.** Actual `mobile390-library.png` puts Menu, heading copy and New bundle on one row: the description is squeezed into roughly 140px and five lines while both sides hold controls. Direct follow-up inspection of `mobile390-connections.png` confirms the longer title also extends into Refresh connections. A compact title/action arrangement with honest rows and description across available width would remove overlap and accidental height without shrinking text/targets. Solve through shared `PageTitle`/heading CSS so admin/library pages agree; prove 320px long titles and preserve detail/editor geometry separately.
2. **Long workspace identity needs an intentional accessible treatment.** Actual narrow sidebar and mobile sheet truncate the single-workspace name; multiple-workspace select also clips. Single workspace has only native `title` for full visual reveal, which cannot be relied on for keyboard/touch. Prefer wrapping the existing single-workspace text or a focusable, touch-accessible details surface if needed. Native select remains legitimate; do not replace platform options merely for visual uniformity. Confirm full names in actual switcher-open captures before changing it.
3. **State-proof gap.** Existing actual screens do not yet substantiate most entry dialogs/recovery paths. Final review needs account details open + clipboard failure, workspace create open/pending/error, adoption review/confirmed/pending/outcome, library empty/no-match/read-only, bundle create all four sources/settings/previews, unresolved creation open with and without retained body. This is verification coverage, not a claim these states are broken.

## Optional polish and cohesion limits

- Native select options, standard button hover/focus, checked radio/checkbox, Dialog close and Disclosure chevrons already provide interaction signals. Keep a single shared system of radius/borders/spacing/focus rather than importing a second sidebar/menu pattern.
- Account's up-chevron visually suggests a menu although it opens a Dialog. This is optional icon polish; label and behavior are clear.
- Library row hover covers the whole row while its central blank area is not clickable. Optional: reduce hover treatment or add focus-within equivalence; do not make a row link wrap multiple channel links.
- Keep one primary publish action, readable immutable-target/immediate-publication summary, and explicit recovery controls. Denser form spacing is useful only when labels/help/errors stay associated and 44px coarse targets remain.
- Do not add tooltips to already labelled navigation, Refresh, Account or channel buttons. Full identity/path reveal is a specific need, not a reason for generic hover-only help.
