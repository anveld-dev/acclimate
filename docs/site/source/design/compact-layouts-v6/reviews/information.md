## Desktop composition brief after clarification

The user explicitly wants desktop layout alternatives. The earlier narrow-evidence brief below is retained as preclarification audit evidence; its restrained implementation recommendation does not decide the desktop direction. Assess all six replacement images on the same dirty draft, then test one composition across Content, Changes, Releases, App setup, library and admin. Mobile remains a regression constraint.

The desktop hierarchy has five real scopes: workspace/account and its destinations; bundle/channel and its views; whole-draft state/actions; selected file and its actions; secondary details/recovery. A good alternative should make their relationships faster to understand and give source space back where possible. It need not keep each scope in its current physical region. It must preserve their identities and behavior.

| --- | --- | --- |

Icon-only labels need hover and focus tooltips plus durable expansion/navigation naming. |
| Bundle/channel/view hierarchy | Back-to-library, bundle identity, channel and Content/Changes/Releases/App setup read as one scope | Long scope must not collide with routes or actions at 1024. A new physical grouping can be useful without inventing routes or making channel silently global. |

Review changes is whole-draft; entry rename/remove stays selected-file scope. Save remains available while working. |
| File navigation | Search/filter and selected file remain findable with less duplicated rail width or metadata | Current persistent 216px file rail may compete with global rail at 1024. Any collapse, finder or revised width needs closed/open, long-path, empty-result, filtering and resize-focus proof. Do not hide names solely behind hover. |

| Secondary utilities and overlays | Import/history/details remain available with less competition for attention | Menus/disclosures/dialogs need closed and open states, retained values, hover/focus/disabled cues, bounded long content and return focus. | Whole-product transfer | Library and sparse admin retain concise purpose/actions; releases and setup retain readable sequence and scope | A dirty-draft board earns a composition donor, not proof of every page. Shared existing shell, navigation, Button/Menu/Dialog/Disclosure primitives should implement the grammar without inventing backend features or forcing editor chrome onto forms. |

The final ranking will compare observed alternatives, not award novelty or assume the current desktop must win. A proposal can materially relocate global/navigation/action regions while preserving semantic scope and the existing library.
