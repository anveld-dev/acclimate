Initial audit: Create already has useful bounded form density and four real source modes. Its heading/form alignment and repeated nested preview/settings boxes deserve challenge. Changes stacks broad task/draft/suggestion bands; Suggest a change spans too wide for prose, editable paths and consent. A bounded task surface and clearer source → scope → inputs → disclosure/authorization → action hierarchy could earn improvement without an artificial wizard or permanent helper column.

I read current `BundleLibrary`, `BundleChanges`, `ImprovementWorkspace` and shared Mira styles. Actual prior creation/import-preview captures are presentation references, not fresh runtime qualification; Changes' older native-zoom capture is likewise a baseline with older navigation. Current source establishes four creation modes, independent draft/suggestion lists, full-parent provider disclosure and explicit authorization.

After viewing all six v11 images and debating all five peers, I recommend bounded refinements rather than a generated screen:

- **A/B:** A's 1024px Changes index and aligned full metadata earn a shorter scan. Keep actual separate sections, identities, states, links, refresh and pagination. B splits channel-scoped drafts and all-channel suggestions into competing queues, constrains long IDs and invents titles/statuses. No tablelike fixed row geometry is justified.
- **C/D:** C's 768px proposal surface improves prose and authorization line length. Include pending/error/recovery notices in the same cap; Check result remains immediately available. Preserve hypothesis → editable paths → evidence → whole-parent disclosure/consent → request. D's skinny path rail separates a required selection from this sequence and invents counters/configuration/progress. Long paths need wrapping text, a nonshrinking top-aligned checkbox and retained label targets.
- **E/F:** Defend the current bounded library and dedicated inline creation form. E duplicates creation in a sidecar; F adds cards and stacked modals while inventing fields/channel behavior. Neither improves real source selection, import preview/confirmation or the immediate-publication decision.

Caps apply only to the index and entire proposal route, preserving accepted editor/review widths. No broader geometry or further generated round earns adoption.
