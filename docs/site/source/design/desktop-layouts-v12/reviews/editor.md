# Frequent-task workbench review

Read shell/navigation, bundle scope/channel, draft and evaluation handoff source; inspected actual v11 dirty editor, coarse navigation, entry/import dialogs, requested handoff and publication confirmation. The baseline already separates global scope, bundle/channel, whole-draft saved/dirty actions and file-local editing. Frequent file selection stays visible. A replacement must improve source room and orientation together, including hidden/reflow states.

## Independent ranking — saved before discussion

Viewed all six actual sheets. **Baseline > A > E > B > C > D > F** for frequent tasks. This order was recorded before peer debate; image callouts are not measurements.

- **Baseline:** strongest known scope, finder, Save and saved-generation handoff; width belongs to work.
- **A:** preserves that model; hiding rare New workspace may quiet chrome, but a new chooser adds work without demonstrated frequent-task benefit.
- **E:** promising source-height experiment, yet long exact identities/tabs force fallback and global destinations become menu actions.
- **B:** narrow global rail may trade width for one band; recognition/focus/reflow costs remain unproven.
- **C:** clear labelled orientation, but a global rail plus file rail spends substantial width on rare destinations.
- **D:** combined rail removes duplicate structure but puts file finding below scope/navigation and competes for vertical room.
- **F:** repeated finder reopening/source occlusion costs more than largely unused extra line width earns.

Reject every generated entry/admin capability fiction, regardless of geometry: duplicate/move/revert-entry commands, new settings, runners and changed publication semantics are not product facts.

## Debate and actual experiment

Debated all five peers; ranks differed. Library preferred D and visual preferred C. I accepted the strongest D challenge: its 256px rail replaces the 216px file rail, so nominal width cost is only about 40px. That deserved a reversible prototype, not automatic rejection or literal adoption. C provided a labelled-navigation control.

Personally inspected matched baseline/C/D source at 1440×700/900, D coarse 1024, expanded review diff, corrected D workspace-tooltip sensitivity, native 200% inline Files, narrow baseline/C, and real Import dialog. Read the [main report](../../../../artifacts/desktop12-experiment/accepted/summary.json), [corrected supplement](../../../../artifacts/desktop12-experiment/final-supplement/summary.json), and [narrow contract](../../../../artifacts/desktop12-experiment/narrow-contract/summary.json).

D earns earlier/larger source, but this implementation does not earn its file-finding cost. With the existing one-line workspace tooltip preserved, the 900px case has **160px** for Files against **273px** needed for controls and three rows. At 700px the Files region has no height and native search/type clicks fail. This is not merely the original over-wrapped workspace artifact. C keeps file finding but narrows ordinary source **1182→1002px**, and coarse source **774→594px**; clearer global labels do not repay that cost for repeated editing.

The corrected menu/utility checks pass for all three. Narrow/native layouts preserve inline Files outside the global sheet and selection focus return. Review evidence/diff remain intact. Shared locator errors and invalid original fixed-rail clip calculations are harness defects, not product regressions; conclusions above use corrected budget/native behavior and actual pixels.

## Final judgment — retain baseline

The tested C/D shells do not beat the current frequent-task workbench. Retain production layout; no further image round is needed to make this decision. This rejects these implementations, not every possible sidebar design. The experiment used injected styles/helper on the frozen real app; it is not shipping qualification. Production files, build hash and persisted state remain unchanged. No tests/app edits by this reviewer, no provider/model calls, and no claim of exhaustive recovery or accessibility qualification.
