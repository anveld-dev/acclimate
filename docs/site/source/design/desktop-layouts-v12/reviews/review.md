# Workflow integrity: holistic desktop

Independent ranking, saved before peer debate: **actual baseline, A, C, B, E, F, D**. I inspected all six actual concept images and current draft, published content and saved-review screenshots, plus shell, route scope, dirty-navigation and related-pending source. The concept insets are not measured runtime proof.

The baseline already separates workspace navigation, bundle/channel/views, whole-draft saved/unsaved state, and selected-file actions. Its dirty evaluation action names the saved generation, and saved review preserves evidence provenance and deliberate target confirmation. A keeps these relationships and is the closest alternative, but a custom workspace chooser and tooltip-truncated identity do not yet earn replacing the current native selection/reflow. C’s labelled global sidebar is clearer than B’s compact rail, but both spend persistent width on infrequent navigation and compete with file, diff and paired-evidence width across the product. Any source-height advantage requires actual matched runtime measurement.

E’s single command bar overloads a row with global and bundle scope while hiding workspace destinations. F keeps global scope but makes frequent file navigation an extra open/search/select/close interaction. D mixes workspace, bundle, channel, views, files and global destinations in one rail; missing the existing back-to-changes relationship and changing rail contents on review adds orientation cost. None currently demonstrates better pending/recovery or evidence handling.

Reject invented duplicate/move/revert/admin commands, changed native identity behavior, and generic discard wording that obscures saved drafts. Retain explicit browser-versus-saved-generation distinctions, app-reported evidence, full target facts in decision dialogs, visible pending Check result before affected actions, exact retry/close semantics, source channel/revision and provider disclosure/consent. No navigation redesign may silently discard browser edits, imply saved content is evaluated live, or treat unknown writes as failed.

Peer debate exposed a real disagreement: library ranked D first, while editor, interaction, skeptic and I initially preferred the baseline. The library argument changed my view of D’s experiment value: its unified rail replaces the existing file navigator rather than adding C’s extra column. At ordinary desktop width, review could retain nearly the existing 1200px evidence area. Width alone does not reject D. Its remaining costs are files pushed below parent navigation, competing file/global scrolling, missing Back to changes, changing rail contents between editor and review, and focus ownership when the narrow navigation changes.

I support an isolated actual D geometry experiment if it keeps labelled scopes, real controls and return paths, then demonstrates long identities/many files, full incomplete comparison and per-arm output, expanded diff/decision dialog, pending notices and narrow/zoom behavior. No adoption is earned by the generated source-height inset. E also merits only a measured experiment: with long scope its single row likely becomes the existing two rows. Current baseline remains my preferred implementation pending actual proof; the original independent ranking stays recorded.

The main actual experiment resolves part of the disagreement. D’s [loaded incomplete comparison](../../../../artifacts/desktop12-experiment/accepted/d-1440x900-review-incomplete-evidence.png) and [expanded full diff](../../../../artifacts/desktop12-experiment/accepted/d-1440x900-review-expanded-full-diff.png) preserve evidence identity, failed/missing arms, real zero, unknown cost, release prerequisite and full-width change inspection. The near-baseline evidence-width argument was correct. Its editor tradeoff is worse: in the actual long-scope [900px-high view](../../../../artifacts/desktop12-experiment/accepted/d-1440x900-source-initial.png), the Files region has only 108px for 273px of heading/search/type and three rows; at [700px height](../../../../artifacts/desktop12-experiment/accepted/d-1440x700-source-initial.png) and coarse 1024px it disappears. C preserves paired review but reduces source width from 1182px to 1002px at 1440px for only 7px additional height. D’s 9.3% source-area gain at 1440×900 does not offset inaccessible frequent file work.

**Final verdict: retain the actual baseline.** The [existing-tooltip identity sensitivity at 900px](../../../../artifacts/desktop12-experiment/final-supplement/d-1440x900-workspace-name-sensitivity-initial.png) gives D 160px instead of 108px, still below the 273px control/three-row budget and with no fully visible file row. At [700px](../../../../artifacts/desktop12-experiment/final-supplement/d-1440x700-workspace-name-sensitivity-initial.png), file search/type controls remain unreachable by native clicks. This is a concrete allocation failure in the tested D layout, not proof that every unified rail is impossible. Fixing it would require another layout decision; no further iteration is necessary to retain the working baseline this round.

Corrected menu/import/history/details checks pass in the three 900px layouts. The separate [narrow contract record](../../../../artifacts/desktop12-experiment/narrow-contract/summary.json) passes all six baseline/C/D 390px and actual Chrome 200% checks: file selection stays inline, outside the global sheet, and returns focus. Earlier identical locator-evaluation errors, narrow wrong-title checks, shared TypeErrors and simplistic fixed-ancestor clipping measurements are superseded harness artifacts, not product regressions.
