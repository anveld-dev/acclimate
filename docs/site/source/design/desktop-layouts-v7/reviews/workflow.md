Reviewed the v6 README and interaction inventory, all actual v6 screen PNGs, the long-name 1024px capture, and `draft-workspace`, `bundle-changes`, `import-content`, and `version-inspector`. Inspected all six actual v7 concepts.

**Concept order: C, A, B, E, F, D.** Borrow C/A’s allocation, with A’s honest title wrapping. Both preserve the existing whole-draft command band above selected-file actions. B gives the channel a large share before necessary. E’s wrapped selection is attractive but does not earn replacing a native control. F moves saved/unsaved status and Save below source and expandable utilities. D starts source earlier but puts frequent file picking beneath bundle scope and navigation.

The existing task order is sound: choose a bundle/channel, select an entry, edit browser content, review the whole draft, save, then evaluate the explicitly identified saved generation. Entry rename/type/remove and imported files change browser content; Save applies the complete draft. Copy/download in the version inspector apply only to the selected saved file. Preserve those scopes.

Import, history and details earn their collapsed states: they remove infrequent material while leaving editing, Save and the next step visible. Expanded imports must retain preview, local-application wording, validation and failure feedback. History/details can grow in document flow. They do not justify another panel or focus mode. File switching preserves other browser edits; leaving/reloading uses the unsaved guard. Unknown submissions retain editable browser content while blocking another Save; visible reconciliation and exact-request recovery must remain separate from ordinary details. Read-only, stale-base, missing-version, empty/filter and retry states remain necessary.
