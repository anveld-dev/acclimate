# Setup and administration with clearer task layouts

[Six generated alternatives](comparison.html) · [Actual screens](screens.html) · [Prompts](prompts.json) · [State coverage](states.md)

Six reviewers challenged the remaining setup and administration pages. They could reject every concept and request more rounds. The actual result combines useful geometry from A, C and F; it does not copy a generated screen or its fictional controls.

## What changed

**App setup:** a 64rem sequential guide, with install copy beside its actual command and a responsive mapping of the five required variables. TypeScript/Python recipes and independent disclosures remain. Copy recipe still means the full recipe, not the displayed invocation.

**Connections:** when a connection is selected by its existing URL, wide desktops show a 280px directory beside the real credential and delivery task. The working area grows to 1440px; below 1200px it stacks in normal document flow. The unselected directory stays bounded at 64rem. No auto-selection, empty inspector, sticky pane or nested directory scroller was added.

**Members:** a 64rem working area puts role beside the actual subject, with the full issuer beneath. Existing identity lookup, confirmation checkbox, role/remove flow and final-admin guard remain.

The current shadcn Mira primitives provide the controls. These are layout and hierarchy changes, with no new dependency, endpoint, credential behavior or permission model.

## What we rejected

The setup reference column duplicated prerequisites and variables. The ledger left selected credential work after every directory row. A separate member-role column added scan distance. Generated access switches, masked persistent tokens, dates, verified badges and replacement dialogs were not implementation facts and were excluded.

The selected Connections rail earned its space because there is real credential, recovery and receipt work beside it. That differs from the earlier library preview idea, which only repeated existing facts.

All six accepted the actual implementation after inspecting rich, narrow and zoomed states: [product](reviews/library.md), [setup journey](reviews/editor.md), [credential/identity contracts](reviews/review.md), [interaction](reviews/interaction.md), [visual system](reviews/visual.md), [skeptic](reviews/skeptic.md). No material objection or request for another round remains.
