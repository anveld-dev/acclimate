# File-tree interaction review

Initial contract: retain the current shell and named narrow Files picker while introducing a real hierarchical file navigator. A tree adds keyboard and state obligations; visual indentation alone is insufficient.

Use one visible roving tab stop. Up/Down traverse visible nodes; Right opens a folder or enters its first child; Left closes or returns to its parent; Home/End and name-based typeahead move focus. Focus must remain distinct from the selected file. Parent nodes expose `aria-expanded` and own their child group; leaves do not expose expansion. The tree has an accessible label. [W3C Tree View Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/).

Published leaves retain real links and their exact destination, including normal modified/new-tab behavior. The current page remains identifiable; draft leaves retain explicit selection. Plain arrows/typeahead must not activate a file or trigger a dirty-navigation guard. Enter/Space perform the chosen node’s action. Keeping focus in the tree after content changes is an established navigation-tree option; it fits frequent file comparison here, subject to the existing narrow picker’s committed-selection return. [W3C Navigation Treeview Example](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/examples/treeview-navigation/).

Material implementation boundaries: folder toggles never count as file intent or close narrow Files. Space activation must preserve the actual control/click path needed by FileNavigator. Temporary filter expansion must restore saved folds and not make visible folder controls inert. Selection, creation and rename reveal ancestors once; they do not repeatedly reopen a manually collapsed branch or steal focus from editor, search, menus or dialogs.

Draft browser edits can contain duplicate/empty paths or a file whose name also forms a directory prefix. Keys and IDs must distinguish those entries rather than merge, drop or select the wrong one. Typeahead should follow displayed names, with full accessible paths available to disambiguate duplicate basenames. Deep visual indentation must leave readable label space while semantic depth remains truthful. Empty/no-match counts describe files, not folder rows. Collapsing or filtering a focused descendant needs a visible in-tree fallback only when focus was actually inside the tree.
