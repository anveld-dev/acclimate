# File tree workflow integrity

Published integration replaces only the flat list with the shared `FileTree`. Items use exact paths as IDs, selected path stays separate from filters, and expansion scope is actor/workspace/bundle/channel rather than current query or selection. Navigation still uses the existing `link({ path })`, preserving submitted query, kind, exact path and real `ConsoleLink` dirty guards. Search submission, filter clearing, no-match/missing-selection copy, published header, draft creation and download remain unchanged. The narrow FileNavigator must observe `data-file-path` and close/return focus only after selection commits.

Review constraints: folder disclosure is browser navigation state, never a content mutation or inferred permission boundary. Filtered results must expose matching descendants without pretending collapsed contents are absent. Selected content and exact full path remain understandable when a parent collapses. Directory/file prefix collisions, duplicate leaf names and long paths must remain independently addressable; no path normalization may change the stored string or URL. Draft tree item identity must remain stable through browser rename/edit operations while published items use immutable exact paths.
