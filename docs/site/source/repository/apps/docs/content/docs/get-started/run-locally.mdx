---
title: Run Acclimate locally
description: Start a laptop evaluation stack with PostgreSQL, Keycloak sign-in, and local HTTPS.
---

The local stack is for evaluation and development. It runs the Acclimate API and console, PostgreSQL 16, Keycloak, Mailpit, and Caddy on one laptop. The console uses the same HTTPS OIDC sign-in as a production deployment.

## Start the stack

From an Acclimate checkout on macOS or Linux, have Docker running with Docker Compose v2.24 or later, plus Node.js with npm and Python 3.9 or later. Run:

```sh
npm run local:up
```

The first run builds the images and provisions a verified Keycloak operator in the Acclimate realm. The command prints the login, URLs, and configuration paths. It prints the initial password on the first successful run. Starting again reuses the databases, operator, and generated credentials. Keep `.local/stack/` private. The initial password is stored in the `operator` field of `.local/stack/credentials.json`.

| Endpoint | URL |
| --- | --- |
| Console | [https://localhost:3443](https://localhost:3443) |
| API | [https://127.0.0.1:3444](https://127.0.0.1:3444) |
| Keycloak issuer | `https://127.0.0.1:3445/realms/acclimate` |
| Mailpit inbox | [http://localhost:8025](http://localhost:8025) |

All published ports bind to loopback. Caddy serves HTTPS with its internal CA. The console and service share Caddy's network namespace, so the issuer URL resolves to the same TLS listener from Docker and from the browser. Invitations, email verification links, and password resets arrive in Mailpit.

## Trust the local certificate

Import `.local/stack/root.crt` as a trusted certificate authority in your browser or OS trust store. On macOS, import it into your login keychain in Keychain Access and set **Secure Sockets Layer (SSL)** to **Always Trust** for that certificate. On Linux, use your browser's certificate authority manager or your distribution's system trust store. Where your browser offers certificate exceptions, you can instead accept one for the console and one for the Keycloak sign-in URL.

For SDKs and curl, you can trust the CA for just the process that needs it. Run these from the checkout:

```sh
export NODE_EXTRA_CA_CERTS="$PWD/.local/stack/root.crt"  # Node.js SDK
export SSL_CERT_FILE="$PWD/.local/stack/root.crt"       # Python SDK
curl --cacert "$PWD/.local/stack/root.crt" https://127.0.0.1:3444/ready
```

Set the variables before launching the SDK. For a Python evaluator that also calls an external model provider, append the local root to a copy of your normal CA bundle and point `SSL_CERT_FILE` at that combined file.

## Open the demo workspace

Sign in to the console with the printed Keycloak login. Open **Adopt an existing workspace** below the workspace creation form. Enter `local-demo` and a reason, review the adoption, then confirm it. The service provisions this workspace for the local machine grant. Adoption gives your signed-in operator administrator membership and records your reason.

Use the printed path to `.local/stack/evaluator.json` as `EVALUATOR_CONFIG` in the [comparison quickstart](/docs/get-started/quickstart). It grants read and write access to `local-demo`. Start by publishing a bundle to that workspace. The stack starts without a model provider.

## Stop or reset

```sh
npm run local:down
npm run local:reset
```

`local:down` stops the stack and keeps its volumes and local configuration. `local:reset` asks you to type `reset` before deleting this checkout's stack volumes and `.local/stack/`, including its evaluator journal. It also deletes the local CA. Remove the old CA from your trust store if you imported it, and trust the new root after starting again.

Each checkout has its own Compose project and volumes. The ports are fixed, so stop any other local stack or standalone Mailpit before starting.
