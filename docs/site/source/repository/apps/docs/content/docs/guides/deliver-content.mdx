This guide is for a developer whose application runs an agent. It shows how to prepare the released version of a bundle for each job, record it with the result and clean up. A job keeps the version it prepared even if a release lands while it runs. See [Delivery](/docs/concepts/how-it-works#delivery).

## Before you start

- Install the SDK. See [Install the SDKs](/docs/get-started/install).
- Create a connection for the bundle and channel, and issue its connection credential. See [Connect your application](/docs/get-started/quickstart#connect-your-application) and [Credentials and rights](/docs/concepts/credentials).
- In the console, open **App setup** on the bundle's channel. It shows the API URL, the workspace, bundle and channel and a recipe to copy.

The snippets read `ACCLIMATE_URL`, `ACCLIMATE_TOKEN` (the connection credential), `ACCLIMATE_SCOPE` (a stable name for your application) and `ACCLIMATE_CONNECTION` (the connection ID). See [Application](/docs/reference/configuration#application) in the environment variables.

## Prepare a job

Call `prepare` once for each new job and give your agent the prepared instructions and skill files. Save the version ID and digest with the result, so you can tell later which version produced it.

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

```ts
import { AcclimateClient } from '@acclimate/sdk';

const { ACCLIMATE_URL, ACCLIMATE_TOKEN, ACCLIMATE_SCOPE, ACCLIMATE_CONNECTION } = process.env;
if (!ACCLIMATE_URL || !ACCLIMATE_TOKEN || !ACCLIMATE_SCOPE || !ACCLIMATE_CONNECTION) {
  throw new Error('Set ACCLIMATE_URL, ACCLIMATE_TOKEN, ACCLIMATE_SCOPE and ACCLIMATE_CONNECTION');
}
const client = new AcclimateClient({
  baseUrl: ACCLIMATE_URL,
  token: ACCLIMATE_TOKEN,
  scope: ACCLIMATE_SCOPE,
  connectionId: ACCLIMATE_CONNECTION,
});

const prepared = await client.prepare({ workspaceId, bundleId, channel: 'stable' });
try {
  const result = await runAgent(jobInput, {
    instructions: prepared.instructions,
    skillFiles: prepared.skillFiles,
  });
  const { id: versionId, digest } = prepared.version.version;
  await saveJobResult(result, { versionId, digest });
} finally {
  await prepared.cleanup();
}
```

</Tab>

```python
import os
from acclimate import AcclimateClient

client = AcclimateClient(
    os.environ["ACCLIMATE_URL"],
    os.environ["ACCLIMATE_TOKEN"],
    os.environ["ACCLIMATE_SCOPE"],
    connection_id=os.environ["ACCLIMATE_CONNECTION"],

with client.prepare(workspace_id, bundle_id, channel="stable") as prepared:
    result = run_agent(job_input, instructions=prepared.instructions, skill_files=prepared.skill_files)
    version = prepared.version["version"]
    save_job_result(result, version_id=version["id"], digest=version["digest"])
```

The IDs, the job input, the agent call and the result storage are your application's. The prepared job has:

| Property | Contents |
| --- | --- |
| `instructions` | The instruction files joined into one string |
| `skillFiles` (`skill_files` in Python) | The staged skill files, each with `path`, `kind` and `absolutePath` |
| `files` | Every staged file, including memory files. Your application chooses which memory the agent gets. |
| `version` | The verified version, with its ID and digest in `version.version` (`version["version"]` in Python) |
| `directory` | The private job directory |

Clean up only after the job has stopped and its result is saved. For a job that finishes inside the call, use `try` and `finally` as above, or the Python `with` block. For background work, keep the prepared object and call `cleanup()` when the job stops.

To run an exact version instead of the channel's current one, pass `versionId` (`version_id` in Python) in place of `channel`.

To have the SDK find the bundle by name and report production outcomes, use `createAcclimate().job()` (`Acclimate.from_env().job()` in Python) instead. See Jobs in the [TypeScript SDK](/docs/reference/typescript-sdk#jobs) and [Python SDK](/docs/reference/python-sdk#jobs) references, and [Support agent](/docs/examples/support-agent) for an application built on it.

## Report job starts

A start receipt records which version a job used, so the workspace can see what each application ran. Reporting is optional, and a failed report never blocks delivery.

1. Give the application a separate receipt credential in `ACCLIMATE_RECEIPT_TOKEN`.
2. Build a reporter with its own client and pass it to `prepare` as `reporter`.
3. At the job's real start event, call `reportStarted()` and keep the returned receipt with the job ID. It returns `null` (`None` in Python) when reporting is unavailable.
4. When the job ends, let the reporter send what it has queued and close it.

<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">

```ts
import { AcclimateClient, createReceiptReporter } from '@acclimate/sdk';

const reporter = createReceiptReporter({
  workspaceId,
  connectionId: ACCLIMATE_CONNECTION,
  client: new AcclimateClient({
    baseUrl: ACCLIMATE_URL,
    token: receiptToken, // from ACCLIMATE_RECEIPT_TOKEN
    scope: ACCLIMATE_SCOPE + ':receipts',
    timeoutMs: 1000, // a short deadline and no retries, so reporting cannot delay the job
    retries: 0,
  }),
});

const prepared = await client.prepare({ workspaceId, bundleId, channel: 'stable', reporter });
const receipt = prepared.reportStarted(); // at the job's real start event

// Run the job and clean up as in "Prepare a job". When the job ends:
await reporter.flush();
reporter.close();
```

</Tab>
<Tab value="Python">

```python
import os
from acclimate import AcclimateClient, DeliveryReporter

receipt_client = AcclimateClient(
    os.environ["ACCLIMATE_URL"],
    os.environ["ACCLIMATE_RECEIPT_TOKEN"],
    os.environ["ACCLIMATE_SCOPE"] + ":receipts",
    timeout=1,  # a short deadline and no retries, so reporting cannot delay the job
    retries=0,
)
reporter = DeliveryReporter(receipt_client, workspace_id, os.environ["ACCLIMATE_CONNECTION"])

with client.prepare(workspace_id, bundle_id, channel="stable", reporter=reporter) as prepared:
    receipt = prepared.report_started()  # at the job's real start event
    ...  # run the job as in "Prepare a job"

# When the job ends:
reporter.wait(1.0)
reporter.close(0.1)
```

## Choose a native integration

A plugin stages a version in the layout its agent SDK reads.

| Agent SDK | Prepared layout |
| --- | --- |
| [Codex](/docs/integrations/codex) | `AGENTS.md` and `.agents/skills/` |
| [Claude Agent SDK](/docs/integrations/claude-agent-sdk) | `CLAUDE.md` and `.claude/skills/` |
| [Pi](/docs/integrations/pi) | `AGENTS.md`, `.agents/skills/` and resource descriptors |
| [Cursor](/docs/integrations/cursor) | `AGENTS.md` and `.cursor/skills/` |

Each plugin's `prepare` writes a verified version, the SDK's checked copy of a version's bytes, to a fresh private directory. It accepts either of these:

- The delivery from `client.prepare()`. Pass the delivery itself, so that `prepared.reportStarted()` still records the start receipt.
- The verified version from `resolveAndCache(client, selection, { cacheDir })`.

```ts
import { prepare } from '@acclimate/codex-plugin';

const delivery = await client.prepare({ workspaceId, bundleId, channel: 'stable' });
const prepared = await prepare(delivery);
// Run the agent SDK in prepared.cwd, then:
await prepared.cleanup();
```

`prepared.cleanup()` removes the directory and releases the delivery. Each integration page shows a complete job.

### Map an agent SDK without a plugin

For an agent SDK with no plugin, call `prepareNativeFiles` with the paths your agent reads:

```ts
import { prepareNativeFiles } from '@acclimate/sdk/native-files';

const prepared = await prepareNativeFiles(verifiedVersion, {
  mapping: { instructionPath: 'AGENTS.md', skillRoot: '.agents/skills', memoryRoot: '.acclimate/memory' },
  prefix: 'my-agent-',
  target: 'codex',
});
```

`target` names the rules to enforce before staging, `codex` by default.

## Rules for bundle files

A plugin refuses a version that breaks one of these rules. Each error names its rule, for example `[skill_metadata]`.

- A file path is relative, with no `.` or `..` segment. No two paths differ only by case, and no file sits where another path needs a directory.
- A version has at most one instruction file.
- A skill lives under `skills/<name>/`. The name has at most 64 letters, digits, `_` or `-`, and does not differ from another only by case. Cursor accepts only lowercase letters, digits and `-`.
- A skill needs a `SKILL.md` whose frontmatter has exactly one `name`, matching the directory, and exactly one non-empty `description`.
- Other frontmatter keys such as `license` or `allowed-tools`, and folded `description: >` values, are kept as written.
- Supporting text files, such as `scripts/check.py` or `config.json`, stay beside the skill.

## Prepare an existing repository

The native repository starter runs a coding agent with the prepared files on a copy of an existing repository and keeps its edits. Its offline replay checks preparation before you install an agent SDK.

1. Extract the starter from the release files. See [Install from verified release files](/docs/get-started/install#install-from-verified-release-files).
2. Run `node smoke.mjs` in the starter's directory.

The [native repository starter README](https://github.com/anveld-dev/acclimate/tree/main/examples/native-repository#readme) covers configuration and recovering private jobs.
