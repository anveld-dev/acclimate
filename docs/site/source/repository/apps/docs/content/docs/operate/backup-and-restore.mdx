This page is for the operator of a self-hosted deployment. It covers what to back up, how to dump each database and how to restore one.

## What to back up

| What | How | Why |
| --- | --- | --- |
| Acclimate database | [Dump it](#dump-a-database) to an archive | Every bundle, version, release history and learning record |
| Keycloak database, if you co-host Keycloak | Dump it to its own archive | The realm's users, credentials and changes. The realm import file only creates the empty realm. |
| `service.env`, which holds the provider encryption key | Copy it off the server, apart from the dumps | Without the key, the saved model provider API keys cannot be decrypted. |
| The other private runtime files | Copy them off the server | The database passwords and the secrets that the service, the console and Keycloak share |

Record the Acclimate release or commit with each dump. A dump is restored with the service build that made it. Data written after your last dump is lost if a volume is lost, so schedule the dump, for example with cron, as often as you can afford to lose.

## Dump a database

`pg_dump` takes a consistent snapshot while the service runs, so a scheduled dump needs no downtime.

### Bundled databases

The bundled databases publish no ports, so run `pg_dump` inside their containers. The tools there match the server version and connect over the local socket without a password. Run this from the checkout with your deployment settings loaded, and choose a private backup directory. Leave out the Keycloak line if you do not co-host Keycloak.

```sh
umask 077
set -o noclobber
stamp=$(date -u +%Y%m%dT%H%M%SZ)
docker compose exec -T postgres pg_dump -U acclimate -d acclimate --format=custom --no-owner --no-acl > "/private/backups/acclimate-$stamp.dump"
docker compose exec -T keycloak-db pg_dump -U keycloak -d keycloak --format=custom --no-owner --no-acl > "/private/backups/keycloak-$stamp.dump"
```

| Part | Effect |
| --- | --- |
| `umask 077` | The archive gets mode 0600. |
| `set -o noclobber` | The shell refuses to overwrite an existing archive. |
| `-T` | Output passes through unchanged. Without it, Compose allocates a terminal, which corrupts the archive. |
| `--no-owner --no-acl` | The archive holds no database roles or grants. |

If a command fails, delete its partial archive. Encrypt the archives at rest and in transit, set a retention period and protect the copies.

### Other PostgreSQL servers

For a database the host can reach, such as a managed server, `scripts/operations/backup.py` runs the same dump. It also checks that `psql`, `pg_dump` and `pg_restore` have the server's major version and refuses to overwrite an archive. You need a checkout with Python 3 and those tools.

1. Set `DATABASE_URL` to the database you want to dump. URL-encode the password. Protect this environment from other users.
2. Run the dump with a new archive path in a private directory. `--pg-bin` names the directory that holds the PostgreSQL tools. Leave it out if they are on your `PATH`.

   ```sh
   python3 scripts/operations/backup.py dump /private/backups/acclimate.dump --pg-bin /path/to/postgresql-16/bin
   ```

For the connection options the script accepts, see [Backup scripts](https://github.com/anveld-dev/acclimate/blob/main/deploy/README.md#backup-scripts). Keep a separate recovery plan for the PostgreSQL server itself.

## Keep the provider encryption key

`ACCLIMATE_PROVIDER_ENCRYPTION_KEY` in `service.env` encrypts the model provider API keys that workspaces save in the database. Back it up whenever you back up the database, and store it apart from the dumps. A dump and the key together reveal every saved provider API key.

The first time the service starts with a key, it stores a check value sealed with that key. A later start with a different key, for example after you restore a backup without its key, stops with an error. Before a check value exists, the service also refuses a key that opens none of the stored provider API keys. You then have two choices:

- **Restore the original key** in `service.env` and start the service again.
- **Start over with the new key.** This deletes every saved model provider, with its URL, models and API key.

  ```sh
  docker compose exec -T service /usr/local/bin/acclimate-service --reset-provider-keys --confirm
  ```

  The command prints `{"removedProviders": n}`. Start the service, then ask each workspace administrator to enter their model provider again.

Without any key, the service starts and logs a warning. Saving a model provider fails with HTTP 503, and saved providers show "Provider key unavailable". If the service cannot decrypt one stored provider API key, it logs the workspace ID, and that provider shows "Provider key unavailable" until a workspace administrator enters its API key again.

## Restore

<Callout type="warn" title="Restore into a new database">
Never restore over a live database. A restore into a database that already has tables fails. Always restore into a new, empty database and verify it before any service uses it.
</Callout>

1. Stop public traffic and the applications.

   ```sh
   docker compose stop proxy
   docker compose stop console service
   ```

2. Create a new, empty database and restore the archive into it. For the bundled Acclimate database:

   ```sh
   docker compose exec -T postgres createdb -U acclimate acclimate_restore
   docker compose exec -T postgres pg_restore -U acclimate -d acclimate_restore --exit-on-error --single-transaction --no-owner --no-acl < /private/backups/acclimate-<stamp>.dump
   ```

   On another server, create the database with the service's role as its owner, set `DATABASE_URL` to it and run `python3 scripts/operations/backup.py restore <archive> --pg-bin <dir>`. The script refuses a database that has tables.

   The restore runs as one transaction. If it fails, nothing is restored. Fix the cause and retry into the same empty database.

3. In `service.env`, point `DATABASE_URL` at the new database. For the bundled database, change the name at the end of the URL from `/acclimate` to `/acclimate_restore`. Keep the provider encryption key that was in use when the dump was taken.
4. Start the service build that matches the dump, with the proxy still stopped.

   ```sh
   docker compose up -d --wait service
   ```

5. Verify the restored data: bundle contents, channel revisions, learning rounds, improvement memory and application access.
6. Start the console and the proxy, then run the checks in [Check health and readiness](/docs/operate/health-and-readiness).

   ```sh
   docker compose up -d --wait console proxy
   ```

Keep the old database until you trust the restored one. Then remove it with `docker compose exec -T postgres dropdb -U acclimate <old-name>`.

To restore as part of undoing an upgrade, see [Roll back an upgrade](/docs/operate/upgrades-and-recovery#roll-back-an-upgrade).

### Restore the co-hosted Keycloak database

`compose.keycloak.yaml` fixes Keycloak's database name as `keycloak`. Restore into a new database, then swap the names while Keycloak is stopped. The swap runs in one transaction.

```sh
docker compose stop keycloak
docker compose exec -T keycloak-db createdb -U keycloak keycloak_restore
docker compose exec -T keycloak-db pg_restore -U keycloak -d keycloak_restore --exit-on-error --single-transaction --no-owner --no-acl < /private/backups/keycloak-<stamp>.dump
docker compose exec -T keycloak-db psql -X -v ON_ERROR_STOP=1 -1 -U keycloak -d postgres -c 'ALTER DATABASE keycloak RENAME TO keycloak_before_restore' -c 'ALTER DATABASE keycloak_restore RENAME TO keycloak'
docker compose up -d --wait keycloak
```

Verify the realm, the client settings and sign-in with the Keycloak version that made the dump. Then remove `keycloak_before_restore` with `dropdb`, as above.

## Rehearse a restore

Restore your real archives on a schedule on a separate host with its own checkout, and verify them as in steps 2 to 5. A dump you have never restored is not a tested backup. The repository's script for testing the backup tooling does not test your archives. See [Backup scripts](https://github.com/anveld-dev/acclimate/blob/main/deploy/README.md#backup-scripts).
