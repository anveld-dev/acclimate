title: Use your own reverse proxy
description: Replace the bundled Caddy with nginx, Traefik or an ingress while keeping Acclimate's HTTPS origins, private listeners and trusted proxy headers.
---

This page is for an operator who replaces the bundled Caddy with nginx, Traefik or a Kubernetes ingress. It lists what your proxy must do and gives an nginx example. [Self-host Acclimate](/docs/operate/self-host) needs no proxy changes.

## Match the bundled proxy

Apply these rules to both the console and the API hostname.

| Requirement | What your proxy must do |
| --- | --- |
| TLS | Terminate TLS and redirect public HTTP to HTTPS. |
| Routing | Send the console hostname to `console:3100` and the API hostname to `service:3000`, over plain HTTP. |
| `Host` | Set the upstream `Host` to the fixed public host for that route. For the console, use the host from `CONSOLE_ORIGIN`, with the port if you use a nondefault HTTPS port. |
| Forwarding headers | Remove incoming `Forwarded` and all `X-Forwarded-*` headers. Then set the three headers listed under this table. |
| Request contents | Preserve paths and query strings, including `/auth/callback`. Keep console cookies, the request `Origin` and the API `Authorization` header intact. |
| Body limit | Let API requests reach the service's 2 MiB body limit. A proxy that enforces the limit itself returns its own 413 response. |
| Timeout | Set the upstream response timeout slightly above 30 seconds, so the service can return its own timeout response. |
| Private listeners | Do not expose either listener, either PostgreSQL database or the proxy's admin interface to public clients. |

Set these forwarding headers on every upstream request:

- `X-Forwarded-Proto` to `https`
- `X-Forwarded-Host` to the fixed public host
- `X-Forwarded-For` to the peer IP address your proxy observed, without appending a chain the client supplied

The console rejects a request for any other host and ignores forwarding headers that a caller supplies. Register the exact public console origin plus `/auth/callback` with Keycloak.

## Allow task imports

Task import needs a larger body limit and a longer timeout. A proxy that applies 2 MiB or 30 seconds to it rejects or cuts off larger imports.

| Host | Request | Body limit | Time allowed |
| --- | --- | --- | --- |
| API | `POST /v1/workspaces/{workspaceId}/bundles/{bundleId}/learning/tasks/import` | 64 MiB | 600 seconds |
| Console | `POST /learning-import` | 64 MiB | 610 seconds |

The console forwards each upload to the service and waits up to 610 seconds for the answer.

## Keep Keycloak sign-in working

With the co-hosted Keycloak, your proxy also serves the Keycloak hostname.

- Forward only `/realms/acclimate`, `/realms/acclimate/*`, `/resources/*` and `/robots.txt` to `keycloak:8080`. Answer every other path yourself, as the bundled configuration does with a 404.
- Apply the same header rules, using the Keycloak hostname.
- Keep `/admin`, the master realm and the management listener private.
- Containers on the private network reach the issuer at its public HTTPS name. In `compose.keycloak.yaml` the `proxy` container carries that name as an alias on the `backend` network. Your proxy needs the same arrangement.

## Run without the bundled proxy

`compose.yaml` defines Caddy as the `proxy` service. To leave it out, start the other services by name. For example, with release images:

```sh
docker compose up -d --no-build --wait postgres service console
```

- Compose still refuses every command unless `CONSOLE_HOST`, `API_HOST` and `ACME_EMAIL` are set.
- The console and the service listen only on the internal Compose network `backend`, which has no outside route. Your proxy must join `backend`, and use a second network or the host's ports for public traffic, as the bundled proxy does with `edge`.

## Run behind a load balancer

To put a cloud or hardware load balancer in front of the server, keep Caddy and send the balancer's traffic to it. Caddy routes by hostname, so the balancer must keep the client's `Host` header and TLS server name.

| Balancer mode | Caddy's certificates |
| --- | --- |
| TCP passthrough on 443 and 80. Caddy terminates TLS. | Caddy's ACME works unchanged, as long as the internet reaches both ports through the balancer. |
| TLS termination at the balancer, then HTTPS to Caddy on 443 | The balancer holds your public certificate. Caddy needs a certificate the balancer accepts: its own ACME certificate, which needs port 80 forwarded from the internet, or your own certificate. |
| TLS termination, then plain HTTP to Caddy | Not supported. The bundled Caddyfile redirects HTTP to HTTPS. |

To give Caddy your own certificate, copy `deploy/Caddyfile`, or `deploy/keycloak/Caddyfile` with the co-hosted Keycloak, to your private directory. Add a `tls` line with the paths as Caddy sees them to each site block, for example `tls /etc/caddy/certs/console.pem /etc/caddy/certs/console.key`. Caddy then requests no certificate for that site. With the co-hosted Keycloak, the console reaches the issuer through Caddy and trusts only public certificate authorities, so the Keycloak hostname's certificate must come from one.

To accept traffic only from the balancer, publish Caddy's ports on a private interface. Put the overrides in a file in your private directory and add its path to `COMPOSE_FILE` in `compose.env`. This example also mounts the copied Caddyfile and your certificates.

```yaml title="~/.config/acclimate/compose.edge.yaml"
services:
  proxy:
    ports: !override
      - "10.0.0.5:80:80"
      - "10.0.0.5:443:443"
    volumes:
      - /home/ops/.config/acclimate/Caddyfile:/etc/caddy/Caddyfile:ro
      - /home/ops/.config/acclimate/certs:/etc/caddy/certs:ro
```

Use absolute paths and your server's private address. Check the merged result with `docker compose config --quiet`, then run `docker compose up -d --wait proxy`.

## Example nginx configuration

<Callout type="warn" title="This example is untested">
The repository's tests do not cover this nginx example or any other replacement proxy. Verify your own routing, TLS, header handling and sign-in before you switch traffic.
</Callout>

This example assumes nginx runs at the public edge and can resolve both service names on the private network. It needs the [headers-more module](https://github.com/openresty/headers-more-nginx-module) to remove request headers by wildcard. Add your own certificate paths and HTTP redirects.

Put the common directives in one file and include it in each proxy location.

```nginx title="/etc/nginx/acclimate-proxy.inc"
more_clear_input_headers 'Forwarded' 'X-Forwarded-*';
proxy_http_version 1.1;
proxy_set_header X-Forwarded-Proto https;
proxy_set_header X-Forwarded-For $remote_addr;
proxy_connect_timeout 5s;
proxy_next_upstream off;
```

Each server sets the ordinary limits, and its import location raises them.

```nginx
server {
    listen 443 ssl;
    server_name console.example.com;
    ssl_certificate /etc/nginx/tls/console.fullchain.pem;
    ssl_certificate_key /etc/nginx/tls/console.key;
    client_max_body_size 2m;
    proxy_send_timeout 35s;
    proxy_read_timeout 35s;
    location / {
        include /etc/nginx/acclimate-proxy.inc;
        proxy_set_header Host console.example.com;
        proxy_set_header X-Forwarded-Host console.example.com;
        proxy_pass http://console:3100;
    }
    location = /learning-import {
        include /etc/nginx/acclimate-proxy.inc;
        proxy_set_header Host console.example.com;
        proxy_set_header X-Forwarded-Host console.example.com;
        client_max_body_size 64m;
        proxy_send_timeout 615s;
        proxy_read_timeout 615s;
        proxy_pass http://console:3100;
    }
}

server {
    listen 443 ssl;
    server_name api.example.com;
    ssl_certificate /etc/nginx/tls/api.fullchain.pem;
    ssl_certificate_key /etc/nginx/tls/api.key;
    client_max_body_size 2m;
    proxy_send_timeout 35s;
    proxy_read_timeout 35s;
    location / {
        include /etc/nginx/acclimate-proxy.inc;
        proxy_set_header Host api.example.com;
        proxy_set_header X-Forwarded-Host api.example.com;
        proxy_pass http://service:3000;
    }
    location ~ ^/v1/workspaces/[^/]+/bundles/[^/]+/learning/tasks/import$ {
        include /etc/nginx/acclimate-proxy.inc;
        proxy_set_header Host api.example.com;
        proxy_set_header X-Forwarded-Host api.example.com;
        client_max_body_size 64m;
        proxy_send_timeout 605s;
        proxy_read_timeout 605s;
        proxy_pass http://service:3000;
    }
}
```

Keep unmatched hosts on a default virtual host that rejects them. nginx timeouts measure inactivity between reads and writes, while the service enforces a total deadline for each request. See the [nginx proxy module reference](https://nginx.org/en/docs/http/ngx_http_proxy_module.html).

When your proxy is in place, run the checks in [Verify API access and sign-in](/docs/operate/health-and-readiness#verify-api-access-and-sign-in) through it.
