## Freeze before broad edits

C0 publishes a small foundation commit first. R1, R2 and C1 can prepare their private-file changes immediately against the following contracts; do not let each invent a different config or state shape.

### Rust configuration and state

`AccessConfig` is immutable and clonable; fields are `issuer: String`, `login_token: String`, `console_token: String`, `operators: Vec<OperatorIdentity>`, with `OperatorIdentity { issuer: String, subject: String }`. Keep secrets out of `Debug`, error strings and serializable responses. `AccessConfig::from_env(grants: &[Grant]) -> Result<Self, ConfigError>` is the production loader; a value-based parser accepts an explicit map for unit fixtures without process-global env mutation. Existing validation exports may wrap this parser for compatibility, but handlers never reread env.

Inputs: retain `ACCLIMATE_AUTH`, `ACCLIMATE_LOGIN_TOKEN`, `ACCLIMATE_CONSOLE_TOKEN`, `ACCLIMATE_OPERATORS`; add required `ACCLIMATE_OIDC_ISSUER`, equal to console `CONSOLE_OIDC_ISSUER`. Reject the *presence* of `ACCLIMATE_MODE` (and console rejects `CONSOLE_MODE`), even if empty or previously `hosted`. Require nonempty distinct login/console secrets, neither equal to any grant token. Keep existing grant validation. Require at least one explicit operator pair; each issuer must exactly equal the pinned issuer and each subject be nonempty and ≤512 bytes. Issuer is HTTPS, ≤2048 bytes, without userinfo/query/fragment; preserve its exact validated spelling, including trailing-slash significance. No issuer normalization or URL-prefix matching.

`AppState` retains `db`, `grants`, `provider` and adds `access: Arc<AccessConfig>` and `runtime: Arc<RuntimeStatus>`. No optional access config or production default constructor. `RuntimeStatus` lives in `src/runtime.rs`, with explicit false-at-construction flags for ownership held, worker initialized/live and draining; methods/atomic internals belong to C0. R2 alone changes their lifecycle values. C0 exports the types and controlled-worker entrypoint. Existing tests constructing struct literals need mechanical additions from a test-only constructor/config helper, never a test bypass inside production parsing.

`RuntimeStatus::is_ready()` requires ownership held, initialized live worker and not draining; `/ready` additionally bounds a PostgreSQL usability query to two seconds and returns 200/503 with a generic body. It does not probe the provider or claim queue progress. R2 supplies `proposal_worker_controlled(AppState, tokio::sync::watch::Receiver<bool>)` for stop-claim notification; preserve exported `proposal_worker(AppState)` as a compatibility wrapper if existing callers need it. The task marks initialized/live only after entering its loop and clears live on termination; main also withdraws readiness on join failure. Draining is set before stop-claim notification. Check stop before each claim; finish/cancel the active future within the shared 45-second application deadline, then stop handlers and worker before closing/unlocking the guard. Ownership loss withdraws readiness and cancels active work immediately. Supervisor grace exceeds that bound (at least 50 seconds).

### Credential classes and session endpoints

Classify bearer first, before trusting a session or producing a session error: `LoginAuthority`, `ConsoleTransport`, `MachineGrant`, or invalid; scoped `aci_` credential behavior remains confined to integration routes. Strip all incoming trusted user/session/role headers. Login authority is usable only at `POST /v1/auth/sessions`; its optional session header is the previous secret to rotate, never the asserted identity. Console transport requires a valid session for browser data routes. Machine grants plus any browser session header fail closed; machine calls without a session retain scoped rights. Wrong/login/machine transport cannot obtain a typed invalid-session proof. Never infer credential class from the presence/absence of a session alone.

Login body remains `{issuer, subject}` and result `{sessionId,userId,secret,expiresAt}`. Match issuer exactly; login authority deliberately asserts the console-verified identity. Session absolute lifetime remains 28,800 seconds. On successful login revoke the supplied prior session regardless of whether its user matches the new account, atomically with new-session creation. No refresh store.

Freeze logout: `DELETE /v1/auth/session` with valid dedicated console transport returns `204` **only after committed revocation**; missing/expired/revoked/unknown session returns `401` with existing API error envelope and `error.code = "invalid_session"`. Invalid transport returns `401` / `"invalid_console_transport"` before session handling; generic database/routing failures retain their usual codes. `invalid_session` is reserved for a correctly transport-authenticated session check, including middleware. C1 clears browser session/selection cookies only on committed 204 or exact 401+`invalid_session`; generic 2xx, 401, 404, malformed bodies, network failure and upstream redirects retain them. No-cookie logout may clear local cookies without an upstream call. Other browser data routes may use `invalid_session` to show signed-out state, but a failed write stays uncertain until receipt reconciliation.

### Adoption DTO, result and transaction

`POST /v1/auth/workspace-adoptions` belongs in `workspaces::routes`, outside `/v1/projects/{project}` membership resolution. Require dedicated console transport, live session and exact current operator pair. `WorkspaceAdoptionRequest { project_id, reason }` serializes camelCase `{projectId,reason}`; project ID uses existing 1–128 ASCII ID validation; reason is trimmed, nonempty, at most 2000 bytes. No target-user input.

Return `200` `{projectId,operatorUserId,adoptedAt,reason,replayed}` after commit. `replayed` is false for the first adoption, true for the original recorded operator's retry. Never promise `role:"admin"` on replay: membership may have changed. Refuse missing project with `404 / not_found`, nonoperator with `403 / denied`, another operator's recorded adoption with `409 / workspace_adoption_conflict`, and memberships without adoption history with `409 / workspace_already_owned`. Invalid payload is `400 / invalid_content`; invalid live session is the typed session failure above. Retry with a different valid reason by the recorded operator returns the original immutable reason, not an update.

Migration 0013 creates `workspace_adoptions(project_id text PRIMARY KEY REFERENCES projects(id), operator_user_id uuid NOT NULL REFERENCES users(id), adopted_at timestamptz NOT NULL DEFAULT now(), reason text NOT NULL)` and revokes preexisting unrevoked browser sessions once. Historical migrations/checksums remain untouched. Application code only inserts/reads adoption rows. No reset, ID replacement, receipt-owner rewrite or user reassignment.

Use the existing exact membership-writer lock: `pg_advisory_xact_lock(hashtextextended('membership:' || projectId,0))`. Acquire it **before** session/member row locks, as `change_membership` already does; then recheck the session with a row lock and obtain the user's exact issuer/subject for the immutable operator config check. Verify existing project, inspect adoption history first: same operator returns history with no membership mutation, another operator fails. With no history, verify zero memberships, insert acting user's admin membership + immutable adoption audit in one transaction, then commit. Existing membership mutation holds this same advisory lock before authorization; extract/reuse its helper within R1. This serializes competing adoption/membership writers and avoids crossed lock order. Unknown response after commit is safely retried through immutable history; never regrant a removed member on replay. C1 refreshes access after first success and reports history independently from current membership.

### Console configuration, transport, access and lifetime

C1 owns `parseConsoleConfiguration(env)` (pure validation) and `loadConsoleConfiguration()` (one frozen runtime value). Required existing names: `CONSOLE_ORIGIN`, `CONSOLE_OIDC_ISSUER`, `CONSOLE_OIDC_CLIENT_ID`, `CONSOLE_OIDC_CLIENT_SECRET`, `CONSOLE_LOGIN_TOKEN`, `CONSOLE_SERVICE_TOKEN`, **explicit** `CONSOLE_SERVICE_URL`. Add optional `CONSOLE_PUBLIC_SERVICE_URL` for external app recipes; it is never a proxy destination and never falls back to the private service URL. Public URLs are HTTPS; private service HTTP is permitted only on the documented protected deployment network. Validate URL credentials/fragments/query and origin syntax; login/transport tokens differ. Project/bundle/channel defaults remain optional preferences.

Preflight validates syntax/config before either Vite's real listen or built Node server import/listen. Build only imports pure validation definitions and succeeds without runtime secrets. C1 supplies the launcher modules/Vite serve-only hook; D wires package scripts/container commands. Do not claim route-level validation meets pre-listen validation. Discovery and real issuer behavior are separate startup/release checks; console `/ready` uses bounded Rust `/ready` without an IdP request on every probe.

Canonical origin is `CONSOLE_ORIGIN`, used for callback/logout checks, cookies and CSRF. Deployment proxy passes canonical Host and strips/replaces `Forwarded`/`X-Forwarded-*`; direct console/Rust access is blocked. Console rejects noncanonical Host and reconstructs its external request URL from configured origin plus request path/query, not arbitrary forwarding headers. C1 owns framework integration and D owns matching proxy config; their joint fixture must exercise actual built request reconstruction and CSRF, not merely a helper. OIDC flow remains five-minute, single-use, bounded process-local state with one console instance; restart requires retry. Secure/HttpOnly/SameSite cookies are unconditional. Keep Node's real TLS verification.

`browserTransport(config, session, fetcher)` requires nonempty session at construction and owns server-only SDK creation plus direct fetch. It always attaches dedicated bearer and session, disables redirects, uses no-store/bounded requests, and does not accept caller-supplied identity headers. Expose both an SDK client and a direct request method so `exact-operation.ts` preserves exact serialized bytes/idempotency keys and receipt-first recovery. Login session creation uses a separate authority helper; it must not squeeze login credentials through browser transport. Keep existing injectable fetcher seams for tests.

Freeze UI-facing `AccessState`: authenticated branch `{ok:true,status:"authenticated",identity:AccessIdentity,projects:AccessProject[],canCreateWorkspace:boolean,actorScope:string,...existing member pagination fields}`; failure branch `{ok:false,status:"signedOut"|"unavailable"|"denied",identity:null,projects:[],message:string}`. No `mode`; successful identity is never null. Browser `AccessProject.role` is only `viewer|editor|admin`. Existing machine project discovery may retain its legacy capability label for compatibility; it must never flow into the browser role union or human authorization. An upstream outage is unavailable, never an empty/signed-out account. Public UI metadata may include `publicServiceUrl` and `editsEnabled`; no internal URL/secret/private evaluator path. `AccessCommand` adds `{kind:"adoptWorkspace",projectId,reason}` and `AccessResult` carries the adoption DTO/history. C2 confirms exact ID/reason before calling C1's action. Operator capability exposes creation/adoption but never workspace-wide access.

C2 defaults evaluation UI to frozen request/config handoff with public service/workspace/bundle/request IDs and revision binding. Optional installed runner uses explicit required `--config PATH` (or one documented private environment path), containing app-owned service URL, machine/scoped credential, principal, workspace and journal root. Never default to `.local/console-demo`, OS-user DB state or console transport. Preserve journal identity checks and attempt/request binding. Public descriptors select compatibility only; they cannot prove an installed runner. D owns old private-state files; C2 owns the new evaluator config and sends D the exact removal request. Test fixture config lives under test-owned directories. No execution fleet or automatic model call.

## Actual conflict points and test handoffs

- `src/lib.rs` currently owns `AppState`, auth exports, worker exports and router; R1/R2 must send C0 small patch requests. `src/types.rs` owns shared public DTOs; avoid parallel additions there. C0 alone reserves migration number 0013.
- `src/main.rs` currently invokes `validate_access_config`, `backfill_projects`, migration and worker; R1 cannot remove/rename registration without a coordinated R2 change. Keep the existing registration export until callers move. `src/improvement.rs` mixes routes with worker loop, so R1 does not edit it for auth cleanup.
- C0 owns the first mechanical `AppState` literal update in `src/auth.rs` tests and every existing `tests/*.rs` that constructs state, then explicitly hands files back. In production implementation this is a brief exclusive phase, not concurrent ownership: R1 then owns `tests/{workspace_access,access_remediation}.rs`; R2 owns `tests/process_ownership.rs`; other existing behavior test bodies remain with acceptance/integration. New C0 config and migration-upgrade tests use distinct files. Do not edit old outcome assertions away.
- C1 owns existing console tests for `access`, `identity`, `channel`, `navigation`, `setup-selection`, `integrations`, `drafts`, `edit-channel`, `version-workflows`, `pending-operation`, `credential-recovery`, `improvement` and `improvement-recovery`: these consume server contracts and mostly need explicit session setup. C2 owns `evaluation-config`, `sdk-setup`, `sdk-setup-recipes`, `member-pages`, `access-navigation`, `channel-navigation`, `connection-navigation` and pure component/lib tests. Coordinate any test importing both surfaces through its single owner.
- Root/acceptance owns `scripts/bdd/**`, `scripts/productization/**`, service/browser E2E fixtures and aggregate evidence. These files are shared across identity/runtime/evaluator stories; R1/R2/C1/C2 supply scenario requirements rather than independently rewrite world/browser launch config. D owns existing launch/private-state tests. New real-protocol HTTPS issuer/TLS proxy fixture is acceptance-owned, never `src/` or runtime selectable.
- Package scripts/lockfiles, generated route tree, Compose health checks and docs mirror generation are integration hot spots. Make requests to D/root; no opportunistic edits from feature branches. Existing SDK machine/receipt tests remain machine-authenticated and need no browser fixture.

## Critical path and review gates

1. Root accepts names/codes/ownership; C0 lands config/state/DTO/migration skeleton and mechanical test constructors. C1 freezes `AccessState` and action signatures early so C2 can implement against them.
2. R1 auth/adoption, R2 lifecycle, C1 transport/preflight and C2 UI/evaluator proceed concurrently in owned files; D prepares packaging against frozen entrypoints. C0 applies small integration requests centrally.
3. R1's credential/session/logout behavior unlocks actual C1 callback/rotation/logout verification. C1's launch/proxy integration plus R2 `/ready` unlock built-console TLS fixture and Compose wiring. Adoption requires R1+0013 before UI end-to-end proof. Explicit evaluator config removal unlocks retiring private-state launch assumptions.
4. Acceptance first verifies isolated 0012→0013 exact-identity preservation + once-only revocation, class separation/adoption races/rotation/logout; then built-process startup/proxy/readiness/drain and existing 141 behaviors / 183 variants. Run isolated PostgreSQL only; no ambient database or runtime credentials. No tests are executed during this planning task.
5. Root reviews integrated changes and evidence. Container/live-provider/public HTTPS/real restore gates stay separately marked not-run/blocked until actually exercised; fixture success does not qualify those external systems. No paid models by default; opted-in models remain Luna only.

The long pole is the acceptance-owned real OIDC/TLS fixture joined to **actual built** console preflight/proxy behavior and Rust transaction semantics. Begin fixture source preparation alongside C0 rather than waiting for UI completion. Shared-file churn and competing fixture rewrites would slow this more than independent UI work; the ownership/handoff rules above are the minimum coordination needed.
