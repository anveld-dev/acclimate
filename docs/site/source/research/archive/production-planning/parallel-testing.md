### One fixture implementation

Today `scripts/productization/qualify.py::Harness` owns PG/service configuration and is imported by `world.py`, `rust_tests.py`, `hosted_authority.py`, full-roadmap and recovery. It strips only `DATABASE_URL`/`ACCLIMATE_*`; `BrowserFixture` switches local/hosted, starts raw Nitro/Vite, and injects cookies. `World.sign_in()` calls the trusted Rust login authority directly. `identity_consumer.mjs` injects claims into the handler. These are the migration seams, not production OIDC evidence.

T should move the shared implementation into proposed `scripts/testing/` and expose one configuration/lifecycle interface. Q may retain a temporary import/re-export from `qualify.py` while consumers move; no duplicate `Harness`. Keep BDD-specific `World` and browser adapters under `scripts/bdd/`. Cross-language scripts consume a generated private manifest or a child-process wrapper from this same implementation; a TypeScript wrapper must not create another issuer/CA or infer PG credentials.

Freeze the following capabilities, with final API spelling chosen by T, before consumers change:

| Capability | Contract |
| --- | --- |
| Private run | Owns a fresh directory, ports, cluster/database names and process group; returns toolchain-safe sanitized child environment. Cleanup is bounded/idempotent after partial startup, assertion failure and interruption. No dotenv, credential store or existing private state reads. |
| Service configuration | Explicit DB/bind, machine grants, distinct random login and console-transport credentials, pinned HTTPS issuer and explicit operator pairs. Authority secrets never appear among grants. Configuration can use an HTTPS issuer identifier without starting its server for machine/API tests. |
| Optional identity/console fixture | Starts the one HTTPS issuer, generated CA/signing/client material, private console upstream and public TLS proxy only when the lane needs them. Returns canonical HTTPS console/issuer URLs, public API URL, CA trust path and child configuration, never public secrets. |
| Launch | Uses the exact supported production built/start or development command, not raw `.output/server/index.mjs` or direct Vite paths bypassing preflight. Reports readiness separately from liveness and records actual command/build identity. |
| Actors | Separate machine, login-authority, transport and human-session namespaces. Browser sign-in follows `/auth/login` to issuer authorization, callback, Rust session and protected UI. Actor-specific cookies/contexts; opaque user ID comes from the actual session endpoint. Narrow direct-authority helpers are explicitly labeled service-test setup. |
| Evaluator handoff | Creates explicit private fixture configuration beneath the run directory with service/principal/root/journal identity. No `.local/console-demo` or OS-user database inference. Machine evaluator credentials remain independent of browser sessions. |
| Evidence | Redacted report metadata, private artifact permissions, test-only trust material and bounded logs. Raw cookies/codes/grants/client secrets must not be uploaded in Playwright traces or process output. |

Sanitize inherited `DATABASE_URL`, PG connection variables, both Rust test DB variables, `ACCLIMATE_*`, `CONSOLE_*`, provider credentials and user-state selectors before constructing run-owned values; preserve necessary toolchain resolution. Machine/API lanes may start only PG and Rust. Rust tests may use direct DB/router setup. Neither needs a browser, running discovery endpoint, or paid model.

T's issuer implements discovery, authorization, code exchange and JWKS once. Use generated signing keys, exact HTTPS issuer, audience/client and redirect URI, one-use expiring codes, S256 PKCE, nonce and signed ID tokens. Node trusts the private CA through the fixture child environment; never set `NODE_TLS_REJECT_UNAUTHORIZED=0`. Specify and verify Chromium/installed Chrome fixture trust, including temporary persistent profiles used by native zoom; trust exceptions must stay fixture-local. Keep the installed default `openid-client` behavior and production Secure cookies. Do not enable an insecure-request hook or injected provider in the lane claiming full protocol success.

## Stages and contract gates

1. **Freeze contracts and preservation baseline.** Application owners publish required/legacy env names, validators, real start/dev commands, readiness/drain semantics, trusted origin/Host reconstruction, credential classification, session rotation/logout result contract, adoption responses and private evaluator schema. B records the 141 IDs/183 variants with their existing assertion paths; Q records old qualifier outcomes. I resolves path ownership and new command names. No consumer builds its own assumed auth/config contract.
2. **Build fixture foundation once.** T implements lightweight production configuration/PG plus optional issuer/TLS. R and C can migrate tests in parallel against agreed interfaces; B can update stories/ledger while awaiting the fixture. Q removes ambient config inheritance and prepares consumer adapters. T's contract gate must prove a successful default-client discovery → signed token verification → callback → protected page through the real built console, failure cleanup, actor separation and correct canonical origin under the actual adapter/proxy.
3. **Migrate independent acceptance consumers.** R completes service/upgrade/process tests; C completes console unit tests; B migrates all stories; Q completes qualifiers, old recovery, native zoom, packaging and evaluator consumers. T alone changes shared fixture lifecycle or inventory. Failed consumers produce a small fixture-contract request, not a copied implementation. I wires only gates whose entrypoints now exist.
4. **Integrate and retire old setup.** Run targeted affected lanes, then complete model-free acceptance on isolated resources. Compare preserved outcomes, not merely green counts. Remove old mode/launcher setup once every consumer has a replacement; retain explanatory retired command aliases only if the app plan allows them. I records executed local evidence separately from unexecuted external gates.

The fixture contract gate cannot pass on unit validation or a stubbed claims object. It must also demonstrate that build succeeds with runtime secrets absent; missing/malformed/legacy config makes the actual Rust, built-console and development entrypoints exit before listening; and fully configured built/dev entrypoints listen and become ready. Observe the selected bind port during startup and process exit, with no successful HTTP listener, rather than requesting a route that validates only after listen. Failure cases include equal authority credentials, a credential reused in machine grants, non-HTTPS issuer/origin, absent internal Rust URL and obsolete mode variables. Validate canonical callback/Host handling with forged forwarding headers through the stripping proxy and rejected wrong-Host/direct untrusted requests under the documented private-listener topology. Fixture success cannot establish deployed network isolation.

## Required acceptance content

- **Upgrade:** R constructs a disposable schema through 0012 with exact versions/payloads, drafts/history, releases/evidence, scoped credentials, human identities/memberships, orphan grant projects, old sessions, pending operations and prepared/evaluation jobs. Snapshot IDs, bytes/digests and owners; start the upgraded binary using singleton-protected migration 0013; compare unchanged business rows and previous migration checksums. Old sessions are revoked, a newly created session survives a second startup, and a fresh login works. No reset, inferred membership, pending-operation replay under a human, or receipt owner rewrite. Q checks pre-cutover SDK credentials still resolve/prepare/deliver, including first-bundle project registration with zero human memberships and read-only GET behavior.
- **Authority/adoption:** R tests dedicated transport plus session, rejects machine/session mixtures, arbitrary trusted-identity headers, expired/revoked/no sessions and operator-as-global-member assumptions. Add nonexistent/owned/orphan projects, two operators, adoption versus membership-writer races, live-session/operator recheck and immutable audit reason. Same adopter retry after demotion/removal returns history without regrant. B exercises the operator adoption review UI and ordinary uninvited state.
- **Protocol/logout:** T provides controlled malformed issuer responses; C retains deterministic-clock handler tests; B verifies actual default-client login, replay/browser-binding/state/nonce/PKCE/code expiry/signature/issuer/audience failures, same-person renewal and account-switch rotation. Existing cookies must observe role downgrade/removal without relogin. Logout commits revocation or recognizes explicit invalid session through valid transport before clearing; wrong transport/routing/generic 401/404 keep the cookie. Keep original identity outcomes even where test machinery moves.
- **Runtime/recovery:** R proves DB readiness, initialized/live worker, non-draining state, single-owner startup, migration failure before listen, ownership-loss failure, bounded shutdown, readiness withdrawal/new-claim cessation and queue guard release last. Q replaces local supervisor mechanics with the supported process/restart contract. Preserve `RUNTIME-01`: owned DB stall and dropped ownership connection, old owner exits before replacement, one queue owner, eventual ready recovery, exact unchanged release, stable independent console and clean intentional shutdown. Keep process backoff assertions only for retained machinery; map retired launcher-only assertions explicitly.
- **Evaluator/SDK:** C tests copyable request/config handoff as default and no command inferred from a public matching descriptor alone. Q tests explicit private installed adapters, no default state-root fallback, request/attempt/settings/digest binding, unchanged service/principal/root journal recovery, lost-response handling and deliberately released/rolled-back bytes. Preserve model-free full-roadmap and packed external TS/Python/native-plugin preparation, scoped content-read/receipt-write credentials and SDK optional session-field source compatibility. `tools/operator` currently describes a scoped machine CLI; I must classify it against the actual retirement scope before deleting it or `test:operator`. If retired, move review/promotion/history/rollback outcomes to the retained public SDK/production UI path. A command named operator is not proof of a browser bypass.
- **UI/native zoom:** B keeps mobile/coarse-pointer targets, keyboard/focus, dialogs, unsaved edits, scoped navigation and Vite module-import checks. Q migrates `test_console_native_zoom.py` to sign in within its fresh persistent Chrome context against the shared HTTPS fixture. Preserve Chrome's actual settings zoom at 2×, baseline half-width/doubled-DPR assertions, 1280/640 outer widths, all seven surfaces, two inspect-dialog bounds/Escape checks, native screenshot pixel assertion and zero browser errors. Narrow viewport emulation or CSS scaling cannot replace this evidence. Review `test_console_browser.py`'s standalone fake API/unconfigured-render expectations: replace obsolete startup behavior and map its literal-content/XSS, no-store, pagination, denial/redaction and read-only outcomes into production-backed tests before retiring its fake local setup.
