# Console and evaluator parallelization input

Planning only; `plan.md` and `review.md` remain authoritative. Eight implementation lanes total follow. Console paths below use `C = apps/console/src`; each lane owns its corresponding tests. Shared-file handoffs are serial, never concurrent edits.

## Ownership

1. **Coordinator/contracts/integration.** Sole owner: `src/types.rs`, `packages/sdk/src/types.ts`, `packages/sdk/src/client.ts`, `packages/sdk/src/index.ts`, `contracts/openapi.yaml`, migration numbering and files, root/package manifests, lockfiles, generated documentation. Integrates route/module registration in `src/lib.rs`; content lane supplies the provider-adapter patch there. Collect contract patches first; publish a compilable contract commit before dependent callers. Reserve shared Rust integration order below.
2. **Content/native/proposals.** Own native validators, plugin integration, provider patch reconstruction, `src/bundles.rs`, `src/channels.rs`, and initially `src/drafts.rs`; console `C/server/setup.ts`, `C/server/setup-actions.ts`, `C/server/drafts.ts`, `C/server/content-actions.ts`, `C/components/draft-workspace.tsx`, `C/components/import-content.tsx`, `C/components/bundle-library.tsx`, `C/components/diff-content.tsx`. Delivers target selection, saveable incomplete drafts, diagnostics, unique skill names and reusable review rendering; then hands listed shared console files to recovery. Supplies candidate-validation patch to evaluation’s `src/improvement.rs` owner.
3. **Recovery/release console.** Own `src/commands.rs`, new `C/server/pending-command.ts` and `C/lib/pending-command.ts`, `C/server/edit-channel.ts`, `C/server/version-workflows.ts`, `C/components/bundle-releases.tsx`. After handoff, exclusively owns content’s `setup.ts`, `setup-actions.ts`, `drafts.ts`, `content-actions.ts`, `draft-workspace.tsx`, `src/drafts.rs`, plus evaluation’s `C/server/improvement.ts`, `C/server/improvement-actions.ts`, `C/components/improvement-workspace.tsx`. Integrates frozen commands into existing actions, receipt-first reconciliation, exact retries and close/forget fences. Channel mutation call-site patches go through content’s `src/channels.rs` owner.
4. **Evaluation service/console/adapters.** Own `src/evaluations.rs`, `src/improvement.rs`, `packages/sdk/src/compare.ts`, initially the three improvement console files above, `C/components/bundle-changes.tsx`, `scripts/evaluate-local.ts`, `examples/evaluate-request.ts`, `examples/service-proposer/workflow.ts`, and new installed-adapter modules. Implements bound evidence, chronological lists, direct active-ID polling, descriptors, payment simulation, native review adapter and journal. Then hands improvement console files to recovery. Uses content’s diff component; no independent rewrite.
5. **Access/connections.** Own `src/workspaces.rs`, `src/integrations.rs`, `C/server/access-core.ts`, `C/server/access-actions.ts`, `C/server/integration-core.ts`, `C/server/integration-actions.ts`, `C/components/workspace-members.tsx`, `C/components/workspace-connections.tsx`. Implements member inspection/final-admin protection and separate memory-only credential reconciliation. Coordinator integrates required `src/auth.rs` changes.
6. **Delivery/cache/recipes.** Own TS cache/reporting, Python reporting, receipt-adoption examples and actual-start instrumentation. Supplies SDK signatures through coordinator; does not edit evaluator helper or launcher.
7. **Local operations/setup.** Sole owner `scripts/dev-console.ts`, `scripts/local-processes.ts`, launcher diagnostics and manual Compose/console documentation. Adds private evaluator configuration and dedicated read/write principal; preserves existing state and database ownership recovery. Consumes evaluation’s helper contract.
8. **Distribution/qualification.** Own packaging, isolated consumer checks, opt-in qualification harnesses, evidence ledger and browser acceptance scripts, including `scripts/test_productization_browser.py` and `scripts/productization/rust_tests.py`. Invokes the one copied helper; does not introduce another launcher/principal.

## Contracts still requiring decisions before callers

- Freeze pending-envelope schema/version, byte/size bounds, normalization timing, actor/session identity source, marker/header spelling, canonical routes, exact legacy/global versus route-scoped lock strings, receipt/close responses and retention. Define storage-loss fences and logout/account-switch clearing hooks. Effective-right mapping must cover setup write+promote and browser-admin connection lookup.
- Freeze target DTO/defaults and diagnostic shape. Current `C/server/drafts.ts` rejects native metadata for every save, contradicting generic compatibility and recoverable incomplete drafts; remove that gate without weakening generic validation.
- Freeze descriptor runtime key names/config revision, inventory ordering, bounded descriptor validation and structural comparison. The console and `examples/evaluate-request.ts` currently duplicate `fixtureIdentity`; replace duplication with one public, credential-free descriptor. Specify optional binding’s all-or-none shape and explicit legacy labeling.
- Freeze installed `describe`/execute/grade callback types and helper configuration schema/path ownership. The copied interface is `npm run evaluate:local -- --bundleID UUID --requestID UUID`. Specify request lock/crash recovery mechanism, atomic journal states and persisted start/submission/finish keys, scoped to service/project/bundle/request/evaluator. A saved report must recover without callbacks; execution-started without a complete report must block reexecution.
- Define member cursor/nullable-role DTO, typed credential-already-issued metadata and confirmed-revocation state. Current integration failures erase the useful issuance identity.

## Launch and acceptance gates

Immediately launch pure validators/patch logic, adapter callbacks/journal, daemon reporting, access invariant and packaging work against agreed interfaces. Coordinator then lands service contracts; service/API rollout precedes clients. Content/evaluation finish their console edits before recovery’s integration pass. Operations and evaluator lanes exchange configuration fixtures before helper integration. Recovery must consult receipts before existing improvement stale-parent/revision checks.

Fresh sanity check: `ContentDiff` detects kind changes but truncates at 500 changed lines; preserve inspectability through an explicit full-content path. Request polling currently refreshes only the head page and lacks scope-safe updates; test a running request beyond page one. Acceptance must cover incomplete native save/reload versus rejected publication, multiple new skills, patch HTTP fixtures, fake-adapter behavioral outcomes, reload/storage failure, close versus late unmarked execution, losing complete bound evidence and interrupted-request evidence, concurrent helper invocation/crash recovery, arbitrary selected bundle IDs, final-admin races and lost credential revoke responses. Browser handoff invokes the actual helper against test-owned private state; isolated Rust tests must execute. Live qualification remains separately dated passed/blocked/not-run evidence.
