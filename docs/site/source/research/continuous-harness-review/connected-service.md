# Continuous improvement on an enrolled connection

Reviewed Acclimate `2951785` on November 17, 2026 against the pinned AgentRun and RRSI sources. Six reviewers investigated the reference designs, mutation, evidence, feedback and release lifecycle. The earlier reviews used a baseline that predates both the application-owned learner and the connected service. Today's service already turns trusted feedback into proposals, runs paired trials, promotes to a connection-specific channel and can roll back a measured field regression. The highest priorities are the evidence used to authorize a release and what the learner remembers across releases. The fixes that followed this review are described in the [connected learning contract](../../../contracts/learning.md) and [operator guide](../../../deploy/README.md#operate-connected-learning). Source links for the findings below are pinned to the reviewed revision.

## 1. Bind an automatic audit to the data actually graded

The cohort registry can prevent reuse of declared identities. Its optional dataset and case fingerprints drop out when the worker builds the evaluation request. The connected driver matches the installed app using revision labels, runtime metadata and case IDs. In a probe, changing an invoice case from overdue to paid and its expected answer from escalate to archive produced identical descriptors and zero reported differences. An accidental fixture change can therefore qualify a release under the original audit identity. The qualification itself hashes the dataset label and case IDs, and its rollback fixture supplies the same task inputs under different cohort names. [Registry identities](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/migrations/0018_connected_learning_renewal.sql#L40) · [Request construction](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning_worker.rs#L350) · [Installed app matching](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/packages/sdk/src/learning/connected.ts#L352) · [Qualification fixture](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/scripts/connected-learning-e2e.ts#L315)

For automatic rollout, commit to the private inputs, expected answers and repetition inventory at registration. Verify the installed values before either arm runs and bind the commitment to the report. Keep private data in the application. The application-owned adapter already makes this comparison against retained artifacts. Semantic independence, including whether two differently worded tasks test the same lesson, still needs an application judgment. [Existing adapter checks](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/packages/sdk/src/learning/adapters/acclimate.ts#L395)

## 2. Keep production evidence after the channel advances

Suppose A handles refunds correctly, B breaks one refund case, and C inherits the break. C can pass its offline audit and ship before B's field grade arrives. The service rejects a new verdict for B once C is current. A fresh C job compares C against B. When both answer incorrectly, the field auditor produces no verdict. Even after an automatic C-to-B rollback, the restored B has a new revision, and the field sample lookup only follows original promotion IDs. A rolled-back candidate also falls outside the next proposer's history of failed development comparisons. [Promotion](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning_worker.rs#L611) · [Late verdict rejection](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning/field_audits.rs#L105) · [Paired field grades](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/packages/sdk/src/learning/connected.ts#L248) · [Field sample lookup](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning.rs#L564) · [Proposal history](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning_worker.rs#L270)

Record late grades against the release actually served. Keep the expected-current-revision check on any action that moves traffic. Retain a field-validated comparison version across promotions and restores. If a field case caused a withdrawal, require the affected behavior to pass that case before reauthorizing the same content under the same conditions. Verify with an A → B → C fixture whose B grade arrives after C ships and whose failure persists on C.

## 3. Give an observation a longer life than one proposal

Two jobs on v1 can uncover unrelated errors. The worker processes the first while the second waits. If the first fix ships v2, the second observation gets a terminal stale rejection even if its task still fails on v2. If the first candidate instead fails development, the same observation cannot trigger a revised hypothesis. The schema links an outcome to at most one round. Separately, reporting completion fixes the entire outcome fingerprint, so a later human correction cannot be appended under the original outcome ID, and a new ID cannot reuse the original started receipt. [Worker admission](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning_worker.rs#L155) · [Development rejection](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning_worker.rs#L566) · [One round per outcome](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/migrations/0017_connected_learning.sql#L69) · [Outcome identity](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning.rs#L501) · [Receipt uniqueness](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/migrations/0019_connected_learning_field_samples.sql#L15)

Give corrections their own IDs and link them to the immutable job and observed delivery revision. Keep unresolved observations eligible for bounded attempts. When the channel advances, recheck the failure on the new parent before drafting a fresh edit. Preserve exact-parent checks on every candidate and promotion. The application-owned controller already retries development under a configured limit. AgentRun offers a related precedent by checking the particular graded files a proposed merge will touch. [SDK retries](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/packages/sdk/src/learning/controller.ts#L369) · [AgentRun merge checks](https://github.com/Parcha-ai/agentrun/blob/077b2fa1c831bdd2bbcb7ed7a0435914f48486b5/packages/serve/src/learn/commit.ts#L198-L205)

## 4. Define improvement for each stage and workload

The managed worker applies the same rule in development and audit. Every paired reward must tie or improve, and at least one must improve. A fix that solves the development failure and preserves perfect performance on all audit cases fails. Identical quality at half the cost also fails, while a tiny positive fluctuation can qualify an expensive candidate. A Rust probe confirmed that empty edits and replacements with identical text both reconstruct the unchanged parent. The service can issue those bytes a fresh candidate UUID and evaluate them. With noisy rewards, identical harnesses could qualify as an improvement. [Selection rule](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/connected_learning_worker.rs#L490) · [Edit reconstruction](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/proposal_edits.rs#L32) · [Candidate creation](https://github.com/anveld-dev/acclimate/blob/2951785aebea82a2df218110e07cb6ec6e2a8766/src/improvement.rs#L464)

Skip unchanged content before spending an audit slot. Bind separate development and audit policies at enrollment. Distinguish protected cases that must always pass, minimum practical gain on target tasks, acceptable variation elsewhere, and cost where it matters. Permit an explicit new policy revision at a round boundary as tasks and graders change. Current renewals can add audit cohorts and admissions while the development descriptor remains frozen. The app-owned SDK already records separate selection policies. RRSI illustrates how a domain can supply guards and account for cost and noise in selection. ## 5. Give operators a way to restore the connection

Enrollment forks the currently published bundle. If an operator later corrects a shared policy on the source channel, the enrolled connection keeps serving its fork. Stopping learning freezes that delivery. The ordinary promotion endpoint refuses managed channels, and automatic rollback only restores the immediate predecessor once enough field verdicts arrive. Provide a reviewed operation to restore a known-good version or qualify an updated source version on the existing connection. Bind it to the current revision, retain its history, and close any candidate evaluated against the superseded parent. ## How much of the harness should evolve?

Fixed-file refinement can improve real behavior. In a previous bounded experiment, fresh jobs scored 32/32 with the released helper and 14/32 with the pinned original. The experimenter first created an empty helper file for the proposer to fill. Managed connections can edit existing allowed files, including executable helper content where the application supports it. They cannot discover a need for an additional helper and create its path. The app-owned mutation planner already supports explicitly authorized skill creation and retirement. Bring that capability to managed enrollments if repertoire growth is a product goal. Evolving the application's runner, tool contracts or control flow as RRSI does would require identifying, evaluating and releasing those executable artifacts as part of each treatment. ## Verification

The model-free PostgreSQL connected-learning qualification passed on the reviewed Git tree. It exercised real service rollout and rollback, eight calls to a local fixture proposer, and the expected rejection of a late verdict. Reviewers ran the audit-descriptor and unchanged-edit probes above, and all nine SDK mutation tests passed. The multi-release inheritance and repeated-promotion scenarios follow from the code paths. This review measured neither production frequency nor live model quality.
