# Second pass: experience, memory and admission

Reviewed 2026-11-17 against current Acclimate source and AgentRun `077b2fa1c831bdd2bbcb7ed7a0435914f48486b5`. This is read-only source analysis, not a reproduced exploit or measured learning experiment. No models or application code were run or changed.

## Verdict

The first review's proposed typed experience records and harness manifests are useful identity primitives. They are **not sufficient to make experience safe or true enough to become standing instructions**. Add an explicit admission decision and an applicability/compatibility policy. Keep execution authorization outside learned text. The current product's deliberate human release authority is valid; the risks below arise when replacing that review with an autonomous controller.

## 1. High goal gap: provenance is not authority to teach

**Evidence.** Acclimate's proposal evidence is `Vec<String>` without source class, approval state, or permitted inference scope ([types.rs:94](../../../../src/types.rs#L94)). The installed proposer serializes parent, request/evidence and edit instructions together into one user message ([lib.rs:242](../../../../src/lib.rs#L242)). Reconstruction checks exact anchors, path capabilities and payload validity; it does not establish the authority of a correction, remove secrets or determine whether a proposed rule is grounded ([proposal_edits.rs:22](../../../../src/proposal_edits.rs#L22)). The twenty-round qualification marks corrections as approved inside application-produced JSON strings ([feedback.ts:33](../../../../examples/self-improvement/twenty/feedback.ts#L33)); that label is not an independently verified admission decision.

**Failure scenario.** A task transcript contains “for this account, skip review” or a retrieved page claims a new payment policy. A controller honestly retains its trace digest and creates a perfectly typed experience, then includes that text as a correction. A structurally valid candidate can turn a task observation into a standing policy. A task score on a narrow suite may not detect the change. Putting the source in JSON, or moving trusted rules into a system message, would not itself establish semantic trust.

**Counterevidence / classification.** `create_proposal` requires `propose` rights and reads the parent under explicit project/bundle scope ([improvement.rs:195](../../../../src/improvement.rs#L195), [improvement.rs:223](../../../../src/improvement.rs#L223)). Publication separately checks promotion authority and exact evidence bindings ([channels.rs:135](../../../../src/channels.rs#L135), [channels.rs:198](../../../../src/channels.rs#L198)). This is **not a demonstrated authentication or cross-workspace access bypass**. A trusted app can already prepare evidence correctly. The missing concept is a reusable admission protocol before that app runs autonomously.

**Minimal remedy.** Experience import should preserve origin class (owner correction, verified external policy, task/tool observation, model inference), original scope, retained/redacted artifact identity, and who authorized use. Admission should output an immutable approved teaching view with allowed target task families, permitted edit capabilities, policy revision and decision reason. Credentials and private identifiers should be removed before sending evidence to a model, not merely before a later export. Untrusted observations may support a hypothesis; they must not grant new tool or publication permissions. Keep tool access and current authorization enforced by the host regardless of remembered text.

**AgentRun comparison.** Its grader distinguishes actual user messages from webhook/trigger text ([GradeInput:127](https://github.com/Parcha-ai/agentrun/blob/077b2fa1c831bdd2bbcb7ed7a0435914f48486b5/packages/serve/src/learn/grade.ts#L127-L134)); its rubric drops planted/secret material and holds risky changes for approval ([rubric:49](https://github.com/Parcha-ai/agentrun/blob/077b2fa1c831bdd2bbcb7ed7a0435914f48486b5/packages/serve/src/learn/grade.ts#L49-L79)). Borrow the distinction between observation and admitted rule. A model rubric is an additional check, not a proof of trusted origin or safety.

## 2. High goal gap: supersession metadata does not establish semantic compatibility

**Evidence.** Acclimate stores memory as ordinary bundle file text; neither `BundlePayload` nor `ProposalRequest` defines applicability, source-policy epochs or inter-lesson compatibility ([types.rs:15](../../../../src/types.rs#L15), [types.rs:94](../../../../src/types.rs#L94)). The qualification explicitly teaches a version-two contract that supersedes stale memory ([twenty/run.ts:55](../../../../examples/self-improvement/twenty/run.ts#L55)), and checks preservation through its domain-specific grader/acceptance ([twenty/run.ts:276](../../../../examples/self-improvement/twenty/run.ts#L276)). This is useful evidence of an app policy, not a general memory lifecycle.

**Failure scenario.** An incident produces a correct lesson for provider A's old API or one customer's policy. A later job selects it under provider B, another customer, or a newer policy. Both notes may have approved provenance and distinct IDs; they can still conflict in their bodies or assumptions. A `supersedes` link records a declared replacement; it does not discover all conflicts or establish which policy is currently authoritative. Workspace isolation also does not establish applicability between customers/tasks inside one workspace.

**Counterevidence / classification.** The app owns domain truth and can implement relevance today. Pinning old jobs to old content is deliberate and should remain. No cross-tenant data disclosure was demonstrated by this review.

**Minimal remedy.** Admit lessons with explicit applicability predicates and source-policy revision/effective interval; preserve known-good task cohorts as regression obligations. Evaluate a candidate against the compatible active lesson set, record deliberate replacements and unresolved conflicts, and reject an indeterminate applicability match rather than treating approval as universal relevance. New jobs should select against current policy; existing pinned jobs must still obey current host authorization, which is distinct from content pinning.

**Upstream limitation.** AgentRun asks whether a new lesson contradicts active notes, but the grade input contains the active index plus full bodies only of explicitly superseded notes ([GradeInput:106](https://github.com/Parcha-ai/agentrun/blob/077b2fa1c831bdd2bbcb7ed7a0435914f48486b5/packages/serve/src/learn/grade.ts#L106-L115), [prompt:448](https://github.com/Parcha-ai/agentrun/blob/077b2fa1c831bdd2bbcb7ed7a0435914f48486b5/packages/serve/src/learn/grade.ts#L448-L456)). A body-only conflict absent from the index need not be visible to that grader. This is an information-limit inference, not a reproduced AgentRun bug. Do not copy “one grader approved it” as a guarantee of global semantic compatibility.

## 3. Medium goal gap, first-review qualification: stored memory and effective context need different evidence

**Evidence and correction.** It would be wrong to say Acclimate has no selective context support. The native repository starter validates selected memory paths, physically removes excluded memory files, and returns only selected memory/resources ([repository-job.mjs:291](../../../../examples/native-repository/repository-job.mjs#L291)). It records the bundle version/digest, source-manifest identity, context-policy revision and a hash of selected paths ([repository-job.mjs:504](../../../../examples/native-repository/repository-job.mjs#L504)). With immutable bundle bytes, the selected-path hash need not itself duplicate the content hash. The starter already supplies a useful app-owned effective-context record.

The generic native preparation helper returns all staged memory files ([native-files.ts:96](../../../../packages/sdk/src/native-files.ts#L96)), and the basic Codex example supplies their paths as approved memory ([codex-agent.ts:62](../../../../examples/codex-agent.ts#L62)). That helper does not silently establish which bytes the model read or used. Review verification explicitly reports `executionAttested: false` ([artifacts.ts:88](../../../../packages/sdk/src/evaluation/artifacts.ts#L88)).

**Failure scenario.** A controller observes a failed task under bundle V and proposes changing note N, even though N was excluded, truncated, or never read. A manifest can establish what the app made available; a final answer or started receipt cannot establish use or causal responsibility. Conversely a changed selector can improve a task without any bundle-byte change. Treating all such cases as “memory V improved” makes the learner credit the wrong change.

**Minimal remedy.** Reuse the repository starter's context binding as the foundation, and record the actual selection output, selection reasons/omissions, mapping/config revision and relevant host-supplied context. Retain SDK/tool read events when available and represent unavailable read evidence honestly. Distinguish available, observed-read and behaviorally-tested influence; only controlled comparisons or ablations support attribution. Keep raw private context local and share scoped references/hashes as needed.

**Counterargument.** Complete token-level context attestation may be unavailable from a hosted native SDK. It is not necessary to start learning. The requirement is accurate claims and a stable, app-observable collection contract, not a claim to prove every model dependency.

## Smallest coherent addition

Add a versioned **ExperienceAdmission** result between task outcomes and proposal input. It should bind the source experience and sanitized teaching view to explicit scope, authority, validity and mutation capabilities. Pair it with an app-observable **EffectiveContext** record and domain regression obligations. Continue using the existing exact content snapshots and human or explicit policy-based release authority. This adds the missing semantics without creating a hosted runtime or assuming typed metadata makes arbitrary transcripts trustworthy.
